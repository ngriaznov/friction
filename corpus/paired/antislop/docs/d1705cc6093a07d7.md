## Thistle Configuration File Reference

This document details the configuration file format for Thistle, a static site generator focused on simplicity and performance. The primary configuration is driven by a YAML or TOML (both supported) file located at the root of your project directory – typically named `thistle.yml` or `thistle.toml`. This configuration dictates overall website behavior and can be overridden on a per-page basis through front matter.

**1. Supported Top-Level Keys**

The following keys are recognized at the top level of the configuration file:

* **`title` (String, Required):**  Sets the title of your entire website. This is typically displayed in browser tabs and used in meta tags.
    * Example (YAML): `title: "My Awesome Website"`
    * Example (TOML): `[general]`
      `title = "My Awesome Website"`

* **`base_url` (String, Optional):** Defines the base URL of your website. This is crucial if your site will be hosted at a location other than the root directory (e.g., `https://example.com/blog`). It influences relative path resolution for assets and links.  If omitted, it defaults to `/`.
    * Example (YAML): `base_url: "/blog"`
    * Example (TOML): `[general]`
      `base_url = "/blog"`

* **`theme` (String, Optional):** Specifies the theme to apply to your website. Themes control the overall visual appearance and layout of your site. Available themes are listed in the Thistle documentation. If omitted, a default theme will be used.
    * Example (YAML): `theme: "minimal"`
    * Example (TOML): `[general]`
      `theme = "minimal"`

* **`output_dir` (String, Optional):** Determines where the generated static files are placed.  The default is a directory named `public`. Ensure this location has sufficient write permissions for the Thistle process.
    * Example (YAML): `output_dir: "_site"`
    * Example (TOML): `[general]`
      `output_dir = "_site"`



**2. Front Matter Overrides – Page-Specific Configuration**

Thistle allows page-specific configuration through “front matter.”  Front matter consists of metadata placed at the very beginning of a Markdown or other supported content file, separated from the main content by three hyphens (`---`). This front matter can override any of the global settings defined in `thistle.yml` or `thistle.toml`.

Supported keys for per-page overrides include:

* **`title` (String):** Overrides the overall website title for a single page.
* **`layout` (String):** Specifies a layout template to use for this specific page.  Layouts are theme dependent and control the structure of the rendered output. If omitted, the default layout will be applied.
* **`permalink` (String):** Defines a unique URL for the page. This overrides the standard permalink generation rules defined by the theme.  Defaults depend on the theme.
* **`tags` (List/Array of Strings):** Adds tags associated with this page, often used for organization and filtering.
* **`exclude_from_search` (Boolean):** When `true`, prevents the page from being included in any site search functionality.

The order of precedence is: per-page front matter overrides top-level config file values.  For example, if your global `title` is "My Website" and a specific page has `title: "About Me"` in its front matter, that page’s title will be “About Me”, while the rest of the site maintains "My Website."

**3. Example Configuration Files**

Here are two complete example configuration files – one using YAML and another using TOML.  These examples highlight different possible configurations.

**Example 1: `thistle.yml` (YAML)**

```yaml
title: "Awesome Photography Blog"
base_url: "https://www.myphotographyblog.com"
theme: "solarized-dark"
output_dir: "dist"

collections:
  posts:
    permalink: /blog/:year/:month/:day/:slug/
```

This configuration sets the website title, defines a `base_url`, selects the "solarized-dark" theme, directs output to a directory named “dist”, and configures a blog post collection with custom permalink rules.  The `collections` section is used for organizing content (explained further in additional documentation).

**Example 2: `thistle.toml` (TOML)**

```toml
[general]
title = "My Personal Journal"
base_url = "/"
theme = "simple"
output_dir = "build"

[collections.journals]
permalink = "/journal/:year/:month/:slug/"
```

This example demonstrates a TOML configuration, achieving the same purpose as the YAML version.  Notice how keys in TOML sections are accessed using `[section.subsection]` notation. The setup assigns a title, establishes a base URL (the root), employs the "simple" theme, and places generated files in “build”, alongside defining per collection permalink rules for journals.

**4. Additional Considerations & Further Documentation**

* **Comments:** Both YAML and TOML support comments to explain configuration options. In YAML, use `#` at the beginning of a line.  In TOML, use `;`
* **Data Types:** Ensure your values correspond to their expected data types. Incorrectly formatted numbers or booleans can lead to parsing errors.
* **Error Handling**: During generation, Thistle will log any configuration errors encountered. Pay attention to these logs as they pinpoint inaccurate syntax or unsupported options.
* **Theme Specificity:**  Certain themes may introduce additional configuration options beyond the basic top-level keys described here. Refer to the theme’s documentation for details on those specific features and settings.
