## Ratchet: REST API Reference

**Version:** 1.0
**Date:** October 26, 2023

This document details the publicly available REST API endpoints for Ratchet, a distributed task queue service designed to handle asynchronous processing and background jobs. It outlines functionality for enqueuing tasks, monitoring their status, and cancelling pending jobs.  All requests should be made over HTTPS.

**Base URL:** `https://api.yourdomain.com/ratchet/v1` (Replace with your actual domain)

**Authentication:** API access requires an authentication token passed via the `Authorization: Bearer <token>` header in each request. Contact your administrator for valid tokens.  Rate limiting is implemented to prevent abuse – please adhere to specified limits.


### 1. Enqueueing a Job (POST /jobs)

This endpoint adds a new task to the queue for processing.

**Method:** `POST`
**URL:** `/jobs`
**Headers:**
*   `Authorization: Bearer <token>`
*   `Content-Type: application/json`

**Request Body (JSON):**

```json
{
  "queue": "default",        // Required. The queue to enqueue the job into. Default is 'default'.
  "payload": {             // Required. The data to be passed to the worker process. Can be any valid JSON object.
    "operation": "process_image",
    "image_url": "https://example.com/images/photo.jpg",
    "priority": 1
  },
  "attempts": 3,            // Optional. The number of attempts to execute the job before marking it as failed. Default is 5.
  "delay": 60               // Optional. Delay (in seconds) before the job becomes available for processing. Default is 0.
}
```

**Parameters:**

*   `queue` (string): Specifies which queue to add the job. Multiple queues allow prioritization and segregation of tasks.
*   `payload` (JSON object):  The data sent to the worker process when execution begins. The structure depends entirely on what your worker processes are designed to handle.
*   `attempts` (integer, optional): Defines how many times a failed job should be retried before being marked as permanently failed.
*   `delay` (integer, optional): Specifies a delay in seconds before the task becomes ready to process.

**Response Codes:**

*   `201 Created`: Job successfully enqueued. The `Location` header contains the URL of the newly created job.
*   `400 Bad Request`: Invalid request body or missing required parameters.  The response body will contain details about the validation errors.
*   `401 Unauthorized`: Authentication failed - invalid or missing token.
*   `500 Internal Server Error`: An unexpected error occurred on the server.

**Response Body (JSON) – 201 Created:**

```json
{
  "job_id": "a1b2c3d4-e5f6-7890-1234-567890abcdef", // The unique identifier for the newly created job.
  "queue": "default",
  "status": "pending",
  "attempts": 3,
  "delay": 60,
  "created_at": "2023-10-26T14:30:00Z" // ISO 8601 timestamp.
}
```

**Example `curl` Request:**

```bash
curl -X POST \
  https://api.yourdomain.com/ratchet/v1/jobs \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "queue": "image_processing",
    "payload": {
      "operation": "resize_thumbnail",
      "image_url": "https://example.com/images/large.png",
      "width": 200,
      "height": 150
    }
  }'
```

### 2. Checking Job Status (GET /jobs/{job_id})

This endpoint retrieves the status of a specific job given its unique ID.

**Method:** `GET`
**URL:** `/jobs/{job_id}`
**Headers:**
*   `Authorization: Bearer <token>`

**Parameters:**

*   `job_id` (string): The unique identifier for the job to retrieve.  This is a UUID generated when the job is created.

**Response Codes:**

*   `200 OK`: Job found and details returned successfully.
*   `401 Unauthorized`: Authentication failed - invalid or missing token.
*   `404 Not Found`: Job with specified ID does not exist.
*   `500 Internal Server Error`: An unexpected error occurred on the server.

**Response Body (JSON) – 200 OK:**

```json
{
  "job_id": "a1b2c3d4-e5f6-7890-1234-567890abcdef",
  "queue": "image_processing",
  "status": "pending",    // Possible values: pending, running, completed, failed, cancelled.
  "attempts": 3,
  "delay": 60,
  "payload": {            // The original payload sent when the job was created.
    "operation": "resize_thumbnail",
    "image_url": "https://example.com/images/large.png",
    "width": 200,
    "height": 150
  },
  "created_at": "2023-10-26T14:30:00Z",
  "updated_at": "2023-10-26T14:35:00Z", // ISO 8601 timestamp. Updated when job status changes.
  "finished_at": null      // ISO 8601 timestamp. Only present if the job is completed or failed.
}
```

**Example `curl` Request:**

```bash
curl -X GET \
  https://api.yourdomain.com/ratchet/v1/jobs/a1b2c3d4-e5f6-7890-1234-567890abcdef \
  -H 'Authorization: Bearer YOUR_API_TOKEN'
```
