## Keeping Your Corkboard Safe: A Guide to Automatic Database Backups

Corkboard is fantastic – but losing your notes would be devastating! This guide walks you through setting up automatic database backups for your self-hosted Corkboard instance, employing cron scheduling and detailing backup storage & restoration procedures.  We'll assume a standard Linux environment (like Ubuntu or Debian) where you have SSH access and sufficient permissions to run commands as the user running Corkboard.

**Understanding the Basics: Where are Your Databases?**

Corkboard typically utilizes SQLite databases for storing your notes. The default location is often `/var/lib/corkboard/database.db`. You *must* verify this path; check your `config.php` file within your Corkboard installation directory – it will specify the `DATABASE_PATH` setting. **Incorrect paths are the biggest error source, so confirm it!**

**1. Creating a Backup Script:**

The foundation of automatic backups is a script that safely exports your database.  Let's create a simple bash script (let's call it `corkboard-backup.sh`) in `/opt/scripts`:

```bash
#!/bin/bash

# --- Configuration (Customize these) ---
DATABASE_PATH="/var/lib/corkboard/database.db" # CHANGE THIS TO YOUR ACTUAL DATABASE PATH!
BACKUP_DIR="/mnt/backups/corkboard"       # Where you want to store backups - create this directory first!
DATE=$(date +'%Y-%m-%d_%H-%M-%S')
BACKUP_FILE="$BACKUP_DIR/corkboard-$DATE.db"

# --- Script Body ---
echo "Starting Corkboard backup..."

# Create the backup directory if it doesn't exist (important!)
mkdir -p "$BACKUP_DIR"

# Perform the SQLite database dump
sqlite3 "$DATABASE_PATH" .dump > "$BACKUP_FILE"

if [ $? -eq 0 ]; then  # Check for successful execution of sqlite3
    echo "Backup created successfully: $BACKUP_FILE"
else
    echo "ERROR: Backup failed!" >&2 # Redirect error to stderr
    exit 1;
fi

# (Optional) Implement a cleanup routine here – keep only X backups.  See section 4 below.

echo "Corkboard backup complete."
```

**Explanation:**

*   `#!/bin/bash`: Specifies the interpreter for the script.
*   `DATABASE_PATH`: **This is critical! Double-check it.**
*   `BACKUP_DIR`: Where your backups will be saved. Create this directory *before* running the script (e.g., `sudo mkdir /mnt/backups/corkboard`). Consider using a separate hard drive or network storage for disaster recovery.
*   `DATE`:  Generates a unique timestamp for each backup file.
*   `BACKUP_FILE`: Constructs the full path and filename of your database dump.
*   `mkdir -p "$BACKUP_DIR"`: Creates the backup directory if it doesn’t exist, avoiding errors. This ensures that the script always has somewhere to save its backups.
*   `sqlite3 "$DATABASE_PATH" .dump > "$BACKUP_FILE"`:  This is the core command. `sqlite3` executes SQLite commands on your database. `.dump` instructs it to export the entire database content into a SQL dump file, which is then redirected (`>`) to the `$BACKUP_FILE`.
*   The `if [ $? -eq 0 ]` statement checks if the previous command (the backup) completed successfully using the exit code. If successful ($? = 0), it prints a success message; otherwise it reports an error and exits with a non-zero status to indicate failure.

**2. Making the Script Executable:**

Give your script execution permissions:

```bash
sudo chmod +x /opt/scripts/corkboard-backup.sh
```

**3. Scheduling Backups with Cron:**

Edit your user's crontab (the same user that runs Corkboard). Usually, this is done with `crontab -e`.  Add a line similar to this:

```cron
0 2 * * * /opt/scripts/corkboard-backup.sh >/dev/null 2>&1
```

**Explanation:**

*   `0 2 * * *`: This schedule tells cron to run the script at 2:00 AM every day. Adjust this based on your needs (consider off-peak hours).  Use a cron schedule generator online if needed.
*   `/opt/scripts/corkboard-backup.sh`: The full path to your backup script.
*   `>/dev/null 2>&1`: This redirects both standard output and standard error to `/dev/null`, suppressing email notifications from the script (unless there's a severe failure reported in the script itself).

**4.  (Optional) Backup Cleanup:**

To avoid filling up your storage, implement cleanup. Add these lines *within* the `corkboard-backup.sh` script *after* the successful backup:

```bash
# Keep only the last 7 backups
find "$BACKUP_DIR" -type f -name "corkboard-*.db" -mtime +7 -delete
```

This will delete any backup files older than 7 days. Adjust `+7` to your desired retention period.

**5. Restoring From a Backup:**

To restore from a backup, stop the Corkboard application (if running).  Then:

1.  Navigate to the backup directory.
2.  Identify the `.db` file corresponding to the desired time.
3.  Execute this command in your terminal, *replacing `YOUR_BACKUP_FILE.db` with the actual filename*:

    ```bash
    sqlite3 /var/lib/corkboard/database.db < YOUR_BACKUP_FILE.db
    ```

4. Restart Corkboard.



**Important Considerations:**

*   **Testing:** *Always* test your backup and restoration process before relying on it! Create a simple note, then verify you can successfully restore from its generated backup.
*   **Permissions:** Ensure the user running Corkboard has sufficient permissions to both read the database file and write to the backup directory.
*   **Storage Location:** Choose a reliable storage location for your backups – ideally off-site or on separate hardware.



By following these steps, you’ll significantly increase the safety of your valuable Corkboard notes and peace of mind!
