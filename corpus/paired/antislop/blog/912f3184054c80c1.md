## Tired of News Videos Starting Automatically? Build Your Own Extension!

We've all been there: refreshing your news feed only to be assaulted by an autoplaying video blasting from somewhere. It’s annoying, disruptive, and often uses up valuable data. Instead of just suffering, you can actually *do* something about it! This post walks through creating a simple Chrome extension that blocks these rogue videos on frequently visited news sites.

**The Core Idea: Blocking with Simple JavaScript**

Our strategy is straightforward: we’ll inject a small script into webpages to monitor for and pause any video elements that begin playing automatically.  The core logic will involve checking `video.currentTime > 0` (meaning the video has started) and then calling `video.pause()`. Repeatedly, of course – because videos are persistent.

**Building the Manifest: The Foundation**

Every Chrome extension needs a `manifest.json` file that tells Chrome how to handle your code. Here’s an example.  Let's break down some key pieces:

```json
{
  "manifest_version": 3,
  "name": "Autoplay Blocker",
  "version": "1.0",
  "description": "Blocks autoplaying videos on news websites.",
  "permissions": [
    "activeTab",
    "scripting"
  ],
  "background": {
    "service_worker": "background.js"
  },
  "content_scripts": [
    {
      "matches": ["https://www.example-news-site1.com/*", 
                   "https://www.example-news-site2.com/*"], // Add your frequently visited sites!
      "js": ["content.js"]
    }
  ]
}
```

*   **`manifest_version`: 3** – Specifies the Manifest format version (important to use a supported one).
*   **`permissions`**: This is critical. `activeTab` allows us to interact with currently open tabs, and more importantly `scripting` which lets us inject our scripts. Without these permissions, your extension simply won't work!
*   **`content_scripts`**:  This section defines when and where our script (`content.js`) will run. The `"matches"` array lists the URLs (using wildcard patterns) where we want to apply this blocking behavior. **You *must* customize these with your target news sites.**

**The Blocking Script: `content.js`**

Here’s what a basic `content.js` might look like:

```javascript
function blockAutoplay() {
  const videos = document.querySelectorAll('video');
  videos.forEach(video => {
    if (video.currentTime > 0) {
      video.pause();
    }
  });
}

setInterval(blockAutoplay, 2000); // Check every 2 seconds
```

**The Unexpected Challenge: Lazy-Loaded Iframes**

While the basic setup worked wonderfully for many sites, I ran into a really interesting (and frustrating) bug. On several news sites that used lazy-loaded iframes to hold videos, my script *wasn’t* catching them. The problem?  These iframes loaded their content asynchronously, meaning the `<video>` elements simply weren't present when our `content.js` initially scanned the DOM.

The fix was straightforward: adding a MutationObserver that listened for changes in those specific iframes and re-ran `blockAutoplay()` whenever new content appeared within them. It meant digging into how each site structured their lazy loads, but it made the blocking significantly more reliable!



**Getting Started:** Load your manifest and script files as an unpacked extension from Chrome's Extensions page (chrome://extensions/). Customize that `matches` array, test thoroughly, and enjoy a less noisy browsing experience.
