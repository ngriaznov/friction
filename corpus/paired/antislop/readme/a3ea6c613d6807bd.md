# wavtag - Metadata Manipulation for WAV Files

`wavtag` is a lightweight C library designed to read and modify metadata chunks (LIST/INFO tags) within WAV audio files without altering the underlying audio sample data itself. It provides simple API functions for opening, reading, writing, and closing WAV files specifically targeting their extended headers.

## Features:

* **Targeted Metadata Modification:** Only modifies LIST/INFO chunks; leaves PCM data untouched.
* **Simple API:** Easy-to-use functions for metadata access and manipulation.
* **Platform Independent:**  Designed with byte-order considerations in mind (see below).
* **Minimal Dependencies:** Requires only a standard C compiler and minimal library support.

## Build Instructions:

The project uses `make` for building. Assuming the source code is located in a directory named `wavtag`, follow these steps:

1.  **Navigate to the Directory:** `cd wavtag`
2.  **Build:** `make`

This will create a library file (`libwavtag.a`) and header files which can be linked against your application.

## Public API:

The main functions available for use are declared in `wavtag.h`.

*   **`int wavtag_open(const char *filename, enum WAVTAG_TYPE *type)`:**
    *   Opens the specified WAV file and identifies its type (WAVTAG_TYPE).
    *   Returns 0 on success, non-zero on failure.
    *   Sets `*type` to one of: `WAVTAG_TYPE_NONE`, `WAVTAG_TYPE_INFO1`, `WAVTAG_TYPE_INFO2`, etc. (defined in `wavtag.h`).

*   **`int wavtag_read(enum WAVTAG_TYPE type, const char **data, size_t *size)`:**
    *   Reads the contents of a specific metadata chunk (`type`) from the opened file.
    *   Populates `*data` with a pointer to the tag data (allocated internally) and `*size` with its size in bytes.
    *   Returns 0 on success, non-zero on failure.  The caller is responsible for freeing the memory pointed by `*data`.

*   **`int wavtag_write(enum WAVTAG_TYPE type, const char *data, size_t size)`:**
    *   Writes a new (or modified) metadata chunk (`type`) to the opened WAV file.  Overwrites any existing tag of the same type.
    *   Returns 0 on success, non-zero on failure.

*   **`int wavtag_close()`:**
    *   Closes the currently opened WAV file. Must be called after using other functions.
    *   Returns 0 on success, non-zero on failure.

## Byte Order Handling:

Metadata chunks are often stored with little-endian byte order (typical of Intel architectures). `wavtag` attempts to handle this by providing a build configuration option (`USE_BIGENDIAN`) that can be defined at compile time using `-D USE_BIGENDIAN`.  This will swap the byte order when reading and writing fields in tags.

**To enable big-endian handling:**

```bash
make CFLAGS="-D USE_BIGENDIAN"
```

It is crucial to choose the correct configuration based on your target platform and the expected byte order of existing WAV files. Incorrect settings can lead to corrupted metadata or failed processing.
