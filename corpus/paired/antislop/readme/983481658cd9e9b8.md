# confkeep: Configuration Parsing with Formatting Preservation

## Motivation: Why Another Configuration Parser?

Python's standard library offers `configparser` for parsing INI-style configuration files. While functional, it suffers from a critical limitation when dealing with user-created configuration files: **it aggressively removes comments and blank lines during parsing.**  This makes round-tripping (reading the file, modifying values in code, then writing the modified content back to the same file) extremely painful because you lose all the original formatting.

Confkeep addresses this issue by providing a parser that strives to preserve the complete structure of the configuration file, including comments and blank lines. This is crucial for configurations heavily commented or formatted with specific spacing – situations common when working on shared projects or distributed systems where human readability matters.  Confkeep allows you to safely modify values programmatically without destroying the formatting established by the user.

## Installation

```

## Usage Example: Read, Modify, Write

Here's a simple example showing how to read a configuration file, change a value, and write it back out while maintaining formatting:

**`config.ini` (Example Configuration File):**

```ini
; This is a global setting
[global]
setting1 = value1  ; A comment describing this setting
setting2 = value2

[section1]
; Another section with a more elaborate description
setting3 = value3
# And another important note!
setting4 = value4

[section2]
setting5 = value5
```

**Python Code:**

```python
from confkeep import ConfigKeep

# Read the configuration file
config = ConfigKeep.from_file("config.ini")

# Modify a setting
config["section1"]["setting3"] = "new_value"

# Write the modified configuration back to the file, preserving formatting
config.write_to_file("config.ini", encoding="utf-8") # Specify encoding if needed

print("Configuration updated in config.ini")
```

After running this code, `config.ini` will contain:

```ini
; This is a global setting
[global]
setting1 = value1  ; A comment describing this setting
setting2 = value2

[section1]
; Another section with a more elaborate description
setting3 = new_value # The existing comment is preserved!
# And another important note!
setting4 = value4

[section2]
setting5 = value5
```

Notice that the comment associated with `setting3` has been retained.  This demonstrates Confkeep's commitment to formatting preservation.

## Supported Syntax Quirks & Considerations

Confkeep attempts to handle as many common INI-style configuration quirks as possible:

* **Inline Comments:** Supports comments starting with `;` or `#`.
* **Multi-line Values:** Handles values that span multiple lines within a section, delineated by line breaks in the original file. The structure of these multiline entries is kept when writing back out.
* **Blank Lines:**  Preserves blank lines between sections and values to maintain visual readability.
* **Section Inheritance (Limited):** While `configparser` supports inheritance with `[section:inheritance]`, Confkeep does *not* implement full inheritance logic. Parsing these will work, but writing back out changes won't automatically propagate down the inheritance chain – preserving their formatting is prioritized over complete feature parity with `configparser`.  You can still access and modify inherited values, but updates will only impact the specific section being written.
* **Encoding:** When using `ConfigKeep.from_file()` or `write_to_file()`, it’s generally recommended to specify an encoding (like "utf-8") explicitly to avoid potential encoding issues.

## API Summary

* **`ConfigKeep.from_file(filepath, encoding=None)`**: Reads a configuration file from the specified path and returns a `ConfigKeep` object.
* **`ConfigKeep.from_string(config_string, encoding=None)`**: Parses a string containing INI-style configuration data.
* **`ConfigKeep.write_to_file(filepath, section=None, encoding='utf-8')`**: Writes the current `ConfigKeep` object back to a file at the specified path.  The optional `section` argument allows you to selectively write out only certain sections of the configuration.

## Limitations & Future Development

* **Inheritance:** As mentioned above, full inheritance functionality is not supported.
* **Advanced Formatting:** While Confkeep strives for formatting preservation, incredibly complex formatting (e.g., inconsistent indentation levels) might occasionally be altered slightly during parsing and writing.  The goal is to minimize any changes.
* **Section Ordering Preservation**: The order of sections in the original file is generally preserved when reading and writing.

Future development may include:

* Improved handling of edge-case formatting scenarios.
* More sophisticated inheritance support (potentially with options for controlling how it's handled).
