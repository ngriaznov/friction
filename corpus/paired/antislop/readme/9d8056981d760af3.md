# invoicer4j: Java Library for Generating PDF Invoices

invoicer4j is a lightweight Java library designed to simplify the creation of professional-looking PDF invoices from data objects using customizable templates. It leverages an underlying, existing PDF layout engine (currently assumed to be iText but this could be abstracted in future versions) and provides a streamlined approach to defining templates, populating them with invoice details, and generating the final PDF file.

## Features

* **Template-Driven Generation:** Easily create invoices using configurable XML templates that separate presentation logic from business data.
* **Data Binding:** Populate templates with your invoice objects without complex coding.
* **Currency Support:** Handles multiple currencies and automatically formats numbers according to locale settings.
* **Locale-Aware Formatting:**  Provides flexible number formatting (currency, percentages, decimals) based on the selected locale.
* **Simple Integration:** Straightforward Maven dependency management for easy integration into your Java projects.

## Dependencies

To use invoicer4j, add the following dependency to your `pom.xml` file:

```xml
<dependency>
  <groupId>com.example.invoicer4j</groupId> <!-- Replace with your actual group ID -->
  <artifactId>invoicer4j</artifactId>
  <version>1.0.0</version> <!-- Replace with the latest version -->
</dependency>

<!-- Dependency on an underlying PDF layout engine (e.g., iText) is REQUIRED, but managed outside invoicer4j -->
<!-- Example for iText 7: -->
<dependency>
    <groupId>com.itextpdf</groupId>
    <artifactId>itext7-core</artifactId>
    <version>7.2.3</version> <!-- Use the latest stable version -->
</dependency>

```

**Important:** `invoicer4j` relies on a core PDF layout engine (such as iText).  You **must** include this dependency in your project alongside invoicer4j. The specific version of iText you choose will depend on your overall project requirements and compatibility constraints. This is not managed directly by invoicer4j itself.

## Minimal Code Sample

Here's a basic example illustrating how to generate an invoice:

```java
import com.example.invoicer4j.InvoiceGenerator;
import com.example.invoicer4j.model.InvoiceData;
import java.io.File;
import java.util.ArrayList;
import java.util.List;

public class InvoiceExample {

    public static void main(String[] args) {
        // 1. Prepare the data
        InvoiceData invoice = new InvoiceData();
        invoice.setInvoiceNumber("INV-2023-001");
        invoice.setDateIssued("2023-10-27");
        invoice.setCustomerName("Acme Corporation");
        invoice.setCustomerAddress("123 Main St, Anytown");

        List<InvoiceData.LineItem> items = new ArrayList<>();
        items.add(new InvoiceData.LineItem("Software License", 500.00));
        items.add(new InvoiceData.LineItem("Consulting Services", 250.00));
        invoice.setItems(items);

        invoice.setCurrency("USD"); // Example: US Dollars

        // 2. Create the generator
        InvoiceGenerator generator = new InvoiceGenerator();

        // 3. Generate the invoice (Assuming "invoice_template.xml" exists)
        try {
            generator.generateInvoice(invoice, "invoice_template.xml", "/tmp/invoice.pdf");
            System.out.println("Invoice generated successfully at /tmp/invoice.pdf");
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

## Template Definition (XML Layout Format)

invoicer4j uses a simple XML format for defining invoice templates.  Here's an example of what a basic `invoice_template.xml` might look like:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<template>
    <header>
        <h1>Invoice</h1>
        <p>Invoice Number: ${invoiceNumber}</p>
        <p>Date Issued: ${dateIssued}</p>
    </header>

    <customer>
        <h2>To</h2>
        <p>${customerName}</p>
        <p>${customerAddress}</p>
    </customer>

    <items>
        <table>
            <tr>
                <th>Description</th>
                <th>Amount</th>
            </tr>
            #foreach($item in $items)
              <tr>
                <td>$item.description</td>
                <td>${item.amount}</td>
              </tr>
            #end
        </table>
    </items>

    <footer>
        <p>Total: ${total}</p>
        <p>Currency: ${currency}</p>
    </footer>
</template>
```

* **`${variable}`:** This syntax is used to reference fields from the `InvoiceData` object.  For example, `${invoiceNumber}` will be replaced with the actual invoice number provided in the data.
* **`#foreach`:** Enables iterating through lists (like items). `$item.description` accesses properties of each list element.
* **Customization:** This provides a basic structure; more sophisticated formatting (fonts, colors, layout) is handled by the underlying PDF rendering engine and can be controlled via additional directives available in that engine's documentation.

## Supported Currencies & Locale-Aware Formatting

invoicer4j supports various currencies through standard currency codes (e.g., USD, EUR, GBP). The `InvoiceData` class includes a `currency` field which is used to format numerical values correctly using the appropriate currency symbol and placement.  The number formatting is locale-aware; by setting the appropriate locale during initialization or configuration of your PDF rendering engine (iText for example), you ensure that numbers are displayed in a manner consistent with regional conventions.

## Known Limitations

* **Multi-Page Invoices:** Currently, invoicer4j does *not* directly support automatic handling of invoices spanning multiple pages. Templates will be processed sequentially and the generated document won't break lines or adjust formatting to prevent content overflow.  Implementing pagination is a planned future enhancement but requires significant changes in both template parsing and layout management.
* **Advanced Formatting:** Template customization options are currently limited to variable substitution and basic iteration. Complex graphical elements, highly customized fonts, or intricate layout designs may require more advanced manipulation of the underlying PDF library directly (e.g., using iText's APIs).  While invoicer4j simplifies many common invoice creation scenarios, it is designed as a streamlined layer *on top* of that lower-level tooling.
* **Template Validation:** The parser provides minimal template validation. Ensure your XML templates are correctly formatted and reference existing data properties to avoid runtime errors.

## Future Development

Planned improvements include:

* Support for multi-page invoices with automatic pagination.
* Expanded template directives for more advanced formatting options (fonts, colors, conditional rendering).
