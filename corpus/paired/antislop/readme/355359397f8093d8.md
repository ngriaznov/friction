# Feedwell - Your Self-Hosted RSS & Atom Reader

Feedwell is a lightweight, self-hosted RSS and Atom feed reader designed for simplicity and flexibility. It provides a clean web interface and powerful organizational features while allowing you to retain complete control over your data.  Designed to be easily deployed behind any Python WSGI server (like Gunicorn or uWSGI), Feedwell prioritizes ease of setup and maintenance.

## Features

* **Folder Organization:** Categorize feeds into folders for easy management and navigation. Create unlimited hierarchies to suit your reading habits.
* **Read/Unread Tracking:** Mark articles as read, allowing you to quickly identify what remains to be consumed.  Filtering options let you view only unread items.
* **Full-Text Search:** Robust search capabilities allow you to find specific content across all cached articles. Easily locate information even within lengthy posts.
* **Automatic Article Downloading (Caching):** All downloaded articles are permanently stored, ensuring availability even if the original source changes or goes offline. This also enables full-text indexing for efficient searching.
* **OPML Import/Export:** Seamlessly import and export your feeds using the standard OPML format. Easily migrate between readers or share your subscriptions with others.
* **Clean & Intuitive Web UI:**  The user interface is designed to be minimal, focused on readability, and easy to navigate.
* **WSGI Compatibility:** Deployable behind any WSGI server – choose your preferred deployment stack without limitations.
* **Multiple Database Backends:** Supports SQLite (default) for ease of setup or PostgreSQL for higher performance in production environments with larger volumes of feeds and articles.
* **Secure Admin Interface:** Manage users, feeds, and application settings through a protected administrative interface.

## Installation from Source

**Prerequisites:**

* Python 3.7+
* `git` (for cloning the repository)
* A WSGI server (e.g., Gunicorn, uWSGI)

**Steps:**

1. **Clone the Repository:**

   ```bash
   git clone https://github.com/your-username/feedwell.git  # Replace with your actual repository URL
   cd feedwell
   ```

2. **Create a Virtual Environment (Highly Recommended):**

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate  # On Linux/macOS
   # OR
   .\.venv\Scripts\activate  # On Windows
   ```

3. **Install Dependencies:**

   ```bash
   pip install -r requirements.txt
   ```

4. **Configuration (Database Setup):**

   Feedwell defaults to using SQLite for storage. The database file will be created in the `data/` directory by default. To use PostgreSQL, you’ll need to configure it as described below.  For now we’ll proceed with the SQLite default:

5. **Run Database Migrations:**
    ```bash
    python feedwell/manage.py migrate
    ```

## First-Run Setup - Creating an Admin Account

Upon first launch, Feedwell requires you to create a system administrator account.

1. **Start the Development Server (Temporary):**  For ease of initial setup, you can use the built-in development server:

   ```bash
   python feedwell/manage.py runserver
   ```

   *This should only be used for local testing or getting started.* <u>Do not</u> expose this to a public network in production!

2. **Access the Setup Page:** Open your web browser and navigate to `http://localhost:8000/admin/setup`.  (Change the port if you specified one when starting the server).

3. **Create Your Admin Account:** Follow the on-screen instructions to create a username, password, and email for the administrator account. This user will have full access to all application settings and feeds.

## Database Backend Configuration

Feedwell defaults to using SQLite. To use PostgreSQL:

1. **Install `psycopg2`:**  Ensure you have the necessary database drivers installed.
   ```bash
   pip install psycopg2-binary
   ```

2. **Modify `.env` (Example):** Create a file named `.env` in the root of your Feedwell installation and configure PostgreSQL settings:

   ```
   DATABASE_URL=postgresql://user:password@host:port/database_name
   ```

   * Replace `user`, `password`, `host`, `port`, and `database_name` with your PostgreSQL connection details.

3. **Run Database Migrations (with PostgreSQL):**  The migrations will now create the necessary tables in your PostgreSQL database.  (This is required regardless of which DB you are using, to initialize).
    ```bash
    python feedwell/manage.py migrate
    ```



## Scheduling Feed Polling with Cron

Feedwell relies on regular polling to check for updates from subscribed feeds. This process should be automated using a scheduler like `cron` (Linux/macOS) or Task Scheduler (Windows).  The scheduling interval is configurable via the admin interface.

**Example cron job (Linux/macOS):**

1. **Edit your crontab:**
   ```bash
   crontab -e
   ```

2. **Add a line similar to this, adjusting paths and execution frequency as needed:**

   ```
   0 3 * * * /path/to/.venv/bin/feedwell-poller >/dev/null 2>&1
   ```

   * `/path/to/.venv/bin/feedwell-poller`:  This is the path to the `feedwell-poller` script located within your virtual environment (or wherever you've installed it). It’s responsible for fetching and processing feeds.
   * `0 3 * * *`: This schedule runs the poller at 3:00 AM every day. Adjust this according to how frequently you want the polls to execute (e.g., hourly, daily, weekly.)
   * `>/dev/null 2>&1`:  This redirects both standard output and standard error streams to `/dev/null`, preventing unnecessary emails or log entries. Consider changing if more verbose logging is required.

**Explanation of the Poller Script:**

The `feedwell-poller` script isn’t directly provided in this package, it would be a separate entry point that triggers a function in your feedwell module to perform fetching and updating of feeds. A typical implementation might use a task queue (like Celery) for efficiency, to minimize blocking during polling.
