## Thistle Configuration File Reference

This document details the configuration file format for Thistle, a static site generator designed for simplicity and flexibility. The primary configuration is handled through a YAML or TOML (both formats are supported) file named `thistle.yaml` or `thistle.toml` located in the root directory of your project. This file dictates global settings that apply to all pages unless overridden by front matter within individual content files.

**1. Top-Level Configuration Keys:**

The main configuration file supports four top-level keys: `title`, `base_url`, `theme`, and `output_dir`.  These define essential aspects of your site’s structure and appearance.

* **`title` (String, Required):**
    * **Description:** The title of your website. This appears in the `<head>` section as the page title and is used for SEO purposes. It's also likely to be displayed prominently on your homepage.
    * **Example:** `title: "My Awesome Website"`

* **`base_url` (String, Optional):**
    * **Description:** The base URL of your website. This is crucial if you plan to deploy your site to a subdirectory instead of the root domain.  Thistle will prepend this URL to all generated links. If omitted, it defaults to the current directory, which is appropriate for local development or deployment to the root.
    * **Example:** `base_url: "/blog"`  (This would generate links like `/blog/about` instead of `/about`)

* **`theme` (String, Optional):**
    * **Description:** Specifies the theme to use for your website. Themes control the overall visual style and layout. If omitted, Thistle uses a default theme. Theme names are case-sensitive.  Themes reside in the `themes/` directory within your project.
    * **Example:** `theme: "dark"`

* **`output_dir` (String, Optional):**
    * **Description:**  Specifies the directory where generated HTML files will be placed. If omitted, Thistle defaults to a directory named `public`.
    * **Example:** `output_dir: "_site"`



**2. Front Matter Overrides:**

Thistle allows you to override global configuration settings on a per-page basis using YAML or TOML front matter within your content files (e.g., `.md` or `.txt` files).  Front matter is enclosed between "---" delimiters at the beginning of the file.

* **Syntax:** Front matter must be placed immediately after the opening "---".
* **Precedence:** Front matter overrides values defined in the main configuration file. Values specified within a content's front matter take precedence over global settings.  Settings *not* present in the front matter will inherit from the top-level config.

**Supported Front Matter Keys (Overridable):**

The following keys can be overridden through front matter: `title`, `base_url`, and `theme`. The `output_dir` key **cannot** be overridden via front matter. This maintains consistency across your site’s structure.

* **Example:**  A page with the following content:

```yaml
---
title: "About Me"
theme: "minimalist"
---
# About Me Page Content
This is the content of my about me page.
```

This page would use `About Me` as its title, the globally defined `base_url`, and the `minimalist` theme instead of the global configuration's values.



**3. Example Configuration Files:**

Here are two complete example configuration files demonstrating different common scenarios: one using YAML and another using TOML.

**Example 1: Thistle (YAML - thistle.yaml)**

```yaml
title: "My Personal Blog"
base_url: "" # No subdirectory, deployed to root domain
theme: "default"
output_dir: "dist"

# Optional settings that could be included for future expansion
# language: en-US  # Example - not implemented yet
# favicon: /images/favicon.ico  #Example - not implemented yet
```

**Explanation:** This configuration sets the site title to “My Personal Blog”, deploys it to a root domain (no subdirectory), uses the default theme, and specifies that the generated files should be placed in a directory called `dist`. The commented-out lines demonstrate where future settings might be added.

**Example 2: Thistle (TOML - thistle.toml)**

```toml
title = "My Company Website"
base_url = "/company"  # Deployed to /company subdirectory
theme = "corporate"
output_dir = "build"


[[extra]] # Not directly related to config, but shows TOML extensibility
name = "analytics_id"
value = "UA-XXXXXXXXX-Y"

```

**Explanation:** This configuration sets the site title to “My Company Website”, deploys it to a subdirectory `/company`, uses the `corporate` theme and places output in the `build` folder. The `[[extra]]` section demonstrates how TOML allows for more complex data structures within the config file, showing a potential use case for tracking IDs or other site-specific information – though this isn't strictly part of core Thistle configuration.




**4.  File Format Choice (YAML vs. TOML):**

Thistle supports both YAML and TOML configuration files. Choose whichever format you prefer; the generator will automatically detect the file type based on its extension (`.yaml` or `.toml`). While functionally equivalent, they have different syntaxes:

* **YAML:** Relies heavily on indentation for structure.
* **TOML:** Uses a more structured key-value pair system with sections and tables.  Generally considered easier to read for complex configurations.



By understanding these configuration options and front matter overrides, you can tailor your Thistle site to precisely meet your needs and create a cohesive and visually appealing online presence. Refer to the core documentation for details on theme development and content formatting.
