## Building a Simple Webhook Receiver in Node.js with Hookline

Webhooks are powerful tools for integrating different services and automating workflows. They allow one application to notify another when something happens, eliminating the need for constant polling. However, building robust webhook receivers can be complex, especially concerning security – verifying that requests genuinely come from your expected source. This tutorial will guide you through building a basic webhook receiver in Node.js using Hookline, an elegant middleware library designed specifically for handling and securing webhooks.

**What is Hookline?**

Hookline simplifies webhook development by providing built-in functionality for:

* **Signature Verification:**  Ensuring the request originates from the expected source (e.g., Stripe, GitHub).
* **Middleware Support:** Allowing you to easily add custom logic before or after signature verification and payload processing.
* **Flexible Configuration:** Adapting to various webhook formats and signing methods.

**Prerequisites:**

* **Node.js & npm:** Make sure you have Node.js (version 14 or higher) and npm (Node Package Manager) installed on your system. You can download them from [https://nodejs.org/](https://nodejs.org/).
* **Basic JavaScript Knowledge:** Familiarity with JavaScript syntax and asynchronous programming is helpful.

**Step 2:  Creating the Webhook Receiver with Hookline**

1.  **Create `index.js` (or your preferred entry point file):** This is where our main server logic will reside. Paste the following code into `index.js`:

    ```javascript
    const express = require('express');
    const hookline = require('hookline');
    const crypto = require('crypto'); // For manual signature verification (optional)

    const app = express();
    const port = process.env.PORT || 3000;

    // Your secret key - KEEP THIS SECRET!  Store this in environment variables in production.
    const signingSecret = 'your-secret-key'; // IMPORTANT: Replace with your actual secret

    // Hookline instance configuration (replace placeholders with your specific webhook details)
    const hookOptions = {
        signingSecret: signingSecret,
        signatureHeaderName: "X-Signature",  // Common header name for signatures
        payloadType: 'json', // or 'form' if the payload is sent as form data.
    };

    const hook = new hookline(hookOptions);


    app.post('/webhook', async (req, res) => {
        try {
            await hook.validateHook(req, res);  // Hookline handles signature verification and error responses

            console.log('Webhook validated successfully!');
            // Here you can process the webhook payload
            const payload = req.body; // Access the parsed JSON body if payloadType is 'json'
            console.log('Received Payload:', payload);


            res.status(200).send('OK');  // Respond with 200 to acknowledge receipt (important for most webhook providers)

        } catch (error) {
            console.error('Webhook validation error:', error);
            if (error.message === 'invalid signature') {
                res.status(401).send('Unauthorized: Invalid Signature'); // Specific 401 for signature failures
            } else {
               res.status(400).send(`Bad Request: ${error.message}`);  // General error status code
            }

        }
    });


    app.listen(port, () => {
        console.log(`Webhook receiver listening on port ${port}`);
    });
    ```

2. **Explanation:**

   * `require('express')`: Imports the Express framework for creating our web server.
   * `require('hookline')`:  Imports the Hookline library.
   * `crypto`: This is imported optionally to demonstrate manual signature verification, which isn't strictly necessary when using Hookline's automatic validation.
   * `app = express()`: Creates an Express application instance.
   * `port`: Defines the port the server will listen on (defaults to 3000).  It reads from environment variables if they are set, a best practice for deployment.
   * `signingSecret`: **CRITICAL!** This is your secret key used to generate and verify signatures. *Never* commit this directly in your code. Store it securely using environment variables or a secrets management system.
   * `hookOptions`:  This object configures Hookline:
        * `signingSecret`:  The shared secret for signature verification.
        * `signatureHeaderName`: The name of the HTTP header containing the webhook signature (common values are "X-Signature", "Authorization").
        * `payloadType`: Specifies how the payload is sent - 'json' or 'form'. Adjust based on what your webhook provider sends.
   * `hook = new hookline(hookOptions)`: Creates a Hookline instance with the specified options.  This handles all signature verification logic.
   * `/webhook` route: This is where incoming webhooks will be sent. The `async` function allows us to use `await` for asynchronous operations.
   * `hook.validateHook(req, res)`: This is the core of Hookline's functionality.  It automatically verifies the signature based on your configuration and sends an appropriate error response if verification fails (e.g., a 401 Unauthorized). It also handles parsing JSON payloads when `payloadType` is set to `'json'`.
   * Error Handling: The `try...catch` block catches errors during validation and provides tailored responses.  A 401 status code indicates an invalid signature, while other errors receive a general 400 Bad Request response.
   * `res.status(200).send('OK')`:  **Crucially important:** This sends a 200 OK response to the webhook provider after successful verification. Many providers *require* this acknowledgment; failure to send it can result in repeated attempts and potentially being blocked.
