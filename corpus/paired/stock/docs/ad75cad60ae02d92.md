## Ratchet Task Queue Service - REST API Reference

This document details the REST API endpoints for Ratchet, a task queue service designed for asynchronous processing of jobs.  Ratchet provides a simple, reliable mechanism to offload long-running tasks from your main application thread, improving responsiveness and overall system performance. This reference covers job enqueueing, status checking, and cancellation.

**Base URL:** `https://ratchet.example.com/api/v1` (Replace with your actual Ratchet instance's base URL)

**Authentication:** All API requests require authentication via a bearer token in the `Authorization` header.  Obtain a token through the appropriate user management interface for your Ratchet deployment.

*   **Header:** `Authorization: Bearer <your_api_token>`

**Data Format:** The primary data format is JSON.

---

### 1. Enqueueing a Job (POST /jobs)

This endpoint creates and enqueues a new job into the task queue.  The job definition specifies the work to be performed, associated data, and optional priority settings.

**Method:** `POST`
**URL:** `/jobs`
**Request Body (JSON):**

```json
{
  "worker": "image_processor",   // Required: Name of the worker responsible for handling this job type.
  "payload": {                   // Required: Data passed to the worker as a JSON object.
    "image_url": "https://example.com/image.jpg",
    "resize_dimensions": [100, 150]
  },
  "priority": 2                 // Optional: Integer representing job priority (lower value = higher priority). Defaults to 3.
}
```

**Parameters:**

*   `worker`: **(String, Required)** The name of the worker responsible for executing this job type. Ratchet will route the job to a worker registered with this name.  Worker registration is handled separately by the system administrator.
*   `payload`: **(JSON Object, Required)** A JSON object containing data necessary for the worker to perform its task. This payload is passed directly to the worker as-is.
*   `priority`: **(Integer, Optional)** An integer representing job priority. Lower numbers indicate higher priority (e.g., 1 is highest, 5 is lowest).  The default priority is `3`.

**Response Codes:**

*   `201 Created`: Job successfully enqueued. The response body contains the newly created job's ID.
*   `400 Bad Request`: Invalid request body or missing required parameters.  The response body will contain an error message detailing the problem (e.g., invalid JSON, missing `worker` field).
*   `401 Unauthorized`: Authentication failed.
*   `500 Internal Server Error`: An unexpected server-side error occurred.

**Example Curl Request:**

```bash
curl -X POST \
  https://ratchet.example.com/api/v1/jobs \
  -H 'Authorization: Bearer <your_api_token>' \
  -H 'Content-Type: application/json' \
  -d '{
    "worker": "image_processor",
    "payload": {
      "image_url": "https://example.com/image.jpg",
      "resize_dimensions": [100, 150]
    },
    "priority": 1
  }'
```

**Example Successful Response (201 Created):**

```json
{
  "job_id": "a1b2c3d4e5f67890"
}
```

### 2. Checking Job Status (GET /jobs/{job_id})

This endpoint retrieves the current status of a job with a specific ID. It provides information about whether the job is pending, running, completed successfully, or failed.

**Method:** `GET`
**URL:** `/jobs/{job_id}`  (Replace `{job_id}` with the actual job ID)

**Response Codes:**

*   `200 OK`: Job found and status returned successfully. The response body contains the job details in JSON format (see example below).
*   `401 Unauthorized`: Authentication failed.
*   `404 Not Found`:  Job with the specified ID does not exist.
*   `500 Internal Server Error`: An unexpected server-side error occurred.

**Response Body (JSON):**

```json
{
  "job_id": "a1b2c3d4e5f67890",
  "worker": "image_processor",
  "status": "pending",          // Can be: pending, running, completed, failed
  "payload": {
    "image_url": "https://example.com/image.jpg",
    "resize_dimensions": [100, 150]
  },
  "priority": 1,
  "created_at": "2023-10-27T10:00:00Z",
  "updated_at": "2023-10-27T10:00:00Z",
  "result": {                    // Only present if status is 'completed'
    "resized_image_url": "https://example.com/resized_image.jpg"
  },
  "error": "Network timeout"     // Only present if status is 'failed'
}
```

**Possible Status Values:**

*   `pending`: Job is waiting to be processed by a worker.
*   `running`: Job is currently being executed by a worker.
*   `completed`: Job has finished successfully.  The `result` field will contain the output of the job.
*   `failed`: Job encountered an error during execution. The `error` field will contain details about the failure.

**Example Curl Request:**

```bash
curl -X GET \
  https://ratchet.example.com/api/v1/jobs/a1b2c3d4e5f67890 \
  -H 'Authorization: Bearer <your_api_token>'
```

### 3. Cancelling a Pending Job (DELETE /jobs/{job_id})

This endpoint cancels a pending job, preventing it from being processed by any worker. Once a job is running or completed, cancellation is not possible.  Cancellation requests for jobs in those states will return a `400 Bad Request` error.

**Method:** `DELETE`
**URL:** `/jobs/{job_id}` (Replace `{job_id}` with the actual job ID)

**Response Codes:**

*   `204 No Content`: Job successfully cancelled.  No response body is returned.
*   `400 Bad Request`: Job cannot be cancelled because it's already running or completed. The response body will contain an error message indicating the reason for failure.
*   `401 Unauthorized`: Authentication
