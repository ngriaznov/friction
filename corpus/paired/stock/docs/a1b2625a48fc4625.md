## Automating Database Backups for Your Self-Hosted Corkboard Instance

Running your own instance of Corkboard gives you great control over your notes, but it also means responsibility for its upkeep – including backups! This guide will walk you through setting up automated database backups using `cron`, ensuring you can recover from data loss due to hardware failure, accidental deletion, or application errors.  We'll cover scheduling, storage location, and restoration steps.

**Prerequisites:**

*   **SSH Access:** You’ll need SSH access to your server where Corkboard is installed.
*   **Corkboard Installation:** This guide assumes you have a working Corkboard installation (e.g., Dockerized or direct install).  Specific paths will vary based on your setup, so adjust them accordingly.
*   **Basic Linux Command Line Familiarity:** You should be comfortable navigating the command line and editing text files.

**1. Understanding Your Database Type & Backup Tools**

Corkboard typically relies on SQLite for its data storage. Therefore, we'll use `sqlite3`’s built-in backup capabilities.  If you are using a different database (highly unlikely with standard Corkboard installations), replace `sqlite3` commands with the appropriate tools for that system (e.g., `mysqldump` for MySQL).

**2. Defining Your Backup Strategy: Location & Naming**

*   **Backup Storage Location:** Decide where to store your backups.  Ideally, this should be *off-site* from your Corkboard server – a different physical machine or cloud storage (like Amazon S3 or Google Cloud Storage) is best for disaster recovery. For simplicity in this guide, we’ll assume an internal directory `/var/backups/corkboard`. **Create this directory:** `sudo mkdir -p /var/backups/corkboard`
*   **Backup Naming Convention:** Consistent file naming helps with organization and restores.  We'll use a format like: `corkboard_backup_YYYYMMDDHHMMSS.db`. This includes the date and time of the backup.

**3. Creating the Backup Script**

Create a shell script to handle the backup process itself. Create a file (e.g., `/usr/local/bin/corkboard-backup.sh`) with the following content, *modifying it based on your Corkboard installation path*:

```bash
#!/bin/bash

# Database Path - CHANGE THIS TO YOUR ACTUAL CORkBOARD DATABASE PATH!
DB_PATH="/var/www/corkboard/data/corkboard.db" # Example Dockerized path

# Backup Location
BACKUP_DIR="/var/backups/corkboard"

# Timestamp for the filename
TIMESTAMP=$(date +%Y%m%d%H%M%S)

# Construct the backup filename
BACKUP_FILE="${BACKUP_DIR}/corkboard_backup_${TIMESTAMP}.db"

# Perform the backup using sqlite3
sqlite3 "$DB_PATH" .backup "$BACKUP_FILE"

# Optional: Compress the backup (reduces storage space, slows down restore)
# gzip "$BACKUP_FILE"  # Uncomment to enable compression. Be mindful of CPU load.

echo "Corkboard backup created: $BACKUP_FILE"
```

**Important:** Replace `/var/www/corkboard/data/corkboard.db` with the **actual path** to your Corkboard database file. This is critical!  Also, consider whether you want to compress the backups. If so, uncomment the `gzip` line, but be aware it will increase CPU usage during backup.

Make the script executable: `sudo chmod +x /usr/local/bin/corkboard-backup.sh`

**4. Scheduling Backups with Cron**

Cron is a time-based job scheduler in Linux.  Open your crontab for editing using: `crontab -e`. Add a line to schedule the backup script. For example, to run the backup daily at 2:00 AM:

```
0 2 * * * /usr/local/bin/corkboard-backup.sh >/dev/null 2>&1
```

*   `0 2 * * *`: This is the cron schedule – minute (0), hour (2), day of month (*), month (*), day of week (*).
*   `/usr/local/bin/corkboard-backup.sh`:  The path to your backup script.
*   `>/dev/null 2>&1`: This redirects the script's output and errors to `/dev/null`, preventing email notifications unless there’s a critical error (which should be visible in system logs).

**5. Restoring from a Backup File**

If disaster strikes, restoring is straightforward:

1.  **Locate the backup file:** Find the `corkboard_backup_YYYYMMDDHHMMSS.db` file you want to restore from.
2.  **Stop Corkboard:** Ensure your Corkboard instance is stopped before restoring.
3.  **Rename/Replace the current database:** Rename or delete your existing Corkboard database file (`/var/www/corkboard/data/corkboard.db` - adjust path as necessary).
4.  **Restore from Backup:** Copy the backup file to replace the original: `cp /var/backups/corkboard/corkboard_backup_YYYYMMDDHHMMSS.db /var/www/corkboard/data/corkboard.db` (adjust paths).
5.  **Start Corkboard:** Restart your Corkboard instance.

**Important Considerations:**

*   **Testing:** Regularly test your backup and restore process to ensure it works correctly.
*   **Retention Policy:** Implement a retention policy for old backups. Delete older backups periodically to save space.  You can add commands to the script to do this.
*   **Security:** Secure your backup directory with appropriate permissions (e.g., `chmod 700 /var/backups/corkboard`).



By following these steps, you’ll have a robust automated backup system for your Corkboard instance, providing peace of mind and ensuring data safety. Remember to adapt the paths and schedules to match your specific environment!
