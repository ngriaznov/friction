## Implementing a Simple Bump Allocator with Free List in C for Embedded Systems

Okay, let's dive into building a simple bump allocator with a free list in C, geared towards embedded systems where you often lack standard `malloc`/`free`. This approach trades off some efficiency and flexibility against simplicity and predictability – crucial factors in resource-constrained environments.  We’ll also cover fragmentation considerations.

**Why Not Just Standard `malloc`?**

Most embedded devices don't have the luxury of a full C runtime library with a robust, general-purpose memory allocator like `malloc`. These allocators (like glibc's `malloc`) are complex, often involve heap management, and can introduce timing unpredictability – unacceptable in many real-time or safety-critical applications. They also consume significant flash space for code and RAM for metadata.

**The Bump Allocator + Free List Approach: A Hybrid Solution**

Our solution aims to provide memory allocation while maintaining some level of control and predictability. It combines the simplicity of a bump allocator with the ability to reclaim previously allocated blocks using a free list.

**1. The Bump Allocator Foundation:**

A bump allocator works by simply incrementing a pointer ("the bump pointer") each time you need memory.  You allocate space by subtracting from this bump pointer, effectively reserving consecutive bytes/words. No complex metadata is stored (initially). This makes allocation *extremely* fast.

**2. Introducing the Free List:**

The basic bump allocator suffers from one major drawback: once allocated, memory is gone until the entire program ends.  To mitigate this, we introduce a free list.  This list keeps track of blocks that have been "bumped" but aren’t currently in use.  When you need to *deallocate* (more accurately, release) a block, it's added back onto this free list.

**Code Example (Simplified):**

```c
#include <stdint.h> // For portable integer types

typedef struct BlockHeader {
    size_t size;  // Size of the allocated block (needed for deallocation!)
} BlockHeader;

static uint8_t *bump_pointer;
static uint8_t *heap_start;  // Pointer to the beginning of our heap
static uint8_t *free_list_head; //Pointer to head of free list


void bump_allocator_init(uint8_t* start, size_t heap_size) {
    bump_pointer = start;
    heap_start = start;
    free_list_head = NULL;

    // Initial block:  The entire heap is one big free block initially.
    BlockHeader *initial_block = (BlockHeader*) bump_pointer;
    initial_block->size = heap_size - sizeof(BlockHeader); //Account for header space
    bump_pointer += sizeof(BlockHeader) + initial_block->size;
}

void* bump_alloc(size_t size) {
    //Ensure we don't go beyond the end of our heap.
    if (bump_pointer + size > heap_start + 1024) { //Example limit:  Adjust as needed!
        return NULL; // Allocation failed - out of memory
    }

    BlockHeader *block_header = (BlockHeader*) bump_pointer;
    block_header->size = size;
    bump_pointer += sizeof(BlockHeader) + size;

    return (void*)(bump_pointer - size - sizeof(BlockHeader)); //Return pointer to user space after header
}


void bump_free(void* ptr) {
  if (!ptr) return; //Handle null pointers gracefully.

  // Calculate the block header address based on the user-provided pointer
  BlockHeader *block_header = (BlockHeader*)ptr - 1; //Subtract one block to find header

  size_t size = block_header->size;

  //Add freed space back to free list, at head.
  BlockHeader* new_head = (BlockHeader*)(ptr);
  new_head->size = size;
  new_head->next = free_list_head; //Link to existing list.
  free_list_head = new_head;

}


//Example Usage:
int main() {
    uint8_t heap[1024];
    bump_allocator_init(heap, sizeof(heap));

    char *str = (char*) bump_alloc(32);  // Allocate space for a string
    if (str) {
        strcpy(str, "Hello, Embedded World!");
        printf("%s\n", str);
    }


    bump_free(str); // Release the memory

    return 0;
}
```

**Explanation:**

* `heap_start`: Points to the beginning of the allocated memory region.
* `bump_pointer`: Tracks the next available address for allocation. This is incremented with each call to `bump_alloc`.
* `free_list_head`:  Points to the first block in our free list.
* `BlockHeader`: Stores the size of the allocated block. Critically, this header *must* be present so we can determine the original size during deallocation (freeing).
* `bump_alloc()`: Allocates a block by advancing the `bump_pointer`. It returns a pointer to the user-accessible portion of the memory after the header.  Crucially checks for out-of-memory conditions.
* `bump_free()`: Adds an allocated block back to the free list.  Calculates the beginning of the BlockHeader, retrieves its size, and adds it to the head of the free list.

**Fragmentation:**

This scheme suffers from *external fragmentation*. Because blocks are allocated in order, deallocating blocks can leave gaps between remaining allocated regions. While we have a free list, finding an available block that’s exactly the right size is difficult.  There's no merging of adjacent freed blocks; this means small holes persist.

**Trade-offs & Considerations:**

* **Simplicity:** The code is relatively easy to understand and implement.
* **Speed:** Allocation (`bump_alloc`) is exceptionally fast – just pointer arithmetic. Deallocation (`bump_free`) is faster than standard `malloc` but involves list manipulation.
* **Predictability:**  Allocation order is predictable, which can be important for real-time systems.
* **Fragmentation:** External fragmentation *is* a significant issue. If the heap becomes highly fragmented, you may run out of usable memory even though there's technically free space.
* **No Fine-Grained Control:** You cannot deallocate individual blocks within an allocated region unless you're willing to keep track of offsets (making things more complex).  You only release entire contiguous regions.
* **Size Tracking Overhead:** The `BlockHeader` adds a small overhead to each allocation, reducing the usable memory slightly.



**Advanced Improvements (Beyond Simple):**

* **Best-Fit/First-Fit Free List Search:** Instead of always adding freed blocks to the head of the free list, implement search algorithms to find the best match for the requested size.
