# Feedwell: Your Self-Hosted RSS/Atom Feed Reader

Feedwell is a lightweight, self-hosted web application for reading RSS and Atom feeds. It offers a clean, minimalist user interface and prioritizes privacy, giving you complete control over your feed data. Designed to be easily deployed behind any WSGI server (like Gunicorn, uWSGI, or Waitress), Feedwell provides a personalized news aggregation experience without relying on third-party services.

## Features

*   **Folder Organization:** Organize your feeds into folders for better management and clarity. Create nested folder structures to categorize your subscriptions logically.
*   **Read/Unread Tracking:**  Mark articles as read to keep track of what you’ve already consumed. The status is persistent across sessions.
*   **Full-Text Search:** Powerful full-text search capabilities allow you to quickly find specific articles within your cached content, even across multiple feeds and folders.
*   **OPML Import/Export:**  Easily import existing feed subscriptions from OPML files (Open Publicly Available Media) or export your Feedwell collection for backup or migration.
*   **Caching:** Articles are cached locally, allowing you to read them even when the original source is unavailable.
*   **Minimalist Web UI:** A clean and intuitive web interface designed for focused reading.  No distracting ads or extraneous features.
*   **WSGI Compatibility:** Deployable behind any WSGI-compliant server, offering flexibility in your deployment environment.
*   **Customizable Polling Interval**: Control how often Feedwell checks for new articles in your feeds.

## Installation

Feedwell is packaged as a Python application and requires Python 3.7 or higher. It's highly recommended to use a virtual environment for isolation.

1.  **Clone the Repository:**
    ```bash
    git clone [Your Git Repository URL] feedwell
    cd feedwell
    ```

2.  **Create and Activate a Virtual Environment (Recommended):**
    ```bash
    python3 -m venv .venv
    source .venv/bin/activate   # On Linux/macOS
    .venv\Scripts\activate      # On Windows
    ```

3.  **Install Dependencies:**
    ```bash
    pip install -r requirements.txt
    ```

## First-Run Setup & Admin Account Creation

On the first run, Feedwell will guide you through creating an administrator account.

1.  **Run the Development Server:**
    ```bash
    python feedwell/app.py --debug  # Use --debug for development only!  Remove for production.
    ```
    (or whatever command your `run.sh` or equivalent might be)
2.  **Access the Setup Page:** Open a web browser and navigate to `http://127.0.0.1:5000/setup` (or the address shown in the server output).
3.  **Create Admin User:** Follow the on-screen instructions to create an initial administrator account. You'll be prompted for a username, email (optional), and password. This user will have full access to manage feeds, users, and application settings.

## Database Configuration

Feedwell uses a database to store feed subscriptions, articles, and user information.  By default, it utilizes SQLite, which is suitable for small to medium-sized deployments. PostgreSQL support is also available.

*   **SQLite (Default):**  No configuration required. Data is stored in `feedwell.db` located in the project's root directory.
*   **PostgreSQL:**
    1.  Install the `psycopg2` package: `pip install psycopg2-binary`
    2.  Create a PostgreSQL database and user for Feedwell.
    3.  Update the `DATABASE_URL` environment variable with your connection string. Example:
        ```bash
        export DATABASE_URL="postgresql://user:password@host:port/database"
        ```
        Or, set it in an environment file (e.g., `.env`) and load it using a library like `python-dotenv`.

## Configuration Options

Feedwell utilizes environment variables for configuration. Create a `.env` file in the project root directory to store these values (recommended).  Here are some important settings:

*   `DATABASE_URL`: The connection string to your database (e.g., "sqlite:///feedwell.db" or PostgreSQL URL).
*   `SECRET_KEY`: A secret key used for session management and security. Generate a strong, random value.
*   `DEBUG`: Set to `True` during development; **must be `False` in production.** This enables debugging features and detailed error messages.
*   `FEEDWELL_BASE_URL`: The base URL of your Feedwell instance (e.g., "https://yourdomain.com"). Used for generating absolute URLs.
*   `POLLING_INTERVAL`:  The interval (in seconds) at which feeds are polled. Default is 3600 (1 hour). Can be overridden per-feed.

## Scheduling Feed Polling with Cron

Feedwell's built-in polling functionality works well for basic use, but for more reliable and scheduled updates, it’s recommended to use a cron job to periodically restart the application or trigger a specific script that polls feeds.

1.  **Create a Script (Optional):** You can create a simple Python script that calls Feedwell's feed polling functions directly. This is useful if you want more control over the polling process.

2.  **Edit Crontab:** Use `crontab -e` to edit your crontab file.

3.  **Add Cron Job Entry:** Add a line like this to run Feedwell every hour (adjust as needed):

    ```
    0 * * * * /path/to/your/venv/.venv/bin/python /path/to/feedwell/app.py poll_feeds --debug # Or whatever your command is
    ```

    *   Replace `/path/to/your/venv/.venv/bin/python` with the actual path to your Python interpreter within the virtual environment.
    *   Replace `/path/to/feedwell/app.py` with the path to your Feedwell application file.
    *   `poll_feeds` is a placeholder; adjust if you have a specific script for polling, or remove the flag entirely and just run the app in question.
