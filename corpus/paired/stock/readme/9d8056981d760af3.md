## Template Definition (Simple XML Layout)

invoicer4j uses a simple XML-based template format to define the layout of your invoices.  Here's an example structure:

```xml
<invoice>
  <header>
    <invoiceNumber>{{invoiceNumber}}</invoiceNumber>
    <dateIssued>{{dateIssued}}</dateIssued>
    <dueDate>{{dueDate}}</dueDate>
  </header>
  <customer>
    <name>{{customerName}}</name>
    <address>{{customerAddress}}</address>
  </customer>

  <table>
    <columns>
      <column width="30%" />
      <column width="15%" />
      <column width="20%" />
      <column width="35%" />
    </columns>
    <tr>
      <th>Description</th>
      <th>Quantity</th>
      <th>Unit Price</th>
      <th>Total</th>
    </tr>
    {{#each lineItems}}  <!-- Loop through line items -->
    <tr>
      <td>{{description}}</td>
      <td>{{quantity}}</td>
      <td>{{price}}</td>
      <td>{{total}}</td>
    </tr>
    {{/each}}
  </table>

  <footer>
    <currency>{{currency}}</currency>
  </footer>
</invoice>
```

* **`{{variableName}}`:** Represents placeholders that will be replaced with data from the Java object.
* **`{{#each collection}} ... {{/each}}`:** Enables looping through collections (e.g., `lineItems`).
* Template elements and attributes are passed directly to the underlying [your layout engine] for rendering, allowing full control over styling through standard PDF formatting techniques.

## Supported Currencies & Locale-Aware Number Formatting

invoicer4j supports various currencies using ISO 4217 currency codes (e.g., "USD", "EUR", "GBP").  The `setCurrency()` method in the `InvoiceData` object specifies the currency for the invoice.

Locale-aware number formatting is enabled by setting the locale with `setLocale()`. This ensures that numbers (prices, quantities) are formatted according to the specified locale's conventions (e.g., using commas or periods as decimal separators).  The underlying [your layout engine] handles this formatting based on the provided locale.

## Known Limitations

* **Multi-Page Invoices:** Currently, invoicer4j does *not* inherently support multi-page invoices. The template and data object are processed to generate a single PDF file. To achieve multi-page functionality, you'll need to modify your templates and potentially extend the library's core logic or integrate with the underlying [your layout engine] directly for more advanced control over page breaks.
* **Complex Layouts:**  While invoicer4j provides flexibility through its template structure, extremely complex layouts might require a deeper understanding of the underlying PDF generation engine. 
* **Template Validation:** The library does not include built-in XML template validation. Ensure your templates are well-formed and correctly reference data fields to avoid errors during invoice generation.
