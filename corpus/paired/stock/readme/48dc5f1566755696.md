# csvtype: Typed CSV Reading in Rust

csvtype is a Rust crate that provides a convenient way to read CSV files and work with typed records instead of raw strings. It intelligently infers the data types of each column (integer, float, date, boolean, string) by sampling a subset of rows, eliminating the need for manual parsing and type conversions in many common scenarios.

## Features

* **Type Inference:** Automatically determines the data type of each CSV column based on a sample of rows.
* **Typed Record Iterator:** Exposes an iterator that yields typed records (`csvtype::Record<T>`) instead of `String` slices, simplifying subsequent processing.
* **Custom Type Support:**  Provides mechanisms to override inferred types and use custom data types for columns.
* **Date Parsing Flexibility:** Offers options for date format specifications.
* **Error Handling:** Provides robust error handling for parsing failures.

## Cargo.toml Installation

Add the following to your `Cargo.toml`:

```toml
[dependencies]
csvtype = "0.7" # Use latest version from crates.io

[dev-dependencies]
csv = "^1.3"  # Required as a peer dependency for testing and some examples.
chrono = { version = "0.4", features = ["serde"] } # For date parsing
```

## Example Usage: Inferring Schema & Typed Iteration

Let's say you have a CSV file named `data.csv` with the following content:

```csv
name,age,birthdate,is_active,score
Alice,30,2000-01-15,true,85.5
Bob,25,1998-05-20,false,92.0
Charlie,40,1985-12-01,true,78.2
```

Here's how you can read this file using `csvtype`:

```rust
use csvtype::{CsvReader, Record};
use chrono::NaiveDate;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let reader = CsvReader::from_path("data.csv")?
        .has_header(true)  // Indicate that the CSV has a header row
        .infer_schema()?; // Infer column types from the first few rows

    println!("Inferred Schema: {:?}", reader.schema());

    for record in reader.iter::< (String, i32, NaiveDate, bool, f64) >() {
        let (name, age, birthdate, is_active, score) = record?;  // Propagate errors
        println!("Name: {}, Age: {}, Birthdate: {}, Active: {}, Score: {}", name, age, birthdate, is_active, score);
    }

    Ok(())
}
```

This code snippet reads the `data.csv` file, infers the schema (name as String, age as i32, birthdate as NaiveDate, is_active as bool, and score as f64), and then iterates over the records, accessing each column by its typed name directly.  The `NaiveDate` type from the `chrono` crate requires the `features = ["serde"]` in your `Cargo.toml`.

## Sampling Size & Accuracy

The accuracy of the inferred schema depends on the sampling size used during inference. By default, `csvtype` samples the first 100 rows to determine column types.  You can adjust this using the `sample_size()` method:

```rust
let reader = CsvReader::from_path("data.csv")?
    .has_header(true)
    .sample_size(500)? // Sample 500 rows for schema inference
    .infer_schema()?;
```

Larger sample sizes generally lead to more accurate type inference, especially when dealing with heterogeneous data within a column (e.g., some values are integers, others are floats).  However, increasing the sample size also increases the time taken during schema inference.

## Overriding Inferred Types

Sometimes, `csvtype` might misinterpret a column's type due to unusual data or limitations in its inference logic. You can override the inferred type for specific columns using the `with_column_type()` method:

```rust
use csvtype::ColumnType;

let reader = CsvReader::from_path("data.csv")?
    .has_header(true)
    .with_column_type("age", ColumnType::String)? // Force "age" column to be String
    .infer_schema()?;
```

This forces the `age` column to be treated as a string, regardless of what `csvtype` initially inferred.  You can also use custom types:

```rust
#[derive(Debug)]
struct MyCustomType(String); // Example Custom Type
let reader = CsvReader::from_path("data.csv")?
    .has_header(true)
    .with_column_type("name", ColumnType::Custom { type_name: std::any::TypeId::of::<MyCustomType>() })?
    .infer_schema()?;
```
