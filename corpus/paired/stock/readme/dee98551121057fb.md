# Packlite: Simple Bundling & Minification for Static Sites

Packlite is a Node.js command-line tool designed to efficiently bundle and minify your JavaScript and CSS files for simple static websites. Unlike larger, framework-centric build tools, Packlite focuses on speed and simplicity – ideal when you need minimal overhead and maximum control over your deployment bundles.  It’s perfect for blogs, landing pages, documentation sites, or any project where a full SPA framework is overkill.

## Installation

Packlite is available via npm:

```bash
npm install -g packlite
```

This installs the `packlite` command globally, allowing you to use it from anywhere in your terminal.  Make sure you have Node.js and npm installed on your system.

## Configuration (packlite.config.json)

Packlite uses a configuration file (`packlite.config.json`) to define which files to bundle. Here's an example:

```json
{
  "entry": {
    "app.js": ["src/js/main.js", "src/js/utils.js"],
    "style.css": ["src/css/global.css", "src/css/components/*.css"]
  },
  "output": {
    "path": "dist",
    "filename": "[name].min.[ext]" // e.g., app.min.js, style.min.css
  },
  "sourcemaps": true,
  "watch": false // Set to 'true' for development (see below)
}
```

**Explanation:**

* **`entry`**: Defines the bundles and their corresponding input files. The key (`app.js`, `style.css`) becomes the output filename (without extension). Values are arrays of file paths.  Glob patterns (like `src/css/components/*.css`) are supported!
* **`output`**: Specifies where to put the generated files.
    * `path`: The destination directory for the bundled files (defaults to "dist").
    * `filename`:  A template string that determines the output filename. `[name]` will be replaced with the entry point's key (e.g., "app"), and `[ext]` will be replaced with the original file extension (e.g., "js", "css").
* **`sourcemaps`**:  Enables or disables source map generation for easier debugging. Defaults to `false`.  Set to `true` for development, highly recommended during debugging.
* **`watch`**:  Enables watch mode (see below).

## Usage

To run Packlite:

```bash
packlite
```

This will read your `packlite.config.json`, bundle and minify the specified files, and output them to the configured directory (`dist` by default).

## Development with Watch Mode

For local development, use watch mode to automatically rebuild bundles whenever you change a source file:

```bash
packlite --watch
# or in your packlite.config.json set "watch": true
```

Packlite will now monitor the files listed in your `entry` configuration and regenerate the bundled files whenever changes are detected, significantly speeding up development iteration.

## Speed & Efficiency - Why Packlite?

Compared to using larger, more complex build tools (like Webpack or Parcel) for simple static sites, Packlite offers a significant speed advantage:

* **Lightweight Core:**  Packlite is intentionally small and focused. This reduces startup time and overall resource consumption.
* **Minimal Dependencies:** Fewer dependencies mean faster installation and less potential for conflicts.
* **Optimized Bundling:**  The bundling logic is tailored for straightforward projects, avoiding unnecessary complexity.

**Example Comparison (Rough Estimates):**

| Task | Packlite | Webpack/Parcel | Notes |
|---|---|---|---|
| Initial Setup | 5 seconds | 30-60+ seconds |  Larger tools have more configuration and dependencies. |
| First Build | 1-5 seconds | 10-30+ seconds | Depends on project size; Packlite is generally faster for smaller projects. |
| Incremental Build (Watch Mode) | < 1 second | 2-10+ seconds | Significant difference in development workflow. |

*These are estimates and will vary depending on the specific project and hardware.*  Packlite shines when you want a fast, simple solution without the overhead of larger build systems.
