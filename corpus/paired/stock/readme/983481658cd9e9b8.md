# Confkeep: INI Configuration Parsing with Formatting Preservation

Confkeep is a small Python library designed to parse INI-style configuration files while meticulously preserving formatting – including comments and blank lines. This makes it ideal for scenarios where you need to programmatically modify configuration files without destroying the user's carefully crafted layout.  It's built as an alternative to Python’s standard `configparser`, which often strips away comments and whitespace during parsing, leading to a loss of formatting when writing back out.

## Motivation: Why Not Just Use `configparser`?

Python's built-in `configparser` is perfectly adequate for many basic configuration scenarios. However, it has a significant drawback:  it aggressively normalizes the input file. During parsing, it strips comments and collapses blank lines. When you write the configuration back out using `configparser`, the original formatting *is not* restored. This can be frustrating for users who rely on those comments for clarity or specific indentation for readability.

Confkeep addresses this by prioritizing formatting preservation.  It aims to read the configuration file as faithfully as possible and reproduce it exactly when writing, allowing you to safely make programmatic changes without introducing unwanted modifications to the user's visual presentation.  Think of it as a "round-tripping" friendly INI parser.

## Installation

You can install Confkeep easily using pip:

```bash
pip install confkeep
```

## Usage Example

Let’s illustrate how Confkeep works with a simple example. Assume you have an `example.ini` file with the following content:

```ini
; This is a comment explaining this section
[Section1]
# A line to highlight another comment
key1 = value1
key2 = value2

; Another comment, showing a blank line above
key3 = value3  ; Inline comment example

[Section2]
key4 = value4
```

Here's how you can use Confkeep to read this file, modify a value, and write it back out:

```python
import confkeep

# Read the configuration file
config = confkeep.parse_file("example.ini")

# Modify a value
config["Section1"]["key2"] = "new_value"

# Write the modified configuration back to the file (overwriting the original)
confkeep.write_file(config, "example.ini", indent=4) # Indent for readability during write
```

After running this code, `example.ini` will contain:

```ini
; This is a comment explaining this section
[Section1]
# A line to highlight another comment
key1 = value1
key2 = new_value  ; Notice the inline comment is preserved!

key3 = value3  ; Inline comment example


; Another comment, showing a blank line above
[Section2]
key4 = value4
```

Notice how all comments and blank lines are preserved. The `indent=4` argument in `write_file()` ensures that the output file is nicely formatted with an indent of 4 spaces, making it more readable.  Without this, the formatting would be as close to the original as possible – often a single space.

## Supported Syntax Quirks and Features

Confkeep attempts to handle common INI syntax quirks gracefully:

* **Inline Comments:** Confkeep correctly parses and preserves inline comments (those following an equals sign `=`) within key-value pairs.
* **Multi-line Values:**  While not explicitly designed for multi-line *strings*, Confkeep will treat consecutive lines with the same indentation as part of a single value, effectively preserving them during round-tripping. Use caution when relying heavily on this behavior, as it's less robust than dedicated multi-line string handling in other configuration formats (like YAML).
* **Blank Lines:** Blank lines are treated as significant and preserved both during reading and writing. This allows for visual separation of sections or key-value pairs.
* **Section Inheritance (Limited):** Confkeep does *not* support complex section inheritance features like those found in some other configuration formats. However, it will preserve the order of sections as they appear in the file.

## Limitations

* **No Advanced Features:** Confkeep focuses on faithful reproduction of the INI format. It doesn't offer advanced features such as variable substitution or type conversion.
* **Error Handling:** Error handling is minimal.  Invalid syntax might lead to unexpected behavior.
* **Complex Multi-line Values:** While consecutive indented lines are preserved, complex multi-line string formatting (e.g., using specific delimiters) is not explicitly supported and may be lost during parsing/writing.
