## Taming the Autoplay Beast: Building a Chrome Extension to Silence News Site Videos

We all know the frustration. You land on your favorite news site, ready to catch up on current events, only to be assaulted by autoplaying videos blasting from your speakers. It's jarring, disruptive, and frankly, annoying.  So, I decided to do something about it – build a simple Chrome extension to block these intrusive videos.

This isn’t going to be a full-blown tutorial with complex JavaScript wizardry. The core idea is straightforward: identify video elements on news sites and prevent them from automatically playing. Here's a rundown of how I approached the project, including some unexpected hurdles along the way.

**The Manifest – Your Extension's Blueprint**

Every Chrome extension needs a `manifest.json` file. This tells Chrome about your extension: its name, description, permissions, and what files to load.  For this simple blocker, we need a few key permissions:

```json
{
  "manifest_version": 3,
  "name": "Autoplay Blocker",
  "version": "1.0",
  "description": "Blocks autoplaying videos on news sites.",
  "permissions": [
    "activeTab",
    "scripting"
  ],
  "action": {
    "default_popup": "popup.html" //Optional - for settings or info
  },
  "background": {
    "service_worker": "background.js"
  }
}
```

*   **`manifest_version`**:  Specifies the manifest file version (use 3).
*   **`permissions`**: This is crucial. `activeTab` allows us to access the currently active tab, and `scripting` lets us inject our script into web pages. Without these, your extension won't be able to do anything!
*   **`background`**:  Defines a service worker (like background.js) which will run in the background and handle logic

The core blocking logic resides within `background.js`:

```javascript
chrome.tabs.onUpdated.addListener(async (tabId, changeInfo, tab) => {
  if (changeInfo.status === 'complete' && tab.url?.includes('example-news-site.com')) { //Replace with your target news site URLs
    await chrome.scripting.executeScript({
      target: { tabId: tabId },
      function: blockAutoplay,
    });
  }
});

function blockAutoplay() {
  const videos = document.querySelectorAll('video');
  videos.forEach(video => {
    video.autoplay = false;
    //Optional - mute audio also
    video.muted = true;
  });
}
```

This script waits for the tab to load and then executes a function `blockAutoplay` that finds all `<video>` elements on the page and sets their autoplay property to `false`. The optional line mutes the videos as well.

**The Lazy-Loaded Iframe Bug**

Everything seemed great until I started testing on sites heavily reliant on lazy-loaded iframes (those embedded content containers that only load when they come into view). Suddenly, my extension wasn't working consistently.  It turned out the `document.querySelectorAll('video')` call in `blockAutoplay` was only targeting videos within the *main* document. Videos inside those iframes weren’t being found until the iframe itself had loaded and its content was rendered.

The fix? I needed to recursively search for video elements within all iframes on the page.  This involved a slightly more complex function:

```javascript
function blockAutoplayRecursive(iframe) {
    const videos = iframe.contentDocument?.querySelectorAll('video');
    videos.forEach(video => {
        video.autoplay = false;
        video.muted = true;
    });

    const iframes = iframe.contentDocument?.querySelectorAll('iframe');
    iframes.forEach(blockAutoplayRecursive);
}
```

This function is now called within the `executeScript` call, and recursively searches all frames for videos to block.



Building this simple extension was a great learning experience. It highlighted the importance of understanding web page structure (especially those pesky iframes!), carefully considering permissions in your manifest, and thoroughly testing across different website implementations. Happy blocking!
