## Don’t Ship Your Secrets: How I Built a Git Pre-Commit Hook to Catch API Keys

We’ve all been there (or at least *heard* horror stories about it). A developer accidentally commits an AWS access key, a production API key, or some other sensitive credential directly into the codebase. The consequences can range from minor inconvenience to full-blown security breaches and panicked emergency rollbacks.  It's a nightmare scenario.

Recently, we had a close call. A new team member, understandably eager to contribute, inadvertently pushed a configuration file containing an API key meant for local development *directly* into our main branch. Thankfully, a vigilant teammate spotted it during code review before it made its way to production. It was enough of a wake-up call – we needed a better line of defense.

Existing tools like linters and IDE plugins help, but they aren't foolproof. A quick and easy solution that stops problematic commits *before* they even reach the repository felt crucial. That’s when I started building a Git pre-commit hook.

**What is a Pre-Commit Hook?**

Essentially, a pre-commit hook is a script that runs automatically before you commit code to your Git repository. It's like a gatekeeper – if it fails (returns a non-zero exit code), the commit is aborted, giving you a chance to fix the issue.

**The Script: Hunting for Secrets**

My hook is written in Python and fairly simple.  It searches through staged files for common patterns associated with API keys and AWS credentials using regular expressions. Here's a simplified snippet (the actual script uses more robust regex):

```python
#!/usr/bin/env python3
import subprocess
import re

def check_for_secrets(files):
    patterns = [
        r"API_KEY=['\"]([a-zA-Z0-9_-]+)['\"]", # Generic API Key pattern
        r"AWS_ACCESS_KEY_ID=['\"]([a-zA-Z0-9_-]+)['\"]", # AWS Access Key ID
        r"AWS_SECRET_ACCESS_KEY=['\"]([a-zA-Z0-9_-]+)['\"]" # AWS Secret Key
    ]

    for file in files:
        try:
            with open(file, 'r') as f:
                content = f.read()
                for pattern in patterns:
                    if re.search(pattern, content):
                        print(f"ERROR: Possible secret found in {file}")
                        return 1 # Fail the commit!
        except Exception as e:
            print(f"Error reading file {file}: {e}")
            return 1

    return 0  # Success - commit can proceed

if __name__ == "__main__":
    files_to_check = subprocess.check_output(['git', 'diff', '--cached', '--name-only']).decode('utf-8').splitlines()
    exit(check_for_secrets(files_to_check))
```

**How to Use It (and Share it!)**

1.  Save the script as `.git/hooks/pre-commit` in your repository.
2.  Make it executable: `chmod +x .git/hooks/pre-commit`.

To share this with your team, you'll typically add it to your `.gitignore` file (so it isn’t tracked) and then have each developer copy it into their local `.git/hooks` directory.  For more complex deployments, consider using a tool like `pre-commit`.

**Important Considerations:**

*   This is a basic example! Expand the regex patterns to cover your specific needs.
*   False positives are possible; carefully review any flagged files.
*   Don't rely solely on this hook – proper secrets management (like HashiCorp Vault or AWS Secrets Manager) is still essential.



This pre-commit hook isn’t a silver bullet, but it provides an extra layer of protection against accidental secret exposure, and that's already worth the effort.
