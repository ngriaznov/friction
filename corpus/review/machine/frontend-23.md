Reviewed the migration from plain `<img>` tags to `next/image` across the product gallery and blog post header images. Good change, this should help LCP on both page types given how large some of these hero images are — a few things to check before merging.

Most of the conversions correctly provide explicit `width` and `height` (or use `fill` with a properly positioned relative-parent container), which is the main thing people get wrong with this migration — without those, `next/image` can't reserve layout space and you lose the cumulative-layout-shift benefit that's a big part of the point of using it. I spot-checked `ProductGalleryImage` and `BlogHeaderImage` and both look correct.

One real issue: the blog post header images are sourced from a CMS (based on the URL pattern, looks like a headless CMS's asset CDN) and are being passed directly into `next/image`'s `src` without the CMS's domain being added to `images.remotePatterns` in `next.config.js` — I see `next.config.js` wasn't touched in this diff at all. Unless that domain was already allow-listed before this PR (worth double-checking), this will fail at runtime with `next/image`'s "hostname not configured" error the moment it tries to load an image from that source. Please confirm that's already set up, or add it as part of this PR since it's directly required for this change to function.

Second: `priority` isn't set on any of the blog header images, meaning they'll be lazy-loaded by default like any other `next/image` instance. But the header image is almost always the largest above-the-fold element on a blog post page — it's very likely the LCP element — and lazy-loading your LCP element actively hurts the metric you're presumably trying to improve with this migration. Add `priority` to the blog header image specifically (not the gallery thumbnails further down the page, which should stay lazy). This is a fairly common miss with `next/image` adoptions — people apply it uniformly without realizing `priority` needs to be opted into deliberately for above-the-fold images.

Smaller: the product gallery thumbnails use a fixed `sizes="200px"` regardless of viewport, but the actual rendered thumbnail size varies by breakpoint per the CSS grid (`repeat(auto-fill, minmax(150px, 1fr))`), so on some viewports you're requesting a larger image than what's actually displayed. Not wrong, just wasteful — worth tightening the `sizes` attribute to better match actual rendered dimensions per breakpoint, though I wouldn't block on this since it's an optimization refinement rather than a functional issue.

Once the CMS domain is confirmed configured and `priority` is added to the blog headers, this is good to merge — the core migration work is solid.
