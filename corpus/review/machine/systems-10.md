Bump allocator for per-frame allocations in the game engine — this is a good fit for the use case (allocate a lot of small transient objects during a frame, reset the whole arena at frame boundary instead of freeing individually) and the implementation is close to right. A few notes.

The pointer-bumping itself is correct: you track a `current` offset into a fixed backing buffer, round it up to the requested alignment before handing out the pointer, and check against `capacity` before advancing. The alignment handling using `(current + align - 1) & !(align - 1)` is the standard bit trick and you've applied it correctly assuming `align` is always a power of two, which for `std::mem::align_of::<T>()` it always is, so that's fine.

One gap: `alloc` doesn't check for overflow in that alignment rounding itself — `current + align - 1` can wrap around near the top of the address space in theory, though practically for a per-frame arena sized in megabytes this is not a real risk. I'd still add a `checked_add` there just because it's free and turns a theoretical wraparound into a clean allocation failure instead of undefined behavior on overflow, but I wouldn't block on it.

More relevant: there's no `Drop` glue for the objects allocated out of the arena. Since `reset()` just sets `current` back to zero without running destructors on anything that was bump-allocated, any `T` with a non-trivial `Drop` impl (anything holding a `Vec`, `String`, a file handle, etc.) will leak its owned resources every frame if it's ever allocated through this arena. If the intent is "only `Copy` types go in here," that should be enforced with a `T: Copy` bound on `alloc`, which also sidesteps the whole issue at compile time and documents the constraint where the API is used, rather than as a comment someone has to go find. If non-`Copy` types are meant to be supported, you need to track allocated objects (or at least ones with drop glue) and run their destructors in `reset()`, which is considerably more machinery for a per-frame allocator and I'd only take that on if you actually need it.

Minor style note: `reset` is `pub fn reset(&mut self)` which is good — requiring `&mut self` means the borrow checker already prevents resetting the arena while any allocation from it is still borrowed out, which is exactly the safety property you want and you get it for free from the API shape rather than needing extra bookkeeping. Nice.

If you add the `Copy` bound (or the destructor tracking, if you need non-Copy support) I'd merge this as-is. Solid, minimal, does what a frame arena needs to do.
