Question was about a Django REST Framework `OrderViewSet.list` that was timing out for customers with large order histories, code included a `queryset = Order.objects.all()` class attribute and a nested `OrderItemSerializer` with a `product` field.

The timeout is almost certainly the classic N+1: for every order you serialize, `OrderItemSerializer` walks `order.items.all()` and then, per item, accesses `item.product.name` and `item.product.sku`. With `Order.objects.all()` as the base queryset none of that is prefetched, so a page of 50 orders with 5 items each turns into roughly 1 (orders) + 50 (items) + 250 (products) queries. Add `.select_related()` for the FKs traversed once per row (like `customer`) and `.prefetch_related(Prefetch('items', queryset=OrderItem.objects.select_related('product')))` for the reverse FK so the item-to-product join happens in one extra query instead of N. You can confirm this is the problem by wrapping the view in Django Debug Toolbar or just counting queries with `django.db.connection.queries` in a test.

Separately, `list` isn't paginated as far as I can tell — there's no `pagination_class` set on the viewset and none in `DEFAULT_PAGINATION_CLASS` in settings that you mentioned, so "large order histories" means you're serializing and transmitting every order a customer has ever placed on every request. Even after fixing the query count, that response size is going to be the next bottleneck. `LimitOffsetPagination` or a cursor pagination class would both work; given orders are naturally ordered by creation time, cursor pagination on `created_at` will also avoid the row-skipping cost that offset pagination has once customers get into the thousands of orders.

Minor: `OrderSerializer.Meta.fields = '__all__'` is convenient but it means any new column you add to the model is exposed by default — worth being explicit about the field list for anything that might later carry sensitive data like internal cost fields.

This one needs the prefetch and pagination fixes before it should ship; everything else about the viewset structure is reasonable DRF.
