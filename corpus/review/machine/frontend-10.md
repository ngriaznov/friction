Looking at the bundle analyzer output you linked alongside the Vite config, a few concrete things are driving the 1.8MB main chunk.

The biggest single contributor is `moment` plus `moment-timezone`, imported at the top level of a utility module (`src/utils/dates.ts`) that's transitively pulled in by nearly every feature module, including ones that only need to format a single date. `moment` is famously not tree-shakeable because of how it bundles all locale data by default, and `moment-timezone` adds its own large IANA timezone dataset on top. Swapping to `date-fns` (tree-shakeable, you only pay for the functions you import) or `dayjs` (tiny core with opt-in plugins) would likely cut a meaningful chunk of that 1.8MB on its own — I'd guess several hundred KB given how much of the timezone data is probably unused.

Second, `lodash` is imported as `import _ from 'lodash'` in three files rather than named imports from `lodash-es` or path imports like `lodash/debounce`. The blanket import pulls in the entire library regardless of what's actually used downstream, defeating tree-shaking even though Vite/Rollup can tree-shake ESM in principle — it can't tree-shake through a namespace import that touches the whole module. Switch to `import debounce from 'lodash/debounce'` (or migrate to `lodash-es` with named imports) at each call site.

Third, and this is more of an architecture point than a quick fix: everything is in one entry chunk because there's no route-based code splitting. The router config imports every page component eagerly (`import Dashboard from './pages/Dashboard'` etc. at the top of `routes.tsx`) instead of lazily. Switching those to `React.lazy(() => import('./pages/Dashboard'))` paired with `<Suspense>` boundaries at the route level would let Vite split each page into its own chunk, so a user landing on the login page doesn't pay for the admin dashboard's bundle weight upfront. Given this app has north of a dozen routes, this is probably the single highest-leverage change here, bigger than the library swaps above, and it's also a much bigger diff to review, so I'd suggest doing it as a separate follow-up PR rather than folding it into this one.

Smaller note: `vite.config.ts` doesn't currently set `build.rollupOptions.output.manualChunks`, so even vendor code that could be shared and cached independently of app code (React, React DOM, your UI library) is bundled inline with app code, meaning every deploy invalidates the vendor chunk's cache along with the app chunk. Worth adding a manual chunk split for vendor deps once the route splitting above is in, so users' browsers can cache the rarely-changing vendor bundle across deploys.

None of this blocks merging what's actually in this diff if the diff itself is just the analyzer script and CI budget check you added — that part looks fine and the budget threshold you picked (250KB gzipped per route chunk) is reasonable. But I'd flag this as needing a dedicated bundle-size cleanup pass soon, since the number is only going to grow from here without route splitting in place.
