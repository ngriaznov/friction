There's a leakage bug in the cross-validation setup that will inflate your reported precision-recall numbers, so I want to flag that before anything else.

You're fitting `TfidfVectorizer` on the full `X` (all documents) once, up front, and then passing the resulting sparse matrix into `StratifiedKFold` for cross-validation. Because the vectorizer's vocabulary and IDF weights are learned from every document — including the ones that will later sit in each fold's held-out set — information about the full corpus (which terms are rare, which are common) leaks into the "training" side of every fold. It's a subtler leak than a label leak, so the effect on your metrics is usually smaller, but it's still real and it means your cross-validated AUC and average precision are optimistic relative to how the model will perform on genuinely new text. The fix is to move vectorization inside the fold loop (or use a `Pipeline` combining `TfidfVectorizer` and the classifier, then pass that pipeline object directly to `cross_val_score`/`cross_validate` so scikit-learn refits the vectorizer on each fold's training split automatically).

On the imbalance handling itself: using `average_precision_score` alongside ROC-AUC rather than relying on ROC-AUC alone is the right instinct given you mentioned the positive class is under 5% — ROC-AUC can look deceptively good on skewed data because the false positive rate denominator is dominated by the (huge) negative class. I'd go a step further and also report precision/recall at a couple of fixed, business-meaningful thresholds rather than only the threshold-free summary metrics, since whoever consumes this model eventually has to pick an operating point, and average precision alone doesn't tell them what recall they get at 90% precision, for instance.

One more thing: `StratifiedKFold(n_splits=5, shuffle=True, random_state=42)` — good that you set a seed, but I don't see that same seed reused consistently in the classifier's own `random_state`, so full run-to-run reproducibility isn't guaranteed yet. Small fix, worth doing while you're in here.

Fix the vectorizer leakage first — that's the one I'd block on — everything else here is solid instinct, just needs the threshold reporting and full seeding to round it out.
