Good direction moving the nightly feature backfill DAG to dynamic task mapping — `expand(customer_segment=get_active_segments())` is a much better fit than the old approach of hand-listing segment names as separate hardcoded tasks, and it means new segments automatically get backfill coverage without a code change. The `@task` decorators throughout also read a lot cleaner than the previous `PythonOperator` boilerplate.

A few things I think need attention before this goes live, though. `get_active_segments()` is called at DAG parse time to determine how many mapped task instances to create — actually, looking closer, since this is dynamic task mapping the expansion happens at runtime based on the upstream task's output, which is correct, but I want to confirm: is `get_active_segments` itself a task, or is it being called directly in the DAG file? If it's the latter, that function is hitting the warehouse on every DAG file parse (which Airflow does frequently, not just at trigger time), and that's an unnecessary and potentially slow query running on a schedule you don't control. It should be its own upstream `@task` whose return value feeds `.expand()`.

Second, there's no `max_active_tis_per_dagrun` or similar concurrency cap on the mapped task group. If the segment count grows to, say, several hundred, this DAG could suddenly spin up hundreds of concurrent tasks against the same warehouse connection pool, and depending on your executor and warehouse concurrency limits that's a good way to get connection errors or throttling across every other job sharing that pool. Worth setting an explicit cap even if it's generous.

Third, no retry configuration on the mapped tasks — same concern as before, transient failures on one segment shouldn't require a full DAG re-run, and with dynamic mapping you can retry just the failed map indices, which is actually one of the nicer properties of this pattern once retries are configured.

Solid refactor overall, needs the parse-time query concern resolved and concurrency/retry settings added before I'd call this ready for production.
