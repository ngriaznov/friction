This is a reasonable, fairly standard builder — I don't have major objections to the shape of it — but a couple of things are worth tightening before I'd call it done.

You've hand-rolled the builder for `ShipmentRequest` instead of using Lombok's `@Builder`, which is fine if there's a reason (custom validation in `build()`, for instance, which you do have — checking that `destination` is set when `expressDelivery` is true), but if that's the only reason, it's worth knowing Lombok's `@Builder` combined with a `@Builder.Default` and a manual `build()` override via `toBuilder` won't easily support cross-field validation like that anyway, so hand-rolling is probably the right call here — just wanted to confirm it's a deliberate choice and not just unfamiliarity with the annotation, since the boilerplate (five near-identical `withX` methods) is exactly what Lombok exists to eliminate for the fields that don't need custom logic.

The real issue is that `ShipmentRequestBuilder` is not thread-safe and is being handed off across threads in `BatchShipmentService.buildAll()` — you create one builder, then pass it into a `parallelStream()` where each thread calls `.withDestination(...)` and other fields before calling `.build()`. Every thread is mutating the same builder instance's fields concurrently, so you'll get either a `ConcurrentModificationException` if any field is a collection, or more insidiously, silently mixed-up values (thread A's destination paired with thread B's package weight) with no exception at all. Builders are meant to be single-owner, single-thread objects — build one per item inside the parallel stream instead of sharing one, or if the shared setup is genuinely common across all items, split it into an immutable "template" object that each thread's builder copies from.

Smaller: `build()` throws a raw `IllegalStateException` for the destination/express-delivery invariant — a dedicated `InvalidShipmentRequestException` would give callers something to catch specifically rather than having to distinguish "you forgot a field" from any other `IllegalStateException` that might come out of this code path.

Otherwise the fluent API reads well and the validation-at-build-time approach is the right instinct — just needs each parallel branch to own its own builder.
