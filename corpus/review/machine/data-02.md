Overall this churn feature pipeline does what it says on the tin, and the feature choices themselves (recency of last login, rolling 30/60/90-day transaction counts, tenure in days) are sensible and well-motivated by the comments you left explaining why each one was included — that context is genuinely helpful for whoever touches this next.

The main thing I'd flag before merging is the `SettingWithCopyWarning` you're presumably seeing (even if suppressed) from lines like `df_active = df[df['status'] == 'active']` followed later by `df_active['days_since_login'] = ...`. That's a view-vs-copy ambiguity, and right now it works by luck rather than by guarantee — pandas could silently write to the parent frame or raise depending on internal memory layout. Add an explicit `.copy()` at the point of the filter, or better, do the filtering and feature assignment in one chained `.assign()` call so there's no intermediate frame to be ambiguous about.

Second, you're computing several of these rolling windows with `groupby('customer_id').apply(lambda g: ...)`, which is going to be slow at any real scale because `apply` on a groupby falls back to Python-level iteration per group. Most of what's inside that lambda (rolling sum, rolling mean) has a vectorized `groupby().rolling()` equivalent that stays in Cython and will be an order of magnitude faster once your customer count grows past the toy dataset you're testing against.

Smaller things: `tenure_days = (pd.Timestamp.now() - df['signup_date']).dt.days` bakes in "now" at pipeline-run time, which is fine for training but means this feature will silently drift in meaning between training and any batch scoring run days later — worth a comment noting that's intentional, or better, parameterize the reference date so it's reproducible. Also `df.fillna(0)` at the end is applied blanket-wide; for a ratio feature like `transactions_last_30d / transactions_last_90d`, zero-filling a missing ratio because the denominator was zero is going to quietly misrepresent brand-new customers as maximally inactive rather than "unknown." I'd special-case that column.

Nothing here is a blocker, but the `.copy()` fix and the groupby-apply-to-vectorized swap are both worth doing before this becomes the reference implementation other pipelines copy from.
