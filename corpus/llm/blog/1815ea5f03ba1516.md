# A pre-commit hook that catches secrets before I do

Two months ago I pushed a branch with a `.env.local` file that had a real AWS secret access key sitting in it, in plain text, in a public-facing repo. I caught it about four minutes after pushing, when a bot account starred the repo — which is the universal sign that a key-scanning crawler found it first. I rotated the credentials within the hour and nothing was actually used, but the whole thing cost me an afternoon of paranoid log-checking and a fairly unpleasant conversation with our security lead. I didn't want to have that conversation twice.

So I wrote a Git pre-commit hook that scans staged changes for anything that looks like a secret before the commit is allowed to happen.

The hook is a short shell script at `.git/hooks/pre-commit` that runs `git diff --cached --name-only` to get the list of staged files, then greps each one against a handful of patterns: the `AKIA[0-9A-Z]{16}` shape of AWS access key IDs, the longer base64-ish shape of AWS secret keys, generic `-----BEGIN PRIVATE KEY-----` blocks, and a catch-all pattern for assignments like `api_key = "..."` or `password: "..."` where the value is a long random-looking string rather than an obvious placeholder.

```bash
#!/bin/sh
staged=$(git diff --cached --name-only --diff-filter=ACM)
found=0

for pattern in 'AKIA[0-9A-Z]{16}' '-----BEGIN (RSA|EC|DSA|PRIVATE) KEY-----' '(api|secret)[_-]?key["\s:=]+[A-Za-z0-9/+]{20,}'; do
  matches=$(echo "$staged" | xargs grep -lE "$pattern" 2>/dev/null)
  if [ -n "$matches" ]; then
    echo "Possible secret matching pattern '$pattern' in:"
    echo "$matches"
    found=1
  fi
done

if [ "$found" -eq 1 ]; then
  echo "Commit blocked. Remove the secret or add an inline # pragma: allowlist to override."
  exit 1
fi
```

It's deliberately crude compared to something like `gitleaks` or `truffleHog`, both of which I looked at and ultimately didn't install, mostly because I wanted something with zero dependencies that every clone of the repo gets automatically via a `core.hooksPath` setting in our shared Git config, rather than a tool people have to remember to install separately.

It's caught three real near-misses since I started using it, all coworkers, none of them me a second time. One was a Stripe test key that somebody left in a spec file, which is low-risk but still not something you want sitting in history forever. The `# pragma: allowlist` escape hatch has been used exactly twice, both times for genuinely fake example keys in documentation, and both times the reviewer double-checked before approving.

It's not a substitute for secret scanning in CI, and we do still run a proper scanner there as a backstop for anyone who commits with `--no-verify`. But catching the mistake locally, before it ever touches a shared branch, has been worth the twenty minutes it took to write.
