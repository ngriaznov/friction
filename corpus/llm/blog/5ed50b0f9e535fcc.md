# A Weekend Chrome Extension to Stop Videos From Autoplaying

I got tired of opening a news article on my phone-sized laptop screen and immediately having a video start blaring in a sidebar I never asked to see. So I spent a Saturday building a small Chrome extension to kill it. It's about 150 lines of JavaScript total, and it taught me more about the `manifest.json` permission model than I expected for something this dumb-simple.

## What it actually does

The extension injects a content script into every page that walks the DOM for `<video>` elements, sets `autoplay = false`, and calls `.pause()` on anything already playing. That part took maybe twenty minutes. The permissions took longer to get right.

My first manifest asked for `"permissions": ["<all_urls>"]` plus `"tabs"`, which is the kind of thing that gets an extension flagged during store review and, more importantly, is just more access than the job needs. I didn't need to read tab URLs or history — I only needed to run a script on pages as they loaded. I ended up with:

```json
{
  "manifest_version": 3,
  "content_scripts": [{
    "matches": ["<all_urls>"],
    "js": ["block-autoplay.js"],
    "run_at": "document_start"
  }]
}
```

`run_at: document_start` matters — running at `document_idle` (the default) meant the video had already started playing by the time my script fired, so I'd see a half-second of sound before the pause kicked in. Starting earlier and re-checking on `DOMContentLoaded` closed that gap.

## The bug that only showed up on lazy-loaded iframes

Everything worked fine on plain news sites until I tested it on a site that embeds its video player inside a lazily-loaded iframe — the iframe's `src` attribute only gets set once the reader scrolls near it. My content script had already run and found nothing, because at page-load time there was no `<video>` element anywhere in the DOM yet.

The fix was a `MutationObserver` watching for added nodes, rather than a one-shot scan:

```javascript
const observer = new MutationObserver(() => {
  document.querySelectorAll('video').forEach(v => {
    v.autoplay = false;
    if (!v.paused) v.pause();
  });
});
observer.observe(document.body, { childList: true, subtree: true });
```

That catches videos that appear after the initial load, including ones injected inside iframes that share the page's origin. Cross-origin iframes are still out of reach — content scripts can't reach into a frame from a different domain without additional permissions I'd rather not request — but in practice most of the news sites I actually read embed same-origin players, so this got me the 95% case.

It's a small thing, but it's been running quietly in my browser for three months now, and I genuinely forget it's there until I visit a site without it installed and jump at the sudden noise.
