# I Moved This Blog Off WordPress and Mostly Don't Regret It

I ran this blog on WordPress for nine years. Nothing dramatic pushed me off it. The hosting bill crept up, the admin dashboard got slower, and I kept getting emails about plugin security updates for plugins I'd forgotten I installed. Somewhere in there I realized I was maintaining a content management system to publish about eleven posts a year.

So over a long weekend in March I moved everything to a static site generator.

## The export

WordPress's built-in exporter spits out a single XML file it calls WXR. Mine was 4 MB and contained 180-odd posts, every draft I'd abandoned since 2016, and all the comments.

I used a converter to turn that into Markdown files with YAML frontmatter. It got maybe 85% of the way there on its own. The remaining 15% was tedious in exactly the way you'd guess:

- Shortcodes. Nine years of `[caption]`, `[gallery]`, and one plugin's custom `[pullquote]` tag that no converter has ever heard of. These came through as literal bracket text.
- Image paths. Everything pointed at `/wp-content/uploads/2019/04/`, so I kept that directory structure verbatim rather than reorganizing. Not elegant, but it meant zero broken links and zero rewriting.
- Smart quotes and em dashes that had been double-encoded at some point, showing up as `â€™` in about thirty posts.

I wrote a throwaway Python script for the encoding mess and fixed the shortcodes by hand. Three hours, a podcast, done.

## Rebuilding the theme

This is where I lost the actual weekend. My old theme was a child theme of a child theme, and I'd been patching its CSS since roughly 2018. I told myself I'd port it faithfully. Two hours in I admitted the honest thing was to start from an empty stylesheet.

The rebuild is about 200 lines of CSS now. No JavaScript at all. It loads faster than the old one by a wide margin, though I want to be careful here — of course it does, I deleted a jQuery bundle and four web fonts. That's not a point in favor of static generators, that's a point in favor of deleting things.

## What backfired

Two things.

**Comments.** I exported them, rendered them as static HTML at the bottom of each post, and switched off new ones. I framed this to myself as a feature. It was not a feature. A handful of posts got genuinely useful corrections in the comments over the years, and now there's no channel for that except email, which almost nobody uses. I'm still deciding what to do here.

**Scheduled posts.** WordPress published on a timer. My build runs on push. I wrote a post in April, set a date in the frontmatter, pushed it, and assumed it would appear on schedule. It appeared immediately, because I hadn't configured the generator to exclude future-dated content. Four days early, with a section I hadn't finished. I now have a `draft: true` habit and a build flag, but I found out the way you'd expect.

Would I do it again? Yes. But not for speed, and not for the tooling. I did it because there's less to look after now, and that turned out to be the part I actually wanted.
