# One page for all my side projects

I have four side projects, and until last month I checked on them by opening seven browser tabs. GitHub for stars on two repos, the npm registry for download counts, Buttondown for newsletter subscribers, and the analytics dashboard for the one project that has a marketing page. It took two minutes, which is not long, except that I did it most mornings and it always ended with me reading GitHub issues for twenty minutes instead of working.

So I built a dashboard. It is one HTML page. It has no build step.

## What it shows

Six numbers, each with the change since the same time last week. Stars on two repos, weekly npm downloads for the published package, newsletter subscriber count, unique visitors, and open issues across everything. That last one is the only number I actively want to go down, so it renders in a different color when it climbs, which is a small piece of theater that works on me.

Below the numbers there is a sparkline per metric covering the last ninety days. That is the part I actually use. A single number tells you nothing — 412 stars means one thing if it was 380 last week and something else entirely if it was 411.

## How it works

A Python script runs every six hours on a cheap VPS I already had. It hits four APIs, writes one row per metric into a SQLite file, and regenerates a static JSON blob. The page fetches the blob and draws everything with about sixty lines of vanilla JS. No React, no charting library — the sparklines are inline SVG polylines, which took me an hour to get right and have needed zero maintenance since.

The GitHub and npm endpoints are public and need no auth. Buttondown wanted an API key. Plausible wanted one too. Both live in environment variables on the box.

## The part that took longest

Historical data. On day one I had six numbers and no history, and sparklines with a single point look ridiculous. GitHub will not tell you what your star count was in April. npm gives you download counts per day going back eighteen months, so that one backfilled cleanly. For the rest I just accepted a flat line for the first few weeks and let it fill in. I briefly considered scraping the Wayback Machine for old repo pages. I am glad I did not.

The other snag: npm's download counts include CI runs and mirrors, so my "downloads" number is inflated by some unknown amount. I stopped trying to correct for it. The trend is honest even if the absolute value is not.

## Was it worth it

Two weekends, roughly. The dashboard is now the only tab I open, and because it is a static page with no links to anywhere interesting, I look at it and close it. That was not the goal when I started, but it may be the best thing about it.

If I extend it, it will be to add a note field per day — something to record what I shipped, so a spike in a sparkline has an explanation attached instead of me squinting at commit history six weeks later trying to remember what happened on a Tuesday.
