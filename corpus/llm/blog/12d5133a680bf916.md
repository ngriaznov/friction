# The pre-commit hook I should have written a year earlier

Last March one of our data folks committed a notebook to a public analysis repo. Buried in a cell output — not even the source, the *output* — was an AWS access key that had been printed while she was debugging a boto3 session. GitHub's secret scanning found it in under a minute, AWS quarantined the key, and we spent the rest of the afternoon rotating credentials and reading CloudTrail to convince ourselves nothing had been done with it. Nothing had. We got lucky.

What bothered me afterward wasn't the mistake. It was that the only thing standing between us and a bad afternoon was a scanner that runs *after* the commit is already public. So I wrote a hook.

It lives in `.git/hooks/pre-commit`, and the whole thing is about forty lines:

```bash
#!/usr/bin/env bash
set -euo pipefail

PATTERNS=(
  'AKIA[0-9A-Z]{16}'                          # AWS access key id
  'aws_secret_access_key[[:space:]]*=[[:space:]]*[A-Za-z0-9/+=]{40}'
  '(api[_-]?key|secret|token)[[:space:]]*[:=][[:space:]]*["'\''][A-Za-z0-9_\-]{20,}'
  '-----BEGIN [A-Z ]*PRIVATE KEY-----'
)

staged=$(git diff --cached --name-only --diff-filter=ACM)
[ -z "$staged" ] && exit 0

hits=0
for pat in "${PATTERNS[@]}"; do
  while IFS= read -r line; do
    [[ "$line" == *"allowlist secret"* ]] && continue
    echo "possible secret: $line"
    hits=1
  done < <(git diff --cached -U0 -- $staged | grep -nE "^\+.*${pat}" || true)
done

if [ "$hits" -eq 1 ]; then
  echo
  echo "Commit blocked. Add '# allowlist secret' on the line if it's a false positive."
  exit 1
fi
```

Two details matter more than the patterns themselves.

First, it scans `git diff --cached`, not the working tree. Only staged additions get checked, so it stays fast on a large repo and it doesn't yell at you about secrets that were already there before you showed up.

Second, the escape hatch. The first version had no allowlist and I disabled it within a week, because our test fixtures are full of things that look exactly like tokens. A hook you turn off protects nothing. The trailing `allowlist secret` comment costs almost nothing to type and makes the exception visible in review, which is the actual goal.

The obvious limitation: hooks are local. They aren't versioned, they don't apply to anyone who hasn't installed them, and `--no-verify` skips them entirely. This is a seatbelt, not a wall. We added a server-side check in CI two months later, which is the thing that actually enforces the rule.

But the hook is what catches it at 6pm when you're tired and typing fast, before it's anywhere at all. That's worth forty lines.
