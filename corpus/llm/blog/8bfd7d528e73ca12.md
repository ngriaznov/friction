# Two Years Into TypeScript: What Actually Caught Bugs

I resisted TypeScript for a long time. I'd shipped plain JavaScript for a decade, I knew the footguns, and I didn't love the idea of writing type annotations for a language that was never designed to carry them. Two years ago I lost that argument at work, and our mid-sized web app — a few hundred components, a handful of services underneath — got migrated over about four months. Here's what I actually think now that the honeymoon period is long over.

The type errors that caught real bugs were almost all at boundaries. API responses, in particular, were a revelation. We had a `User` object that, it turned out, could come back from three different endpoints with three subtly different shapes — one omitted `avatarUrl`, another returned `id` as a string instead of a number. None of this was documented anywhere except in the runtime behavior of code that had been "working" for years, meaning it was working until it wasn't, and nobody had a repro until a customer hit it in production. Modeling those responses as actual types, rather than trusting a mental image of the shape, surfaced four or five latent bugs in the first month alone. Same story with anything crossing a serialization boundary — data coming out of `localStorage`, query params parsed from a URL, form data before validation. Wherever data enters the system from somewhere TypeScript can't see, typing the boundary and then trusting the inside paid off constantly.

Refactoring safety was the other genuine win, and it's the one I undersold going in. Renaming a field on a shared object used to mean grepping and hoping. Now the compiler just tells you every call site that broke. I've done renames I would never have attempted in plain JavaScript because the blast radius was too scary to reason about by hand.

The busywork, honestly, mostly lives in generics and in fighting the type of third-party libraries whose authors clearly wrote the types after the fact, as an obligation rather than a design. I've lost real hours to a `useMemo` return type that TypeScript inferred as some six-line union nobody would choose to write by hand, when the actual runtime behavior was completely unambiguous. Utility types like `Partial<Omit<Pick<T, K>, J>>` show up in code review more than any human being should have to parse. And there's a category of error that's technically correct — a value could theoretically be `undefined` — but the surrounding code already guarantees it can't be, and proving that to the compiler costs more attention than the bug class is worth.

Net, I'd never go back. The boundary bugs alone justified it. I just wish the type system got out of the way faster when the logic underneath isn't actually in question.
