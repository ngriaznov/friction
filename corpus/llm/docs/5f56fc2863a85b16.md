# Configuration file reference

Thistle reads its configuration from `thistle.toml` in the root of your project. The file is required; running `thistle build` without one exits with an error rather than guessing defaults.

Values are read once at the start of a build. Editing `thistle.toml` while `thistle serve` is running triggers a full rebuild, not an incremental one.

## Top-level keys

### `title`

Type: string. Required.

The site title. It is available to templates as `site.title` and is used for the `<title>` suffix on every page unless a page overrides it. There is no length limit, but themes generally assume something short enough to sit in a header bar.

### `base_url`

Type: string. Required.

The absolute URL where the site will be served, including the scheme. Thistle uses this to expand relative links into absolute ones in feeds and sitemaps, so getting it wrong produces a site that looks fine locally and has broken feed links in production.

A trailing slash is optional and is normalized away internally. Both `https://example.com` and `https://example.com/` behave identically. If your site lives in a subdirectory, include it: `https://example.com/notes`.

### `theme`

Type: string. Optional. Default: `"plain"`.

The name of a directory under `themes/`. Thistle looks for `themes/<name>/templates/` and `themes/<name>/static/`. The bundled `plain` theme is used when the key is absent.

If you have a `templates/` directory in your project root, its files take precedence over the theme's files of the same name. This is the supported way to override a single template without forking a theme.

### `output_dir`

Type: string. Optional. Default: `"public"`.

Where the built site is written, relative to the project root. Thistle deletes the contents of this directory before each build, so do not point it at a directory that contains anything you want to keep. Absolute paths are accepted but discouraged, since they break for anyone else who clones the repository.

## Per-page front matter overrides

Individual pages can override a subset of the site configuration in their front matter, which is a TOML block delimited by `+++` at the top of the file.

```markdown
+++
title = "Notes on the harvest"
template = "wide.html"
draft = true
+++

The first rain came late this year.
```

Three keys are recognized:

- `title` — replaces `site.title` for this page's `<title>` element only. Other pages are unaffected.
- `template` — the template file to render this page with, resolved against the theme's `templates/` directory. Overrides whatever the theme would have selected.
- `draft` — a boolean. Draft pages are skipped by `thistle build` and rendered by `thistle serve`, so you can preview work in progress without publishing it.

Keys that are not in this list are still parsed and exposed to templates as `page.<key>`, but Thistle assigns no meaning to them. `base_url`, `theme`, and `output_dir` cannot be overridden per page; setting them in front matter is silently ignored.

## Examples

A minimal configuration:

```toml
title = "Field Notes"
base_url = "https://fieldnotes.example.org"
```

This builds into `public/` using the bundled `plain` theme.

A fuller one, for a site served from a subdirectory with a custom theme and a build directory that matches a deploy tool's expectations:

```toml
title = "The Orchard Register"
base_url = "https://example.org/register/"
theme = "quince"
output_dir = "dist"
```

With this file in place, `thistle build` writes to `dist/`, pulls templates from `themes/quince/templates/`, and expands feed links against `https://example.org/register/`. Any file in a root-level `templates/` directory overrides the equivalent file in the Quince theme.
