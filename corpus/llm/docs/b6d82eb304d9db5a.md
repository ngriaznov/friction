# Programming channel memories with ChirpLine

This guide covers programming a handheld transceiver's memory channels from a desktop computer using ChirpLine. You will connect the programming cable, read the radio's current memory image, edit channels, and upload the result.

Programming from the desktop is faster than the front panel for anything beyond a couple of channels, and it gives you a file you can back up, edit in a spreadsheet, and share with the rest of your club.

## Before you start

You need:

- A programming cable for your specific radio. Cables are not universal — a cable cut for a Kenwood two-pin jack will not work on a Yaesu, even if the plug physically fits.
- The USB-serial driver for your cable's chipset. Genuine FTDI and Silicon Labs CP210x cables work with the drivers shipped by macOS and most Linux distributions. Prolific PL2303 clones frequently do not, and are the single most common cause of "radio not responding."
- Your radio's model number, including any regional suffix.

On Linux, add yourself to the `dialout` group and log out and back in, otherwise ChirpLine cannot open the serial port.

## Connecting the cable

1. Turn the radio **off**.
2. Seat the cable plug fully in the speaker/mic jack. Partial insertion is the second most common cause of read failures — you should feel a distinct click, and on two-pin radios both barrels should be flush against the case.
3. Turn the radio on. Set the volume to about mid-range. Some models use the audio path for data and will fail at zero volume.
4. Plug the USB end into the computer.

Confirm the port is visible. On macOS and Linux:

```
chirpline ports
```

You should see an entry such as `/dev/cu.usbserial-A50285BI` or `/dev/ttyUSB0`. On Windows the port appears as `COM3` or similar.

## Reading the radio first

Always download from the radio before you upload to it. The image contains model-specific settings that ChirpLine will otherwise write back as defaults.

```
chirpline read --port /dev/ttyUSB0 --model uv82 --out club-baseline.clx
```

Keep `club-baseline.clx` somewhere safe. If an upload goes wrong, restoring this file returns the radio to its previous state.

## Editing memories

Open the image in the editor:

```
chirpline edit club-baseline.clx
```

Each row is one memory channel. The columns you will use most often are Frequency, Name, Tone Mode, Tone, Duplex, and Offset. For a typical repeater, set Duplex to `-`, Offset to `0.600` on 2 m or `5.000` on 70 cm, Tone Mode to `Tone`, and Tone to the repeater's CTCSS frequency.

To bulk-load channels, export to CSV, edit in a spreadsheet, and import the result:

```
chirpline export club-baseline.clx channels.csv
chirpline import channels.csv --into club-baseline.clx --out club-2026.clx
```

The importer rejects rows whose frequency falls outside the radio's transmit range rather than silently clamping them.

## Uploading

```
chirpline write --port /dev/ttyUSB0 --model uv82 club-2026.clx
```

Do not unplug the cable or power the radio off while the transfer bar is moving. A half-written memory image usually recovers with a second successful upload, but on some models it requires a factory reset from the front panel.

When the upload finishes, power-cycle the radio and spot-check two or three channels against the CSV before you rely on them in the field.
