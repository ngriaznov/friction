# Configuration Reference

Thistle is configured through a single file, `thistle.toml`, located at the root of your site. This page documents the supported top-level keys, how per-page front matter can override them, and provides two complete example configurations.

## Top-level keys

### `title`

The site's display title. Used in the default theme's header and as a fallback for the `<title>` tag on pages that don't set their own.

```toml
title = "Notes from the Shed"
```

### `base_url`

The absolute URL the site will be served from, including scheme and no trailing slash. Thistle uses this to generate absolute links in the RSS feed and sitemap, and to resolve relative asset paths during build.

```toml
base_url = "https://example.com"
```

If you're building for local preview only, `base_url` can be omitted; Thistle falls back to `http://127.0.0.1:8080`.

### `theme`

The name of a theme directory under `themes/`, or one of the two themes bundled with Thistle: `default` and `paper`. Themes control layout templates, not content, so switching themes never requires touching your Markdown files.

```toml
theme = "paper"
```

### `output_dir`

Where the built site is written, relative to the project root. Defaults to `public/`.

```toml
output_dir = "dist"
```

Thistle clears this directory before every build, so avoid pointing it at anything you don't want wiped.

## Other recognized keys

A handful of optional keys round out the top level:

- `language` — a BCP-47 language tag (e.g. `"en-us"`), used in the HTML `lang` attribute and the RSS feed.
- `draft_mode` — when `true`, pages marked `draft = true` in their front matter are included in local builds and excluded from `thistle build --release`.
- `pagination_size` — number of posts per index page; defaults to `10`.
- `[extra]` — a free-form table for custom values your theme templates can reference as `extra.whatever`.

Unrecognized keys are ignored with a warning rather than causing a build failure, which is useful when migrating a config between Thistle versions.

## Per-page front matter overrides

Each Markdown file can carry a front matter block at the top, delimited by `+++`, that overrides site-wide settings for that page alone:

```markdown
+++
title = "Why I Switched to a Mechanical Keyboard"
theme = "default"
draft = false
+++

Content starts here.
```

Any top-level key valid in `thistle.toml` can be set in front matter, with two exceptions: `base_url` and `output_dir` are build-wide and cannot be overridden per page. Front matter values always take precedence over the site config for that page's rendering.

Front matter also accepts page-only keys not valid at the site level, most commonly `date`, `slug`, and `layout` (which selects a specific template file within the active theme, rather than the theme's default).

## Example: a personal blog

```toml
title = "Notes from the Shed"
base_url = "https://shed.example.com"
theme = "paper"
output_dir = "public"
language = "en-us"
pagination_size = 8

[extra]
author = "R. Voss"
show_reading_time = true
```

## Example: a documentation site with drafts enabled

```toml
title = "Palisade Docs"
base_url = "https://docs.palisade.dev"
theme = "default"
output_dir = "dist"
draft_mode = true
pagination_size = 20

[extra]
repo_url = "https://github.com/palisade-project/palisade"
edit_this_page = true
```

In the second example, any Markdown file with `draft = true` in its front matter will appear when running `thistle serve` locally but will be silently skipped by `thistle build --release`, which is the command typically wired into a deploy pipeline. This lets you keep in-progress pages in the same repository as published content without accidentally shipping them.
