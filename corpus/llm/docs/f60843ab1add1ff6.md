# Template syntax

Postmark Lite templates are plain text files with `{{ }}` markers for anything dynamic. A template renders against a context — a dictionary you pass to `render()` — and everything outside the markers is copied through untouched. Templates ending in `.html` are escaped by default; `.txt` templates are not.

This page documents the four constructs: interpolation, conditionals, loops, and includes.

## Variable interpolation

`{{ name }}` looks up `name` in the context and writes its string form into the output.

```
Hi {{ first_name }}, your order {{ order.id }} shipped.
```

Dotted paths walk attributes and dictionary keys, in that order. `{{ order.id }}` tries `order.id` first, then `order["id"]`. List elements use the same dot syntax with an integer: `{{ items.0.sku }}`.

A path that resolves to nothing renders as the empty string. This is deliberate — a missing middle name should not blow up a receipt. If you would rather catch typos early, construct the renderer with `strict=True` and unresolvable paths raise `UndefinedVariable` instead.

Filters transform a value before it is written. Chain them with `|`:

```
Total: {{ cart.total | money }}
Sent {{ sent_at | date:"%B %-d" }}
{{ blurb | truncate:80 | upper }}
```

Filters taking an argument use `filter:arg`. Arguments are string or integer literals only; you cannot pass another variable. The built-in set is small on purpose: `money`, `date`, `truncate`, `upper`, `lower`, `title`, `default`, `escape`, `raw`. Register your own with `env.filter("name")`.

Escaping in HTML templates happens after filters run. To emit markup you have already sanitized yourself, end the chain with `| raw`.

## Conditional blocks

```
{% if subscription.trial %}
  Your trial ends on {{ subscription.trial_ends | date:"%x" }}.
{% elif subscription.past_due %}
  We could not charge your card.
{% else %}
  Thanks for being a member since {{ subscription.started | date:"%Y" }}.
{% endif %}
```

`{% if %}` takes a path, optionally compared to a literal with `==`, `!=`, `<`, `>`, `<=`, `>=`. It has no general expression language — no arithmetic, no function calls, no parentheses. Combine conditions with `and`, `or`, and `not`; `and` binds tighter than `or`, and there is no way to override that grouping, so nest a second `{% if %}` when you need different precedence.

Truthiness follows Python: empty strings, empty lists, zero, `None`, and `False` are falsey. A path that does not resolve is falsey rather than an error, even under `strict=True`.

`{% elif %}` may repeat; `{% else %}` is optional. Every `{% if %}` needs a matching `{% endif %}` or the parser raises `TemplateSyntaxError` with the line number of the unclosed tag.

## Loops over lists

```
{% for item in cart.items %}
  {{ loop.index }}. {{ item.name }} — {{ item.price | money }}
{% empty %}
  Your cart is empty.
{% endfor %}
```

The loop variable is scoped to the block and shadows any context key of the same name. Iterating a dictionary yields keys; use `{% for k in totals %}{{ k }}: {{ totals[k] }}{% endfor %}` — bracket lookup with a loop variable is the one place brackets are permitted.

Inside the body, `loop` exposes:

| Field | Meaning |
| --- | --- |
| `loop.index` | 1-based position |
| `loop.index0` | 0-based position |
| `loop.first` | true on the first pass |
| `loop.last` | true on the last pass |
| `loop.length` | total item count |

Nested loops each get their own `loop`; the outer one is not reachable from inside the inner body. If you need it, assign it first with `{% set outer = loop.index %}`.

The optional `{% empty %}` clause renders when the sequence has no items. Without it, an empty sequence produces nothing.

Iterating something that is not iterable — a number, `None`, a missing path — renders the `{% empty %}` branch rather than raising. Set `strict=True` to make it an error.

## Partial includes

Split shared fragments into their own files and pull them in with `{% include %}`:

```
{% include "partials/header.html" %}
{% include "partials/address.html" with address=order.shipping %}
```

Paths are resolved relative to the loader root, not to the including template, so `"partials/header.html"` means the same thing everywhere. Only forward slashes; `..` segments are rejected.

By default the partial sees the full parent context. The `with` clause adds or overrides names for the duration of the include; add `only` to hide the parent context entirely and pass a clean slate:

```
{% include "partials/row.html" with item=item only %}
```

Includes may nest. A cycle raises `TemplateRecursionError` once depth passes 25, and the exception message lists the chain of filenames so you can find the loop.
