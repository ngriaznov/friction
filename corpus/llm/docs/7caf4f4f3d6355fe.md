# Programming Channel Memories with ChirpLine

This guide covers using ChirpLine, a desktop utility for programming channel memories into a handheld transceiver, from connecting the programming cable to uploading a finished memory file to the radio.

## Before you start

You'll need:

- A programming cable matched to your radio model (usually a USB-to-TRRS or USB-to-TRS cable — check your radio's manual, since the wrong cable can carry audio and PTT signals into pins the radio doesn't expect them on).
- ChirpLine installed on your computer (available for Windows, macOS, and Linux from the project's downloads page).
- The correct driver for your cable's USB-to-serial chipset installed, if your OS doesn't already recognize it. Most cables use a CP2102 or FTDI chipset; ChirpLine's downloads page links to drivers for both.

## Connecting the radio

Power off the radio, plug the programming cable into its side port, then connect the cable's USB end to your computer. Power the radio back on. Open ChirpLine and go to **Radio > Detect**, which scans available serial ports and attempts to identify the connected radio by querying it directly rather than requiring you to select a model manually.

If detection fails, check **Radio > Select Port** and confirm the correct serial port is chosen — on Windows this will be a `COM` port number, on macOS/Linux something like `/dev/tty.usbserial-XXXX` or `/dev/ttyUSB0`. A cable using an unrecognized chipset, or a driver that didn't install correctly, is the most common cause of a port not appearing in this list at all.

## Reading the current memory

Before making changes, it's worth reading the radio's existing configuration rather than starting from a blank file, especially if it already has channels you don't want to lose. Go to **Radio > Download from Radio**. ChirpLine will show a progress bar as it reads memory over the cable — this typically takes 20–60 seconds depending on the radio model — and then open the result in the main channel table.

## Editing channel memories

The channel table shows one row per memory slot, with columns for channel number, name, receive frequency, transmit frequency (or offset, for repeater channels), and tone settings. To add a channel, click an empty row and fill in:

- **Name** — up to 6–8 characters depending on your radio model's display.
- **Frequency** — the receive frequency in MHz.
- **Offset/Duplex** — for repeater use, whether transmit is shifted up (`+`), down (`-`), or matches receive (`simplex`), and by how much.
- **Tone** — CTCSS or DCS tone if the repeater or group you're working with requires one, otherwise leave as "off."

ChirpLine validates frequencies against the radio's known band coverage as you type and will flag (in orange, non-blocking) a channel outside what the radio can actually transmit on — useful for catching a typo like `146,520` entered as `14.6520`.

## Uploading to the radio

Once your channel table looks right, save the file locally first (**File > Save**, which stores a `.cll` file you can reopen or back up) — this step is easy to skip but worth doing, since re-reading from a partially-programmed radio is a worse starting point than a saved file on your computer if something goes wrong mid-upload.

Then go to **Radio > Upload to Radio**. ChirpLine writes the full memory table back to the radio over the cable, again showing a progress bar. Do not disconnect the cable or power off the radio during this step — an interrupted upload can leave the radio's memory in a partially written state, which on some models requires a full factory reset to recover from.

When the upload finishes, ChirpLine prompts you to verify by reading the memory back and comparing it against what was just sent. This verification step is optional but recommended, especially the first time you're programming a given radio model, since it will catch a cable or driver issue that silently corrupted data during transfer rather than leaving you to discover it in the field.

## After uploading

Power-cycle the radio once uploading and verification are complete — most models don't require this, but a few need a restart before newly written channels appear correctly on the display. Then step through a few channels manually on the radio itself to confirm frequencies and tones match what you expect before relying on them.
