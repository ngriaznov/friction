# Sprocket Annotation Reference

Sprocket wires object graphs at compile time. You describe how objects are built using three annotations, and the annotation processor generates a factory class that constructs them in the right order. There is no reflection at runtime and no XML.

This page documents the three annotations and shows them wiring a small application together.

## `@Provide`

`@Provide` marks a method as a source of instances. Sprocket reads the method's return type as the type being supplied and its parameters as the dependencies needed to supply it.

```java
@Provide
static ConnectionPool connectionPool(DatabaseConfig config) {
    return new ConnectionPool(config.url(), config.maxConnections());
}
```

Rules:

- The method may be `static` or an instance method on a module class. Static methods are preferred; Sprocket does not need to instantiate the enclosing class for them.
- The return type must not be `void` and must not be a primitive wildcard or type variable.
- Parameters are resolved recursively. Every parameter type must itself be provided somewhere in the graph, or compilation fails.
- Two `@Provide` methods returning the same type in the same graph is an error. Use a qualifier (see below) to disambiguate.

`@Provide` accepts one optional element, `qualifier`, a string that distinguishes multiple bindings of the same type:

```java
@Provide(qualifier = "readonly")
static ConnectionPool replicaPool(DatabaseConfig config) { ... }
```

Consumers request the qualified binding with `@Inject(qualifier = "readonly")`.

## `@Inject`

`@Inject` marks a constructor as the one Sprocket should call. A class annotated this way does not need a corresponding `@Provide` method; Sprocket treats the constructor itself as the binding.

```java
final class ReportBuilder {
    private final ConnectionPool pool;

    @Inject
    ReportBuilder(ConnectionPool pool) {
        this.pool = pool;
    }
}
```

Rules:

- At most one constructor per class may carry `@Inject`. Annotating two is a compile error.
- The constructor may be package-private or public. Private constructors are rejected because the generated factory lives in the same package but cannot see private members.
- `@Inject` may also be applied to a constructor *parameter* to attach a qualifier: `@Inject(qualifier = "readonly") ConnectionPool pool`.
- Field and method injection are not supported. Sprocket only injects through constructors.

## `@Scope`

By default every request for a type calls the provider again, producing a fresh instance. `@Scope` changes that. Applied to a `@Provide` method or an `@Inject` constructor, it caches the instance for the lifetime of the graph.

```java
@Provide
@Scope(Scope.SINGLETON)
static ConnectionPool connectionPool(DatabaseConfig config) { ... }
```

`Scope.SINGLETON` is the only built-in value. Custom scopes are declared by supplying any other string, and the graph builder decides when to reset them:

```java
@Scope("request")
```

Scoped instances are created lazily on first request and are safe to share across threads: the generated factory uses double-checked locking on a per-binding lock object.

A scoped binding may not depend on an unscoped binding of a *narrower* scope. Depending on a singleton from a request-scoped provider is fine; the reverse is a compile error, because the singleton would capture a value that outlives its scope.

## Worked example

Three classes: a configuration holder, a connection pool, and a report builder that uses the pool.

```java
final class AppModule {

    @Provide
    @Scope(Scope.SINGLETON)
    static DatabaseConfig config() {
        return new DatabaseConfig(System.getenv("DB_URL"), 10);
    }

    @Provide
    @Scope(Scope.SINGLETON)
    static ConnectionPool pool(DatabaseConfig config) {
        return new ConnectionPool(config.url(), config.maxConnections());
    }
}

final class ReportBuilder {
    private final ConnectionPool pool;

    @Inject
    ReportBuilder(ConnectionPool pool) {
        this.pool = pool;
    }

    String monthlySummary() { ... }
}
```

Declare the graph:

```java
@Graph(modules = AppModule.class)
interface AppGraph {
    ReportBuilder reportBuilder();
}
```

The processor emits `SprocketAppGraph`. Use it:

```java
AppGraph graph = SprocketAppGraph.create();
ReportBuilder builder = graph.reportBuilder();
```

`DatabaseConfig` and `ConnectionPool` are each constructed once. `ReportBuilder` is unscoped, so each call to `reportBuilder()` returns a new instance sharing the same pool.

## Compile-time errors

| Message | Cause |
| --- | --- |
| `no binding for type X` | A parameter type has no `@Provide` method and no `@Inject` constructor. |
| `duplicate binding for type X` | Two providers for the same type and qualifier. |
| `dependency cycle: A -> B -> A` | Circular constructor dependencies. |
| `scope X may not depend on scope Y` | A wider scope depends on a narrower one. |

All four are reported at the offending source location, so your editor will underline the method or constructor responsible.
