# Corkboard Plugin API Reference

Corkboard plugins are JavaScript modules loaded from the `plugins/` directory inside the vault. Each plugin is a folder containing a `manifest.json` and an entry file (by default `main.js`). Corkboard loads plugins at startup, in alphabetical order by folder name, after the vault index has been built but before the first note is rendered.

This page documents the lifecycle hooks, the permissions manifest, and the plugin object that Corkboard passes to your code.

## The plugin object

Your entry file must export a default object. Corkboard reads three optional functions from it — `on_load`, `on_save`, and `on_note_open` — and ignores anything else. All three receive a context object as their first argument. That context is the only supported way to reach the vault; there is no global `corkboard` symbol, and reaching into Node's `fs` will fail unless your manifest declares filesystem access.

```js
export default {
  on_load(ctx) { /* ... */ },
  on_save(ctx, note) { /* ... */ },
  on_note_open(ctx, note) { /* ... */ },
};
```

## Lifecycle hooks

### `on_load(ctx)`

Called once, when the plugin is first loaded. Use it to register commands, read your settings, and set up any state you need. Corkboard awaits the return value, so you can make this `async`, but the whole application startup blocks on it — if you need to do network work, kick it off and let it settle later rather than awaiting it here.

`on_load` is also called again after a hot reload during development (`Settings → Plugins → Reload`). If your plugin registers commands, register them idempotently; re-registering an existing command ID replaces the old one rather than throwing.

### `on_save(ctx, note)`

Called immediately before a note is written to disk. The `note` argument is mutable, which makes this the hook for automatic frontmatter, timestamps, link rewriting, and formatting.

```js
on_save(ctx, note) {
  note.frontmatter.modified = new Date().toISOString();
}
```

Two constraints worth knowing. First, `on_save` must be synchronous — the save path does not await it, and a returned promise is discarded. Second, mutating `note.body` inside `on_save` does not re-trigger the hook, so plugins cannot loop on each other's edits. If several plugins define `on_save`, they run in load order and each sees the previous plugin's changes.

Autosave fires `on_save` too, roughly every four seconds while a note is being edited. Do not put expensive work here.

### `on_note_open(ctx, note)`

Called when a note becomes the active note in the editor, including when the user switches tabs back to an already-open note. The `note` argument is read-only here; assignments are silently dropped. This hook is for reacting to context — updating a side panel, fetching related notes, logging.

Unlike `on_save`, this hook may be `async`. The editor renders without waiting for it.

## Permissions manifest

Corkboard plugins run with no ambient capability. Everything beyond reading the currently open note has to be declared in `manifest.json` and approved by the user the first time the plugin loads.

```json
{
  "id": "word-count-plus",
  "name": "Word Count Plus",
  "version": "1.2.0",
  "entry": "main.js",
  "minCorkboardVersion": "3.1",
  "permissions": {
    "vault": "read",
    "network": ["api.example.com"],
    "filesystem": false,
    "clipboard": true
  }
}
```

The permission keys:

- **`vault`** — one of `"none"`, `"read"`, or `"write"`. `"read"` grants `ctx.vault.getNote()` and `ctx.vault.list()`; `"write"` additionally grants `ctx.vault.createNote()` and `ctx.vault.deleteNote()`. Note that mutating the `note` object in `on_save` does *not* require `"write"` — that is considered part of the save the user already initiated.
- **`network`** — an array of hostnames. Wildcards are not supported; list each host. `fetch` to an undeclared host rejects with `PermissionError`.
- **`filesystem`** — a boolean. Grants access to paths outside the vault via `ctx.fs`. Users see a strongly worded prompt for this one, so avoid it unless the plugin genuinely needs it.
- **`clipboard`** — a boolean, gating `ctx.clipboard.read()` and `.write()`.

Omitted keys default to the most restrictive value. If you add a permission in a later version, the user is prompted again on upgrade; existing grants for unchanged permissions carry over.

## A minimal example

This plugin appends a word count to the frontmatter of every note on save, and shows it in the status bar when a note is opened.

```js
// main.js
function countWords(text) {
  return text.trim().split(/\s+/).filter(Boolean).length;
}

export default {
  on_load(ctx) {
    ctx.log.info("word-count-plus loaded");
    this.status = ctx.ui.statusBarItem("wc");
  },

  on_save(ctx, note) {
    note.frontmatter.wordcount = countWords(note.body);
  },

  on_note_open(ctx, note) {
    this.status.setText(`${countWords(note.body)} words`);
  },
};
```

Its manifest needs no permissions at all — it only touches the note it is handed:

```json
{
  "id": "word-count-plus",
  "name": "Word Count Plus",
  "version": "1.0.0",
  "entry": "main.js",
  "minCorkboardVersion": "3.1",
  "permissions": {}
}
```

Drop the folder into `plugins/`, restart Corkboard or reload plugins from Settings, and the counter appears in the status bar.
