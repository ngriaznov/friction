# Setting Up Two-Factor Authentication in Latchkey

Latchkey supports time-based one-time passwords (TOTP) as a second factor on the vault login. Once enabled, unlocking your vault requires both your master password and a six-digit code from an authenticator app. This guide covers turning it on, saving backup codes, and getting back in if you lose the device holding your authenticator.

Two-factor authentication in Latchkey protects the *login* to your server. It does not change how the vault itself is encrypted — that still depends entirely on the strength of your master password. Treat TOTP as protection against someone who has your password but not your phone, not as a substitute for a good password.

## Before you start

You need:

- Latchkey server 2.4 or later (check with `latchkey --version` on the host)
- An authenticator app that supports TOTP — Aegis, Ente Auth, 1Password, and Google Authenticator all work
- Your master password, since Latchkey re-prompts for it before changing security settings

If your server clock drifts, TOTP codes will be rejected. Confirm NTP is running on the host before you enable anything, or you may lock yourself out for reasons that have nothing to do with your phone.

## Enabling TOTP

1. Sign in to the web vault and open **Settings → Security → Two-factor authentication**.
2. Click **Enable TOTP**. Latchkey asks for your master password again.
3. A QR code and a base32 secret appear. Scan the QR code with your authenticator app, or type the secret in manually if the camera is not cooperating.
4. Enter the current six-digit code in the confirmation field and click **Verify**.

Latchkey will not activate the second factor until it sees one valid code from your app. If verification fails twice in a row, the most likely cause is clock skew on either the phone or the server.

To enable TOTP from the CLI instead:

```
latchkey 2fa enable --method totp
```

The command prints the secret as text and an `otpauth://` URI, then waits for a confirming code on stdin.

## Saving backup codes

As soon as TOTP is verified, Latchkey generates ten single-use backup codes. This is the only time they are shown.

Each code works exactly once in place of a TOTP code. Print them and keep the sheet somewhere physical — a drawer at home, a safe, an envelope with your passport. Do not store them inside the vault they unlock. Storing your only recovery path behind the thing it recovers is the most common way people lose access.

Regenerate the set at any time with **Settings → Security → Regenerate backup codes**. Regenerating invalidates every previously issued code.

## If you lose your phone

Try these in order:

**Use a backup code.** At the TOTP prompt, click **Use a backup code** and enter one. Once inside, immediately disable TOTP, then re-enable it against your new device. The old secret stays valid otherwise, and a lost phone that gets restored from backup still generates working codes.

**Restore the secret from an authenticator backup.** Aegis and Ente export encrypted vaults. Import the export on the new device and the Latchkey entry comes back intact.

**Reset from the server.** With shell access to the host, run:

```
latchkey admin 2fa reset --user you@example.com
```

This clears the TOTP secret and all backup codes for that account, returning it to password-only login. Anyone with root on the box can do this, which is worth remembering when you think about your threat model. Re-enroll a new authenticator right after logging back in.
