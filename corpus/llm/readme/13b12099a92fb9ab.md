# multitail-go

`multitail-go` tails several log files at once from a single terminal window, prefixing every line with a color-coded label so you can tell at a glance which file it came from. It's built for the common case of watching an application server and its database (or a web server and a worker process, or three microservices) side by side without juggling multiple terminal panes.

## Installation

```
go install github.com/example/multitail-go@latest
```

This places a `multitail-go` binary in your `$GOPATH/bin` (or `$HOME/go/bin` if `GOPATH` isn't set). Make sure that directory is on your `PATH`.

Prebuilt binaries for Linux, macOS, and Windows are also available on the [releases page](#), if you'd rather skip the Go toolchain.

## Basic Usage

Pass one or more file paths as arguments:

```
multitail-go /var/log/app.log /var/log/postgres.log
```

Each line printed to your terminal is prefixed with a short, color-coded label derived from the file name:

```
[app ] 2024-03-11 10:02:14 INFO  request completed in 42ms
[pg  ] 2024-03-11 10:02:14 LOG   duration: 3.219 ms  statement: SELECT ...
[app ] 2024-03-11 10:02:15 WARN  slow downstream call: 812ms
```

Labels are padded to a consistent width so columns stay aligned as lines stream in. By default `multitail-go` follows each file the way `tail -f` does, picking up new lines as they're written and handling files that are rotated out from under it (see below).

Useful flags:

- `-n <count>` — number of existing lines to print from each file before following (default: 10)
- `-no-color` — disable ANSI colors, useful when piping output to another tool or a file
- `-timestamps` — prepend `multitail-go`'s own read timestamp to each line, independent of whatever the source log already contains

## Glob Pattern Support

Log rotation tools like `logrotate` rename the active file (`app.log` → `app.log.1`) and start a fresh one, which breaks naive tailing. `multitail-go` accepts glob patterns instead of literal paths and re-resolves them periodically, so it picks up the newly created file automatically:

```
multitail-go "/var/log/app*.log" "/var/log/postgres/*.log"
```

Quote your globs so the shell doesn't expand them first — `multitail-go` needs to see the pattern itself, not a pre-expanded list, since it re-evaluates the pattern every few seconds to detect rotation. When a glob matches multiple files at once, each gets its own label and color, same as if you'd listed them individually.

## Filtering with a Regex

To cut down the noise, filter every source down to lines matching a pattern with `-match`:

```
multitail-go -match "ERROR|WARN" /var/log/app.log /var/log/postgres.log
```

`-match` applies the same pattern across all sources. If you need per-source filtering, prefix the pattern to a specific file using `path:pattern` syntax:

```
multitail-go -match "/var/log/app.log:ERROR" -match "/var/log/postgres.log:duration"
```

Regex syntax follows Go's `regexp` package (RE2 syntax), which covers the vast majority of everyday filtering needs but does not support backreferences or lookahead.

## How Colors Are Assigned

Each source gets a color deterministically derived by hashing its file path (or glob pattern) and mapping the result onto a fixed palette of eight ANSI colors. This means the same file always gets the same color across runs, which matters when you're context-switching between terminal sessions and relying on muscle memory to spot the database log versus the app log.

If two sources happen to hash to the same color, `multitail-go` perturbs the hash for the second one so no two active sources ever share a color in a single run. Colors reset and get reassigned each time the process starts — they are not persisted between runs.
