# csvtype

`csvtype` is a Rust crate that reads CSV files and infers a column type schema — integer, float, date, boolean, or string — by sampling rows, then hands you a typed record iterator instead of raw strings. No more parsing every field by hand after pulling it out of a `csv::Reader`.

## Why

Reading a CSV in Rust usually means getting back `&str` or `String` for every field and parsing each one yourself, field by field, row by row. `csvtype` does that inference once, up front, and gives you an iterator of records where each field already carries its inferred type.

## Installation

Add it to your `Cargo.toml`:

```toml
[dependencies]
csvtype = "0.3"
```

## Basic usage

```rust
use csvtype::TypedReader;

fn main() -> Result<(), csvtype::Error> {
    let reader = TypedReader::from_path("data/orders.csv")?;

    let schema = reader.infer_schema()?;
    println!("{:#?}", schema);
    // Schema { columns: [
    //   Column { name: "order_id", kind: Integer },
    //   Column { name: "total", kind: Float },
    //   Column { name: "placed_at", kind: Date },
    //   Column { name: "shipped", kind: Boolean },
    //   Column { name: "notes", kind: String },
    // ] }

    for record in reader.typed_records()? {
        let record = record?;
        let total: f64 = record.get_float("total")?;
        let shipped: bool = record.get_bool("shipped")?;
        println!("total = {total}, shipped = {shipped}");
    }

    Ok(())
}
```

`infer_schema()` and `typed_records()` can be called independently, but calling `infer_schema()` first lets you inspect or override the schema before iterating.

## How sampling affects accuracy

By default, `csvtype` samples the first 1,000 rows to infer each column's type. That's a deliberate tradeoff: sampling the whole file guarantees correctness but is wasteful on large files, while sampling too few rows risks missing a rare value that doesn't fit the inferred type (a stray non-numeric entry in an otherwise numeric column, for instance).

You can adjust the sample size to fit your data:

```rust
let reader = TypedReader::from_path("data/orders.csv")?
    .with_sample_size(10_000);
```

Setting `sample_size` to `None` forces a full-file scan before inference, which is the safest option for smaller files or one-off scripts where correctness matters more than startup time. As a rule of thumb: the more homogeneous your data, the smaller a sample you can get away with. Files with sparse or optional columns benefit from a larger sample or a full scan.

When a value in the actual data doesn't match its column's inferred type, `typed_records()` yields an error for that record rather than silently coercing or dropping the value, so bad inference surfaces immediately instead of corrupting downstream calculations.

## Overriding an inferred type

Sometimes inference gets it wrong — a `zip_code` column made entirely of five-digit numbers will infer as `Integer`, which drops leading zeros. Override it per column before reading records:

```rust
let mut schema = reader.infer_schema()?;
schema.set_kind("zip_code", csvtype::Kind::String);

let records = reader.typed_records_with_schema(&schema)?;
```
