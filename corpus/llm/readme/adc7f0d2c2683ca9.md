# tablescrape

Pull tabular data out of messy HTML pages into pandas DataFrames.

`pandas.read_html` is fine when a page contains one clean `<table>` with a single header row. Real pages are rarely that. They wrap layout in tables, split headers across two or three rows, merge cells with `rowspan` and `colspan`, and bury the data you want among navigation, ad slots, and sidebar widgets. `tablescrape` handles those cases: it scores candidate tables to find the one that actually holds data, expands merged cells, and flattens nested headers into a usable column index.

## Installation

```
pip install tablescrape
```

Requires Python 3.9+. Depends on `pandas`, `lxml`, and `requests`.

## Quick start

From a local file:

```python
from tablescrape import extract

tables = extract("reports/q3_summary.html")
df = tables[0]
print(df.head())
```

`extract` returns a list of DataFrames, ordered by confidence score — highest first. In most cases the table you want is `tables[0]`.

From a live URL:

```python
from tablescrape import extract_url

tables = extract_url(
    "https://example.org/stats/population",
    user_agent="my-research-bot/1.0 (contact@example.org)",
    respect_robots=True,
)

df = tables[0]
df.to_csv("population.csv", index=False)
```

If you already have the markup in hand — from Playwright, a cached response, whatever — pass the string directly:

```python
tables = extract(html_string)
```

### Nested headers

When a table has multiple header rows, `tablescrape` produces a `MultiIndex` on the columns:

```python
df = extract("financials.html")[0]
df.columns
# MultiIndex([('2023', 'Revenue'),
#             ('2023', 'Margin'),
#             ('2024', 'Revenue'),
#             ('2024', 'Margin')])
```

Pass `flatten_headers=True` to collapse these into single strings joined with a separator (`2023 · Revenue`). Set `header_sep` to change the separator.

### Merged cells

Cells spanning multiple rows or columns are expanded so the value is repeated across every position it covers. This makes the frame rectangular and safe to index. If you would rather see the duplicates as nulls, pass `fill_spans=False`.

## How table detection works

Given a page with a dozen `<table>` elements, `tablescrape` scores each one and returns them ranked. The scoring is heuristic, not magic, and it is deliberately simple enough to reason about:

- **Shape.** Data tables tend to be taller than they are wide and have a consistent cell count per row. Ragged row lengths are penalized heavily.
- **Header markup.** Presence of `<th>`, a `<thead>` block, or a `scope` attribute raises the score. Layout tables almost never bother.
- **Cell content density.** Tables whose cells contain mostly short text and numbers score higher than ones stuffed with images, forms, or nested block elements.
- **Type consistency down columns.** If a column is 90% parseable as numbers or dates, that is strong evidence of real data. Mixed junk is evidence against.
- **Nesting depth.** A table containing another table is usually scaffolding. The inner one usually holds the data.
- **Size floor.** Anything under two rows or two columns is dropped unless `min_rows` / `min_cols` are lowered.

You can inspect the scores when a page surprises you:

```python
from tablescrape import extract_scored

for df, score, reasons in extract_scored("page.html"):
    print(score, reasons, df.shape)
```

`reasons` is a dict of the individual heuristic contributions, which makes it much easier to see why the wrong table won.

If detection picks badly and you know the structure, skip it entirely with a CSS selector:

```python
df = extract("page.html", selector="#results table.data")[0]
```

## A note on scraping live sites

`extract_url` sets `respect_robots=True` by default. It fetches `/robots.txt`, checks the path against your declared user agent, and raises `RobotsDisallowed` rather than making the request if the rules forbid it. You can turn this off, but please think about whether you should.

Beyond robots.txt: send a real user agent with a way to contact you, keep request rates low, and cache responses locally while you iterate on parsing rather than re-fetching the page fifty times. Many sites publish the same data as CSV or through an API — check for that first. A polite scraper that nobody notices is one that keeps working.
