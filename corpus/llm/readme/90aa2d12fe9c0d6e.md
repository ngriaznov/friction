# wavtag

A small C library for reading and writing `LIST`/`INFO` metadata chunks in WAV files — artist, title, comment, and the rest of the standard RIFF info tags. It never touches the `data` chunk, so your audio samples come out bit-identical.

Roughly 900 lines, no dependencies beyond libc, C99.

## Building

```sh
make            # builds libwavtag.a
make test       # runs the test suite
make install    # PREFIX=/usr/local by default
```

To build a shared library instead, `make shared`. There is no configure step.

## API

```c
#include <wavtag.h>

wav_file *wav_open(const char *path, int mode);
```

`mode` is `WAV_READ` or `WAV_RDWR`. Returns `NULL` and sets `wav_errno` on failure.

```c
const char *wav_get_tag(wav_file *f, const char *id);
int         wav_set_tag(wav_file *f, const char *id, const char *value);
int         wav_del_tag(wav_file *f, const char *id);
```

`id` is a four-character RIFF info ID such as `"IART"` (artist), `"INAM"` (title), or `"ICMT"` (comment). Convenience macros — `WAVTAG_ARTIST`, `WAVTAG_TITLE`, `WAVTAG_COMMENT` — are provided for the common ones. `wav_get_tag` returns a pointer owned by the file handle; copy it if you need it after `wav_close`.

```c
int wav_save(wav_file *f);   /* rewrite the LIST chunk in place */
int wav_close(wav_file *f);
```

Edits are held in memory until `wav_save`. If the new `LIST` chunk is larger than the old one, the file is rewritten via a temporary file in the same directory and renamed over the original, which keeps the operation atomic on POSIX filesystems.

A minimal example:

```c
wav_file *f = wav_open("track.wav", WAV_RDWR);
wav_set_tag(f, WAVTAG_ARTIST, "Marit Halvorsen");
wav_save(f);
wav_close(f);
```

## Byte order

RIFF is little-endian, always. All chunk sizes and field lengths are read and written through explicit byte-shuffling helpers rather than by casting a `char *` to a `uint32_t`, so the library behaves the same on big-endian hosts and does not rely on unaligned access. There is no need to define anything at build time to select a target endianness.

## Limitations

Only the `LIST`/`INFO` chunk is understood. `ID3` chunks embedded in WAV files, BWF `bext` metadata, and iXML are all left in place untouched but are not parsed or exposed. Files larger than 4 GB (RF64 and its variants) are rejected with `WAV_ERR_FORMAT`, since the RIFF size fields cannot describe them.

Tag values are treated as opaque byte strings terminated by NUL. The spec predates any sensible encoding story, so if you need UTF-8 you can write it, but nothing here validates it and other tools may disagree about how to read it back.
