# invoicer4j

invoicer4j is a Java library for generating PDF invoices from a template plus a plain data object. It handles layout, currency formatting, and pagination on top of an existing PDF layout engine, so your application code only has to supply the invoice data and a template file.

## Installation

Add the Maven dependency:

```xml
<dependency>
    <groupId>com.invoicer4j</groupId>
    <artifactId>invoicer4j-core</artifactId>
    <version>2.3.0</version>
</dependency>
```

## Quick example

```java
Invoice invoice = Invoice.builder()
    .invoiceNumber("INV-2024-0113")
    .issueDate(LocalDate.of(2024, 3, 4))
    .billTo(new Party("Aster Rentals LLC", "412 Kettle St, Portland, OR"))
    .currency(Currency.USD)
    .locale(Locale.US)
    .addLineItem(new LineItem("Consulting - March", 12, new BigDecimal("95.00")))
    .addLineItem(new LineItem("On-site travel", 1, new BigDecimal("340.00")))
    .build();

InvoiceRenderer renderer = InvoiceRenderer.fromTemplate("templates/standard.xml");
renderer.renderToFile(invoice, Paths.get("out/INV-2024-0113.pdf"));
```

`LineItem` takes a description, a quantity, and a unit price; invoicer4j computes line totals and the invoice grand total for you, applying the currency and locale you specified.

## Templates

Templates are defined in a simple XML layout format, not code. A minimal template looks like this:

```xml
<template>
  <header>
    <logo src="assets/logo.png" align="left"/>
    <field name="invoiceNumber" label="Invoice #"/>
    <field name="issueDate" label="Date" format="MMMM d, yyyy"/>
  </header>
  <body>
    <table columns="description,quantity,unitPrice,lineTotal"/>
  </body>
  <footer>
    <field name="grandTotal" label="Total Due"/>
  </footer>
</template>
```

The `<table>` element's `columns` attribute controls which fields appear and in what order; each named field maps to a getter on `LineItem` or `Invoice`. You can add as many `<field>` elements to the header or footer as you need, and each supports an optional `format` attribute for dates and numbers.

## Currencies and locales

invoicer4j formats monetary values using Java's built-in locale-aware number formatting, so a `USD` invoice rendered with `Locale.US` prints `$1,235.00` while the same invoice rendered with `Locale.GERMANY` and `Currency.EUR` prints `1.235,00 €`. Supported currencies are anything in `java.util.Currency`; there's no invoicer4j-specific currency list to maintain. Set both the currency and locale on the `Invoice` builder, since currency determines the symbol and locale determines the separator and grouping conventions.

## Known limitations

- **Multi-page invoices are basic.** If an invoice's line items overflow onto a second page, invoicer4j repeats the table header on the new page but does not currently support custom per-page headers or footers — every page after the first uses the same footer as the last page, which can look odd if your footer includes page-specific totals.
- **No built-in support for tax line calculation.** invoicer4j will render a tax line if you add one as a regular `LineItem`, but it does not compute tax amounts for you; that logic needs to live in your application before you build the `Invoice` object.
- **Template validation happens at render time, not at load time.** A template referencing a field that doesn't exist on `Invoice` or `LineItem` will fail with an exception the first time you call `renderToFile`, not when you call `InvoiceRenderer.fromTemplate`.

## Contributing

Issues and pull requests are welcome. Please include a minimal reproducing template and data object for any rendering bug reports — most layout issues are easiest to diagnose with the actual XML and Java that triggered them rather than a description of the output.
