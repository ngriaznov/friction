# confkeep

confkeep is a small Python library for reading and writing INI-style configuration files without losing the user's formatting. It parses a file into an editable structure, and when you write it back out, comments, blank lines, key ordering, and section ordering are all preserved exactly as they were — only the values you actually changed are different.

## Why not configparser?

The standard library's `configparser` is a perfectly good INI parser, but it's a one-way trip. Once you load a file into a `ConfigParser` object, the comments are gone and the blank lines are gone, and if you call `.write()` afterward you get a re-serialized file in configparser's own formatting, not the user's. That's fine if the file is machine-generated and nobody ever looks at it. It's a problem the moment a human maintains that file by hand, adds their own comments to explain a setting, or groups related keys with blank lines for readability — because the next time your program touches the file programmatically, all of that gets silently thrown away.

confkeep keeps a parse tree that tracks every line, not just the key-value pairs, so a round trip through confkeep with no edits produces byte-for-byte identical output.

## Installation

```bash
pip install confkeep
```

## Usage

```python
from confkeep import ConfigFile

config = ConfigFile.load("app.conf")
config["database"]["host"] = "db.internal.example.com"
config.save("app.conf")
```

Only the `host` line inside the `[database]` section changes. Every comment, every blank line, and every other section in the file is untouched.

## Supported syntax

confkeep handles a few INI quirks that trip up simpler parsers:

**Inline comments.** A `;` or `#` after a value on the same line is treated as a trailing comment and preserved separately from the value itself:

```ini
timeout = 30  ; seconds, tune this if requests start timing out
```

Editing `timeout` programmatically leaves the inline comment in place.

**Multi-line values.** A value can continue onto following lines as long as they're indented further than the key:

```ini
description = This is a long value
    that continues onto a second
    and third line.
```

confkeep joins these into a single logical value on read and re-wraps them the same way on write, unless you explicitly assign a new single-line string, in which case it collapses to one line.

**Section inheritance.** A section can declare `extends = other_section` to inherit any keys it doesn't itself define:

```ini
[base]
retries = 3
timeout = 30

[production]
extends = base
timeout = 60
```

Reading `config["production"]["retries"]` returns `3`, resolved from `base`, while `timeout` resolves to `60` from `production` itself. Inheritance is resolved at read time and does not affect how the file is written back out — the `extends` key and each section's own explicit keys are preserved exactly as written.

## Limitations

confkeep expects well-formed INI syntax and will raise `ConfkeepParseError` on files with unmatched brackets or keys outside any section. It does not support the `%()s` interpolation syntax from configparser; values are always read as plain strings.
