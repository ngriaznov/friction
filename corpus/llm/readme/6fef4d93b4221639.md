# passvault

A command-line password manager that stores every credential as its own GPG-encrypted file inside a git repository.

If you have used `pass`, the idea will be familiar. passvault differs in its storage layout: secrets live in a two-level directory structure with a plaintext index of *names only*, which makes listing and searching fast without decrypting anything, and it keeps metadata (username, URL, notes) inside the encrypted blob rather than in the filename.

There is no daemon, no database, and no sync service. Your vault is a git repo full of `.gpg` files. If passvault disappeared tomorrow you could still read every secret with `gpg -d`.

## Requirements

- GnuPG 2.2 or later
- git 2.20 or later
- A GPG key pair (see below if you don't have one)
- `xclip` (Linux) or `pbcopy` (macOS) for clipboard support

## Installation

From a release archive:

```
curl -LO https://example.invalid/passvault/passvault-1.4.0.tar.gz
tar xzf passvault-1.4.0.tar.gz
cd passvault-1.4.0
sudo make install
```

From source:

```
git clone https://example.invalid/passvault.git
cd passvault
sudo make install
```

`make install` places the `passvault` script in `/usr/local/bin` and shell completions for bash and zsh in the usual locations. Set `PREFIX` to install elsewhere.

## Initializing a vault

You need a GPG key first. If you don't have one:

```
gpg --full-generate-key
```

Accept the defaults, use a real email address, and give the key a passphrase you will remember. Then find its ID:

```
gpg --list-secret-keys --keyid-format=long
```

Initialize the vault with that key ID:

```
passvault init 3AA5C34371567BD2
```

This creates `~/.passvault`, writes the key ID to `~/.passvault/.gpg-id`, and runs `git init` inside it. Every subsequent change is committed automatically.

To use a different location, set `PASSVAULT_DIR` in your shell profile.

## Adding secrets

```
passvault add github.com/alice
```

You will be prompted for the password, then dropped into `$EDITOR` to fill in optional metadata:

```
username: alice
url: https://github.com/login
notes:
```

Leave any field blank to omit it. Save and quit, and the whole thing is encrypted to a single file and committed.

To skip the editor and store only a password:

```
passvault add --quick github.com/alice
```

To pipe a password in from another program:

```
some-generator | passvault add --stdin github.com/alice
```

## Retrieving secrets

Print a secret to the terminal:

```
passvault show github.com/alice
```

Print only one field:

```
passvault show --field username github.com/alice
```

List everything in the vault:

```
passvault list
```

Search by substring across names:

```
passvault find github
```

Both `list` and `find` read the plaintext name index and never invoke GPG, so they return instantly even on large vaults.

## Clipboard with auto-clear

```
passvault copy github.com/alice
```

The password goes to the clipboard and is cleared after 45 seconds. passvault restores whatever was in the clipboard before, rather than leaving it empty, and it only restores if the clipboard still contains the secret it put there — if you copied something else in the meantime, your copy is left alone.

Change the timeout with `--timeout` or by setting `PASSVAULT_CLIP_TIME`:

```
passvault copy --timeout 15 github.com/alice
```

Note that clipboard managers with history will keep the secret regardless. If you run one, either exclude passvault or use `show` and select the text manually.

## Generating passwords

```
passvault generate github.com/alice
```

Generates a 24-character password from `/dev/urandom`, stores it, and prints it. Flags:

- `--length N` — set the length (default 24)
- `--no-symbols` — alphanumeric only, for sites that reject punctuation
- `--copy` — copy instead of printing
- `--force` — overwrite an existing entry

Regenerating an existing entry without `--force` is refused, since the git history is the only way back and it is easier to not need it.

## Syncing

The vault is an ordinary git repository, so use ordinary git:

```
passvault git remote add origin git@example.invalid:alice/vault.git
passvault git push -u origin main
```

`passvault git` runs any git command inside the vault directory. Shortcuts exist for the two you'll use daily:

```
passvault push
passvault pull
```

Because each secret is a separate file, conflicts are rare — two machines editing different credentials merge cleanly. If you do get a conflict on the same entry, git will leave both versions and passvault will refuse to decrypt until you resolve it, since a merged ciphertext is meaningless.

The remote sees only encrypted blobs and the name index. Treat the name index as public: the fact that you have an account somewhere is visible to anyone who can read the repo.

## On-disk layout

```
~/.passvault/
├── .gpg-id                  key ID the vault encrypts to
├── .index                   plaintext list of entry names
├── .git/
└── store/
    ├── gi/
    │   └── github.com%2Falice.gpg
    ├── ex/
    │   └── example.org%2Fwork.gpg
    └── ba/
        └── bank%2Fchecking.gpg
```

Entries are sharded into subdirectories by the first two characters of the SHA-256 hash of their name, which keeps directory sizes reasonable and avoids exposing entry names in the filesystem to a casual observer. Slashes in entry names are percent-encoded, so `github.com/alice` is one file, not a nested directory.

The `.index` file maps hashes back to names. It is regenerated with `passvault reindex` if it is ever lost.

## Multiple keys

To encrypt to more than one key — a second machine, or a colleague on a shared vault — list the IDs in `.gpg-id`, one per line, then run:

```
passvault reencrypt
```

This decrypts and re-encrypts every entry to the new recipient set and commits the result as a single commit.
