# brewlog

An Android app for people who brew beer at home and are tired of losing track of which carboy is which.

brewlog stores your recipes, tracks batches from pitch to packaging, records gravity readings, and estimates ABV from them. Everything lives in a local SQLite database on the device. There is no account, no server, and no network permission in the manifest.

## Getting it

### APK

Signed releases are published on the [Releases page](https://github.com/example/brewlog/releases). Download the `.apk`, allow installation from unknown sources for your file manager, and open it. Minimum supported version is Android 8.0 (API 26).

brewlog is also on F-Droid. If you already have F-Droid installed, search for "brewlog" — the build there is reproducible from this repository.

### Building from source

```sh
git clone https://github.com/example/brewlog.git
cd brewlog
./gradlew assembleDebug
```

The APK lands in `app/build/outputs/apk/debug/`. You will need JDK 17 and the Android SDK with build-tools 34. No signing config is required for a debug build.

To run the test suite:

```sh
./gradlew test connectedAndroidTest
```

The instrumented tests need a connected device or running emulator.

## The main screens

### Recipe library

The landing screen. Recipes are stored independently of batches, so one recipe can produce many batches over the years and you can see how they compare.

Each recipe holds a name, style, target batch volume, a fermentable list with weights, hop additions with timings, yeast strain, and a free-text notes field. There is a duplicate action, which is what most people actually use — you rarely start a recipe from nothing, you start from the last one and change the hops.

Recipes can be exported to and imported from BeerXML, so you can move things in from other brewing software. The importer is forgiving about missing optional fields and will tell you what it dropped.

### Active batch tracker

A batch is created from a recipe and carries its own timeline. When you create it, brewlog asks for the brew date and the original gravity.

The timeline is the heart of the app. Every event you log — gravity reading, temperature check, dry hop addition, transfer to secondary, cold crash, packaging — appears in date order with any note you attached. Gravity readings are also plotted on a small chart so you can see the fermentation curve flatten out.

Batches move through states: **Fermenting**, **Conditioning**, **Packaged**, **Archived**. The state is manual, because only you know when the beer is really done.

Each batch also gets a day counter on the card, which is the number most people open the app to check.

### Tasting notes

Attached to a packaged batch. Aroma, appearance, flavour, mouthfeel, and overall, each with a free-text field and an optional 1–5 rating. You can add more than one tasting note per batch, dated, so you can track how a beer changes over three months in the bottle.

Photos can be attached to tasting notes. They are stored in the app's private files directory and included in backups.

## Gravity readings and ABV

brewlog uses the standard estimate:

```
ABV% = (OG − FG) × 131.25
```

where OG is the original gravity and FG the final gravity, both in specific gravity units. For a beer that went from 1.056 to 1.012, that gives roughly 5.8% ABV.

A few details worth knowing:

- **Temperature correction.** Hydrometers are calibrated to a reference temperature, usually 20 °C / 68 °F. If you enter the sample temperature alongside the reading, brewlog applies the correction before storing the value. The correction is small below about 30 °C and gets significant above it.
- **Plato input.** You can enter readings in degrees Plato instead of specific gravity; set the unit in Settings and brewlog converts internally. Stored values are always SG.
- **Refractometer readings.** Once fermentation has started, alcohol skews refractometer readings. Mark a reading as coming from a refractometer and brewlog applies a correction using the original gravity. Treat corrected values as approximate — a hydrometer reading on the final gravity is still the honest one.
- **Attenuation.** Apparent attenuation is shown on the batch screen once there are at least two readings. It is useful for spotting a stalled fermentation early.

The ABV figure is an estimate. It does not account for priming sugar in bottle-conditioned beer, which typically adds something in the region of 0.2–0.4%.

## Backup and export

Settings > Data has three actions.

**Export database.** Writes the full SQLite file to a location you pick through the system file picker. This is a complete backup: recipes, batches, readings, notes, and photo references. Photos are bundled alongside it if you choose the zip option.

**Import database.** Replaces the current database with one from a previous export. This is destructive and the app asks twice.

**Export CSV.** Writes a flat CSV of batches and readings for anyone who wants to do their own analysis in a spreadsheet. This is one-way; there is no CSV import.

There is no automatic cloud sync, by design. If you want your backups offsite, point the export at a folder that your own sync app already watches.
