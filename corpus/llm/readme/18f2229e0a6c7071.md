# multitail-go

Tail several log files at once, with each line prefixed by a color-coded label telling you which file it came from.

If you have ever had four terminal panes open — app server, database, worker, nginx — and tried to correlate a request across them by squinting at timestamps, this is for that. One stream, one screen, sources you can tell apart at a glance.

```
$ multitail-go /var/log/app/server.log /var/log/postgresql/postgresql.log
server    14:02:11 POST /api/orders started
postgres  14:02:11 LOG:  duration: 1841.220 ms  statement: SELECT ...
server    14:02:13 POST /api/orders 200 in 1893ms
```

## Install

```
go install github.com/mrothwell/multitail-go/cmd/multitail-go@latest
```

Requires Go 1.21 or newer. The binary has no runtime dependencies; you can also grab a prebuilt one from the releases page.

## Basic usage

Pass any number of file paths:

```
multitail-go server.log worker.log db.log
```

Each file gets a label derived from its base name with the extension stripped (`server.log` → `server`) and a color. Labels are padded to a common width so the message text lines up.

Override a label with `path=label` syntax:

```
multitail-go /var/log/nginx/access.log=web /var/log/app/current=api
```

By default multitail-go starts at the end of each file, like `tail -f`. To include existing content, use `-n`:

```
multitail-go -n 200 server.log worker.log   # last 200 lines of each, then follow
multitail-go -n all server.log              # whole file, then follow
```

Lines are interleaved in arrival order, not by any timestamp parsed out of the content. If two sources write at nearly the same instant, ordering between them is whatever the filesystem hands us.

## Globs and log rotation

Quote the pattern so your shell doesn't expand it — multitail-go needs the pattern itself, not a one-time expansion:

```
multitail-go '/var/log/myapp/*.log'
```

Passing the pattern lets it pick up files that appear later. It rescans matching paths every two seconds (configurable with `-rescan`) and starts following anything new.

Rotation is handled by watching the inode of each open file. When a file is renamed or replaced — logrotate's `create` mode, `copytruncate`, or a plain `mv` — multitail-go notices, closes the old handle after draining it, and reopens the path. You will not silently stop receiving output after midnight, which is the failure mode that motivated writing this.

Truncation in place (a file getting shorter) is detected by comparing size against the read offset, and reading resumes from byte zero.

## Filtering

`-grep` keeps only matching lines; `-v` drops matching lines. Both take a Go regular expression (RE2 syntax — no backreferences or lookaround, which is a feature, since patterns can't blow up on you).

```
multitail-go -grep 'ERROR|WARN' app.log db.log
multitail-go -v '/healthz' access.log
```

Filters apply to the message text only, not the label prefix, so `-grep server` will not match every line from the `server` source.

To filter a single source differently from the others, prefix the pattern with a label:

```
multitail-go -grep 'db:duration' app.log db.log
```

`-i` makes all patterns case-insensitive.

## Colors

Colors are assigned deterministically: the label string is hashed (FNV-1a) and the result indexed into a palette. The same file gets the same color every run and on every machine, which matters more than you'd think when you're comparing your terminal against a colleague's screenshot.

The default palette is eight 256-color entries chosen to stay legible on both light and dark backgrounds. It deliberately excludes red — red is reserved for lines matched by `-highlight`, so a genuine error stands out against the label colors rather than competing with them.

Pin a color explicitly with the extended label syntax:

```
multitail-go 'db.log=db:red' 'app.log=app:cyan'
```

Named colors: `red`, `green`, `yellow`, `blue`, `magenta`, `cyan`, `white`, `grey`, plus `color0`–`color255` for direct 256-color codes.

Output is colorized only when stdout is a terminal, so piping into `grep` or a file gives you clean text. Force it either way with `-color=always` or `-color=never`. `NO_COLOR` is honored.

## Flags

| Flag | Default | Description |
|---|---|---|
| `-n` | `0` | Lines of history per file; `all` for the whole file |
| `-grep` | — | Keep lines matching this regex (repeatable) |
| `-v` | — | Drop lines matching this regex (repeatable) |
| `-i` | `false` | Case-insensitive matching |
| `-highlight` | — | Print matching lines in red |
| `-rescan` | `2s` | Glob rescan interval |
| `-color` | `auto` | `auto`, `always`, or `never` |
| `-ts` | `false` | Prefix each line with local receive time |
