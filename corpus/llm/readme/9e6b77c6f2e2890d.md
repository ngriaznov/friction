# pastebin-lite

A small self-hosted paste service. Drop a snippet in, get a link back, share it. Pastes can expire on a timer and can be locked behind a password. Syntax highlighting covers about 180 languages.

It ships as a single Docker image with SQLite for metadata and the filesystem for paste bodies. There is no external database, no message queue, and no build step — `docker compose up -d` and you have a working instance.

## Quick start

Create a directory for the deployment and drop in this `docker-compose.yml`:

```yaml
services:
  pastebin-lite:
    image: ghcr.io/dunemoor/pastebin-lite:1.4
    restart: unless-stopped
    ports:
      - "8080:8080"
    environment:
      PASTEBIN_BASE_URL: "https://paste.example.com"
      PASTEBIN_SECRET_KEY: "replace-me-with-32-random-bytes"
      PASTEBIN_MAX_PASTE_BYTES: "524288"
      PASTEBIN_DEFAULT_EXPIRY: "7d"
      PASTEBIN_ALLOW_ANONYMOUS: "true"
    volumes:
      - ./data:/var/lib/pastebin
```

Then:

```
docker compose up -d
```

The service listens on port 8080 inside the container. It speaks plain HTTP and expects to sit behind a reverse proxy that terminates TLS — Caddy, nginx, Traefik, whatever you already run. It reads `X-Forwarded-Proto` and `X-Forwarded-For` when they are present.

Generate the secret key with something like `openssl rand -hex 32`. It signs the deletion tokens and the cookies used for unlocking password-protected pastes. Changing it invalidates every outstanding deletion token and forces re-entry on locked pastes; it does not affect the pastes themselves.

## Environment variables

| Variable | Required | Default | Notes |
| --- | --- | --- | --- |
| `PASTEBIN_BASE_URL` | yes | — | Public origin, no trailing slash. Used to build the links shown after creating a paste. |
| `PASTEBIN_SECRET_KEY` | yes | — | At least 32 characters. The container refuses to start without it. |
| `PASTEBIN_MAX_PASTE_BYTES` | no | `262144` | Rejects larger bodies with HTTP 413. |
| `PASTEBIN_DEFAULT_EXPIRY` | no | `30d` | Applied when a paste is created without an explicit expiry. Accepts `10m`, `4h`, `7d`, or `never`. |
| `PASTEBIN_MAX_EXPIRY` | no | `never` | Caps what users may select. Set this to `30d` if you never want indefinite pastes. |
| `PASTEBIN_ALLOW_ANONYMOUS` | no | `true` | When `false`, creation requires an API token (see below) and the web form is hidden. |
| `PASTEBIN_RATE_LIMIT` | no | `30/hour` | Per source IP, creation only. Reads are not limited. |
| `PASTEBIN_LOG_LEVEL` | no | `info` | One of `debug`, `info`, `warn`, `error`. |

## Storage layout

Everything lives under the single mounted volume, `/var/lib/pastebin`:

```
data/
  pastebin.db          SQLite: paste metadata, expiry timestamps, password hashes
  pastes/
    a3/
      a3f19c2e8b...    paste body, one file per paste
    7e/
      7e04d1aa55...
```

Bodies are sharded into 256 directories by the first byte of the paste ID so that no single directory accumulates hundreds of thousands of entries. Files are stored raw — no compression, no encryption at rest. If you need encryption, put the volume on an encrypted filesystem.

Password-protected pastes store an Argon2id hash of the password in SQLite. The body is not encrypted with the password, so anyone with filesystem access can read a locked paste. The lock is an access control on the web interface, not a confidentiality guarantee against the person running the server.

A sweeper runs every ten minutes, deletes expired rows, and unlinks the corresponding body files. To back up an instance, stop the container and copy the whole `data` directory; copying it live risks capturing a torn SQLite file.

## Web interface

- **Create.** Paste text, optionally pick a language, an expiry, and a password. Language defaults to plain text; there is an "auto-detect" option that guesses from the content, which is right most of the time for anything with distinctive syntax and wrong fairly often for shell versus plain text.
- **View.** Highlighted output with line numbers. Clicking a line number selects it and puts an anchor in the URL (`#L42`); shift-click extends the range (`#L42-L58`).
- **Raw.** Every paste is available at `/<id>/raw` as `text/plain`, which is what you want for `curl` and for pointing a script at a config snippet.
- **Delete.** The creation response includes a one-time deletion URL. It is the only way to delete a paste from the web interface — there are no accounts, so there is no "my pastes" page.

The interface is server-rendered, works without JavaScript except for the copy-to-clipboard button, and has a dark theme that follows the system preference.

## HTTP API

Create a paste by POSTing form-encoded fields to `/api/paste`:

```
curl -X POST https://paste.example.com/api/paste \
  --data-urlencode "content@notes.txt" \
  -d "language=python" \
  -d "expiry=24h"
```

Response:

```json
{
  "id": "a3f19c2e8b",
  "url": "https://paste.example.com/a3f19c2e8b",
  "raw_url": "https://paste.example.com/a3f19c2e8b/raw",
  "delete_url": "https://paste.example.com/a3f19c2e8b/delete?t=9f2c...",
  "expires_at": "2024-05-14T09:22:11Z"
}
```

Fields:

- `content` (required) — the paste body.
- `language` (optional) — a highlighter name such as `python`, `go`, `yaml`. Omit or send `auto` for detection, `text` to disable highlighting.
- `expiry` (optional) — duration string or `never`, subject to `PASTEBIN_MAX_EXPIRY`.
- `password` (optional) — locks the paste. Note that this sends the value in the request body; use it over HTTPS only.

Reading is a plain `GET` on the raw URL. Locked pastes return 401 unless you supply the password as a `password` query parameter or in an `X-Paste-Password` header — prefer the header, since query strings end up in proxy logs.

Deleting is a `GET` or `DELETE` on the deletion URL. The token is single-use.

When `PASTEBIN_ALLOW_ANONYMOUS` is `false`, creation requires `Authorization: Bearer <token>`. Tokens are managed with `docker compose exec pastebin-lite pastebinctl token add --label ci-runner`, which prints the token once and stores only its hash.

## Limits and non-goals

There are no user accounts, no editing after creation, no folders, and no search. Adding any of those would mean adding identity, and the whole point of this project is that it does not have identity. If you need those things, run something bigger.
