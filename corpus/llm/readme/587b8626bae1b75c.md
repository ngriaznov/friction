# exifsort

Sort a pile of photos into `year/month` folders and give them consistent filenames, using the EXIF capture date.

If a file has no usable EXIF timestamp — screenshots, exports from editors that strip metadata, images pulled off a messaging app — exifsort falls back to the file's modification time and marks the file in the output so you can review it.

## Install

```
pip install exifsort
```

Python 3.9 or newer. The only runtime dependency is `piexif`.

## Basic usage

```
exifsort ~/Pictures/dump ~/Pictures/library
```

The first argument is the source folder, the second is the destination. Source files are **copied**, not moved, unless you pass `--move`. The source folder is scanned recursively; the destination structure is created as needed.

Given a photo shot on 14 March 2023, the default result is:

```
~/Pictures/library/2023/03/2023-03-14_142207.jpg
```

Files that are not images, or that exifsort cannot read at all, are left alone and listed at the end of the run.

## Dry run

Always worth doing first on a large folder:

```
exifsort --dry-run ~/Pictures/dump ~/Pictures/library
```

This prints every planned operation — including how each timestamp was determined — and writes nothing:

```
IMG_4471.jpg   exif      -> 2023/03/2023-03-14_142207.jpg
IMG_4472.jpg   exif      -> 2023/03/2023-03-14_142213.jpg
Screenshot.png mtime     -> 2023/03/2023-03-14_190002.png
scan_01.tif    unreadable   (skipped)
```

The `mtime` marker is the one to look at. Modification times are easily clobbered by copying between drives, so a file dated by mtime may well be in the wrong month.

## Rename pattern

The output filename is controlled by `--pattern`, using `strftime` codes plus a few extras:

```
exifsort --pattern '%Y%m%d-%H%M%S' ~/Pictures/dump ~/Pictures/library
```

| Token | Meaning |
| --- | --- |
| `%Y %m %d %H %M %S` | Standard `strftime` fields from the capture date |
| `{orig}` | Original filename without extension |
| `{n}` | Collision counter (see below) |
| `{cam}` | Camera model from EXIF, lowercased, spaces to underscores |

The extension is always preserved from the source file and should not be included in the pattern. For example:

```
--pattern '%Y-%m-%d_{cam}_{orig}'
```

produces `2023-03-14_x-t30_IMG_4471.jpg`.

The folder layout can be changed independently with `--folders`, which takes the same tokens:

```
--folders '%Y/%Y-%m'     # 2023/2023-03/
--folders '%Y'           # flat year folders
--folders ''             # no subfolders at all
```

## Duplicate target names

Two photos taken in the same second — burst mode, or two bodies with synced clocks — will map to the same output name. exifsort never silently overwrites. When a target name is already taken it:

1. Compares the SHA-256 of both files. If they are byte-identical, the incoming file is treated as a duplicate: skipped in copy mode, deleted from the source in `--move` mode (use `--keep-duplicates` to disable this).
2. Otherwise, appends a counter. `2023-03-14_142207.jpg` is followed by `2023-03-14_142207_2.jpg`, then `_3`, and so on. Include `{n}` in your pattern to place the counter yourself.

Counter suffixes are assigned in the order files are processed, which is alphabetical by source path — so runs are reproducible.

## Other flags

| Flag | Effect |
| --- | --- |
| `--move` | Move instead of copy |
| `--mtime-fallback never` | Skip files with no EXIF date rather than using mtime |
| `--ext jpg,heic,dng` | Restrict to specific extensions |
| `--tz +02:00` | Treat naive EXIF timestamps as being in this offset |
| `--log run.csv` | Write a CSV of every operation, for auditing or undo |
| `-v` | Print each file as it is processed |

## Notes on timestamps

EXIF `DateTimeOriginal` is preferred, then `CreateDate`, then `ModifyDate`, then filesystem mtime. EXIF timestamps carry no timezone in most cameras, so exifsort treats them as local wall-clock time unless `--tz` is given. If your camera clock was wrong for a trip, fix it with a bulk EXIF editor before sorting rather than trying to correct it here.
