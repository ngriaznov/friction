# confkeep

Read, edit, and write INI-style config files without destroying the comments, blank lines, or spacing the author put there.

## Why not configparser?

`configparser` parses an INI file into dictionaries. That is the right model if all you want is to read values. It is the wrong model if you want to write the file back out, because everything that isn't a key or a value — comments, blank lines between sections, whether the author wrote `key = value` or `key=value` — is gone by the time parsing finishes. Round-tripping a file through `configparser.read()` and `configparser.write()` reformats the whole thing.

That matters when the file belongs to a human. If your installer flips one flag in someone's `/etc/myapp.conf` and hands back a file with every comment stripped and the sections reordered, you have made their life worse.

confkeep parses into a document model that keeps the original lines. Values you don't touch are written back byte-for-byte. Values you do touch are edited in place, preserving the surrounding whitespace style.

## Install

```
pip install confkeep
```

Requires Python 3.9 or newer. No dependencies.

## Usage

```python
import confkeep

doc = confkeep.load("app.conf")

print(doc["database"]["port"])       # '5432'  — always a string
print(doc["database"].get("host"))   # None if absent

doc["database"]["port"] = "6432"
doc["logging"]["level"] = "debug"    # creates the key if the section exists

confkeep.dump(doc, "app.conf")
```

Given this input:

```ini
[database]
# bumped from 100 after the March incident
pool_size = 200
port      = 5432

[logging]
level = info
```

the output differs by exactly two characters plus the changed word:

```ini
[database]
# bumped from 100 after the March incident
pool_size = 200
port      = 6432

[logging]
level = debug
```

Note that `port` kept its column alignment. confkeep matches the existing padding around `=` when the replacement value is short enough, and falls back to a single space when it isn't.

You can also work with strings directly via `confkeep.loads()` and `confkeep.dumps()`.

## Syntax notes

**Inline comments.** A `#` or `;` preceded by whitespace starts an inline comment and is preserved as part of the line, not the value. `level = info  # noisy` reads as `info`, and the comment survives a rewrite. A `#` with no leading whitespace is treated as part of the value, since URLs with fragments are common in practice.

**Multi-line values.** Continuation lines indented deeper than their key are joined with newlines, the same way `configparser` handles them:

```ini
hosts =
    alpha.internal
    beta.internal
```

reads as `"alpha.internal\nbeta.internal"`. Assigning a value containing newlines writes it back in the same indented form, using the indent already present in the file if there is one.

**Section inheritance.** A section header of the form `[child : parent]` makes `doc["child"]` fall back to `parent` for keys it doesn't define itself. Lookups follow the chain; writes always land on the child. `doc["child"].own_keys()` returns only the locally defined keys if you need to tell them apart.

## Limitations

- Values are always strings. There is no type coercion and no `getboolean()` equivalent — convert at your call site.
- Duplicate keys within a section are an error, not a last-one-wins.
- Comment text cannot be edited through the API, only preserved. If you need to generate commented config from scratch, write it as a template instead.
