# packlite

packlite is a command-line tool that bundles and minifies a project's
JavaScript and CSS into a small number of output files. It's aimed at
simple static sites — a marketing page, a blog, a small app without a
component framework — not at replacing webpack or similar for anything
built around modules, code-splitting, or a framework build pipeline.

## Installation

```
npm install --save-dev packlite
```

## Config file

packlite reads `packlite.config.js` from the project root:

```js
module.exports = {
  entries: {
    app: ["src/js/main.js", "src/js/widgets.js"],
    styles: ["src/css/base.css", "src/css/layout.css", "src/css/theme.css"]
  },
  outDir: "dist",
  sourceMaps: true
};
```

Each key under `entries` becomes one output bundle — the example above
produces `dist/app.js` and `dist/styles.css`, each the concatenation and
minification of the listed files in order. There's no module resolution or
`import` rewriting; packlite just concatenates the files you give it, so
entry lists need to already be in dependency order.

Run a build with:

```
npx packlite build
```

## Watch mode

For local development:

```
npx packlite watch
```

packlite watches every file listed across all entries and rebuilds
whichever bundle changed, without touching the others. Rebuild time on
a change is proportional to the size of the affected bundle only, which
is most of the point of keeping entries small and explicit rather than
letting a dependency graph balloon them.

## Source maps

Set `sourceMaps: true` in the config (or pass `--source-maps` on the
command line) and packlite emits a `.map` file alongside each bundle with
a `//# sourceMappingURL` comment pointing to it, so browser devtools can
map minified output back to the original files.

## Build time, compared

On packlite's own test fixture — about 40 small JS files and 15 CSS files,
roughly 900KB combined source — a full build finishes in a bit under a
second on a modern laptop. That's not a fair apples-to-apples comparison
against webpack or Rollup, since those tools are doing module resolution,
tree-shaking, and often transpilation that packlite simply doesn't attempt
— packlite's speed comes largely from having a much narrower job. If your
project needs any of that, packlite isn't a substitute; it's meant for
sites where "concatenate these files, minify, done" was already going to
be the whole build, and doing it by hand with a heavier bundler configured
down to nothing was more setup than the site warranted.
