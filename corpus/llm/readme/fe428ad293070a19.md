# phodedupe

phodedupe scans one or more directories for duplicate photos, even when the
duplicates aren't byte-identical. It uses perceptual hashing rather than a
checksum, so a photo that's been resized, re-saved at a different JPEG
quality, or had its EXIF orientation flag flipped is still recognized as a
copy of the original.

## Why not just compare checksums?

A checksum (MD5, SHA1, whatever) tells you two files are byte-for-byte
identical. That's fine for catching an accidental double-copy, but it's
useless the moment either file has been touched in any way — re-exported
from Lightroom, downsized for a web upload, or re-compressed by a messaging
app. All of those operations change the bytes without changing what a human
would call "the same photo."

Perceptual hashing works on the image content instead. phodedupe reduces
each photo to a small fingerprint derived from its overall structure and
luminance pattern, and two photos that look alike produce fingerprints that
are close in Hamming distance even if the underlying files are completely
different. That's what lets it catch a thumbnail next to the original, or
a photo saved twice at different quality settings.

## Installation

```
pip install phodedupe
```

Requires Python 3.7+. Pillow is pulled in automatically for image decoding.

## Usage

Scan a folder and write a report of duplicate groups:

```
phodedupe scan ~/Pictures --report duplicates.json
```

Review the report before deleting anything — phodedupe never deletes files
on its own during a scan. Once you're happy with what it found:

```
phodedupe apply duplicates.json --keep largest
```

`--keep largest` keeps the biggest file in each group (by resolution, then
file size) and removes the rest. Other strategies are `oldest`, `newest`,
and `first` (whichever file phodedupe encountered first during the scan).

### Dry run

Add `--dry-run` to `apply` to see exactly what would be deleted without
touching anything:

```
phodedupe apply duplicates.json --keep largest --dry-run
```

## Configuration

- `--hash {ahash,phash,dhash}` — choose the hashing algorithm. `phash`
  (the default) is the most robust against resizing and recompression;
  `ahash` is faster but more prone to false positives on nearly-flat
  images; `dhash` is a good middle ground and holds up well against
  mirroring.
- `--threshold N` — maximum Hamming distance between two hashes for them
  to be considered duplicates. Default is 8. Lower values require a closer
  match and reduce false positives at the risk of missing heavily edited
  copies; higher values catch more but increase false positives.
- `--recursive` / `--no-recursive` — whether to descend into
  subdirectories. Recursive by default.
