# feedwell

feedwell is a self-hosted RSS and Atom feed reader with a lightweight web
UI. It's meant to be run on your own server behind whatever WSGI server
you're already using — there's no bundled production server, no Docker
image, no external service dependency beyond a database.

## Features

- **Folder organization.** Feeds are grouped into folders you define; a
  feed can belong to exactly one folder, and folders can be reordered from
  the UI.
- **Read/unread tracking.** Articles are marked read individually or in
  bulk per-feed or per-folder. Unread counts show up next to each feed and
  folder in the sidebar.
- **Full-text search.** Every fetched article's content is cached locally
  and indexed, so search covers article bodies, not just titles.
- **OPML import/export.** Bring in an existing subscription list from
  another reader, or export feedwell's list to move elsewhere.

## Installation

feedwell is distributed as source; there's no package on PyPI yet.

```
git clone https://github.com/feedwell/feedwell.git
cd feedwell
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

This installs feedwell's Python dependencies (Flask, SQLAlchemy, feedparser,
and a handful of smaller libraries) into the virtualenv. feedwell itself is
a WSGI application — `feedwell.wsgi:app` — so it plugs into gunicorn,
uWSGI, or mod_wsgi the same way any other Flask app would.

A minimal gunicorn invocation for testing:

```
gunicorn feedwell.wsgi:app -b 127.0.0.1:8000
```

For anything beyond local testing, put nginx or Apache in front of it and
proxy to the WSGI server, same as you would for any other Python web app.

## First-run setup

On first launch, visiting the site with no admin account configured drops
you into a setup wizard that creates the initial admin user:

```
Username: ________
Password: ________
Confirm password: ________
```

Once that account exists, the setup route is disabled — feedwell doesn't
support open registration, so any additional accounts have to be created
by an existing admin from the Users page in settings.

## Database backend

feedwell uses SQLite by default, which is enough for a single-user or
small-household install and needs no separate configuration — the database
file is created automatically at `instance/feedwell.db` on first run.

For larger installs, or if you'd rather run feedwell alongside other
services against a shared PostgreSQL instance, set `DATABASE_URL` before
starting the app:

```
export DATABASE_URL=postgresql://feedwell:password@localhost/feedwell
```

feedwell will create its schema on first connection if it doesn't already
exist. Migrating an existing SQLite database to PostgreSQL isn't automated
— export your subscriptions to OPML first, switch `DATABASE_URL`, and
re-import, since article history isn't preserved across that kind of
migration.

## Scheduling feed polling

feedwell doesn't poll feeds on its own in the background — the web process
only serves requests. Fetching new articles is a separate management
command meant to be run periodically:

```
python -m feedwell.cli fetch
```

Add it to cron for whatever interval makes sense for how often you check
your feeds. Every 15 minutes is a reasonable default for most people and
plays nicely with servers that publish `Last-Modified` and `ETag` headers
(feedwell respects both, so a `fetch` run against an unchanged feed
doesn't re-download the whole thing):

```cron
*/15 * * * * cd /path/to/feedwell && venv/bin/python -m feedwell.cli fetch >> /var/log/feedwell-fetch.log 2>&1
```

If you're running feedwell for a household with a lot of active feeds,
you can drop the interval further, but be considerate of the sites you're
polling — feedwell doesn't currently do per-feed rate limiting beyond
respecting `ETag`/`Last-Modified`, so hammering a slow feed every minute
is on you.

## OPML

Import a subscription list from Settings → Import, or from the command
line:

```
python -m feedwell.cli import-opml subscriptions.xml
```

Feeds are added to a folder matching the OPML outline's category, creating
folders that don't already exist. Export works the same way in reverse,
either from Settings → Export or:

```
python -m feedwell.cli export-opml > subscriptions.xml
```

## Configuration

Most runtime settings — session secret key, cache size for full-text
search, whether to fetch full article content or just the feed's summary
— live in `instance/config.py`, which is created with sane defaults on
first run and not overwritten by upgrades.
