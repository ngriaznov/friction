# addrvalid

Validates and normalizes US postal addresses according to USPS Publication 28 formatting rules. Works entirely offline against a bundled rules table — no network calls, no API key, no rate limits.

## Installation

Add to your Gemfile:

```ruby
gem 'addrvalid', '~> 2.1'
```

Then `bundle install`.

## Usage

Pass a hash of address components. You get back a result object with the normalized address and a list of warnings describing what was changed.

```ruby
require 'addrvalid'

result = Addrvalid.validate(
  street1: '1234 north maple avenue',
  street2: 'apartment 3b',
  city:    'Springfield',
  state:   'Illinois',
  zip:     '62704'
)

result.valid?   # => true
result.address  # => {
                #      street1: "1234 N MAPLE AVE",
                #      street2: "APT 3B",
                #      city:    "SPRINGFIELD",
                #      state:   "IL",
                #      zip:     "62704"
                #    }

result.warnings.each { |w| puts "#{w.field}: #{w.message}" }
# street1: suffix "avenue" standardized to "AVE"
# street1: directional "north" abbreviated to "N"
# street2: unit designator "apartment" standardized to "APT"
# state: full state name converted to two-letter abbreviation
```

Warnings are informational, not errors. A result can be valid and still carry several of them — that is the normal case for user-entered input.

Hard failures set `valid?` to false and populate `result.errors`:

```ruby
result = Addrvalid.validate(street1: '1234 Maple Ave', city: 'Springfield', state: 'ZZ', zip: '627')
result.valid?  # => false
result.errors  # => ["state: \"ZZ\" is not a recognized state or territory code",
               #     "zip: expected 5 or 9 digits, got 3"]
```

## What it checks

- **Street suffixes** — the full Publication 28 Appendix C1 table, so `BOULEVARD`, `BLVD.`, and `boulvard` all normalize to `BLVD`.
- **Directionals** — leading and trailing, spelled-out and abbreviated, including compounds (`NORTHEAST` → `NE`).
- **Secondary unit designators** — `APT`, `STE`, `FL`, `RM`, `UNIT`, and the rest of Appendix C2, including which ones require a following number.
- **State and territory codes** — all 50 states, DC, and the USPS-recognized territories and military codes (`AA`, `AE`, `AP`).
- **ZIP format** — 5-digit and ZIP+4, with hyphen normalization. Checksum-free; format only.
- **Case and punctuation** — output is uppercased with periods and commas stripped, per USPS preference.

## What it does not do

**It does not verify that an address exists.** There is no live USPS API lookup, no CASS certification, no delivery-point validation. `1299 N MAPLE AVE` will pass cleanly even if the street only runs to 800.

It also does not check that a ZIP code corresponds to the given city and state, and it does not append the +4 add-on. If you need any of that, you need an address verification service; this gem is for cleaning up input before you send it to one, or for the many cases where consistent formatting is all you actually wanted.
