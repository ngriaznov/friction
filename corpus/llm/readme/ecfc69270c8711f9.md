# csvtype

csvtype is a Rust crate that reads a CSV file, samples its rows to infer a
type for each column, and hands you back a typed record iterator instead
of an iterator of raw string fields. No more `row[3].parse::<f64>()`
scattered through your code — csvtype does the inference and the parsing
for you.

## Installation

```toml
[dependencies]
csvtype = "0.4"
```

## Example

```rust
use csvtype::{Reader, Value};

fn main() -> Result<(), csvtype::Error> {
    let mut reader = Reader::from_path("sales.csv")?;

    // sample the first N rows (configurable) and infer a schema
    let schema = reader.infer_schema()?;
    println!("{:#?}", schema);

    for record in reader.typed_records(&schema) {
        let record = record?;
        match record.get("amount") {
            Some(Value::Float(f)) => println!("amount: {:.2}", f),
            _ => {}
        }
    }

    Ok(())
}
```

`infer_schema` returns a `Schema` mapping each column name to one of
`Integer`, `Float`, `Date`, `Boolean`, or `String`. `typed_records` then
re-reads the file (or continues from wherever the reader is positioned)
and parses each row according to that schema, yielding a `Record` whose
fields you can look up by column name or index.

A column that fails to parse against its inferred type for a given row
doesn't panic — it falls back to `Value::String` for that field, so a
single malformed row degrades gracefully instead of aborting the whole
read.

## How sampling affects accuracy

Schema inference works by sampling rows from the start of the file and
checking, for each column, whether every sampled value parses as an
integer, then a float, then a date, then a boolean, falling back to string
if none of those match consistently. By default csvtype samples the first
1,000 rows.

The obvious failure mode: a column that's genuinely numeric for its first
1,000 rows but has a stray non-numeric value (a footnote marker, an "N/A")
somewhere later in a ten-million-row file will still be inferred as
numeric, and that later row will fall back to a string value at read time
rather than breaking inference. If your data has that shape, either raise
the sample size with `Reader::sample_size(n)` or sample the whole file
with `Reader::infer_schema_full()`, which is slower but exhaustive.

Smaller sample sizes are faster on large files but more likely to miss a
type that only shows itself later — a `Date` column where every sampled
row happens to look like a plain integer (e.g. `20230401`) will be
inferred as `Integer` unless the sample happens to catch a
differently-formatted date further down.

## Overriding a column's type

If inference gets a column wrong, or you simply know better than the
sampler, override it before building the typed iterator:

```rust
let mut schema = reader.infer_schema()?;
schema.set("order_date", csvtype::Type::Date);
```

`Schema::set` takes the column name and one of the `Type` variants; it
replaces whatever csvtype inferred, and every subsequent
`typed_records` call uses the override.
