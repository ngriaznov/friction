# multitail-go

multitail-go tails several log files at once in a single terminal,
prefixing each line with a color-coded label so you can tell at a glance
which file a given line came from. Handy for watching an app server and
its database logs side by side without juggling multiple terminal panes.

## Installation

```
go install github.com/multitail-go/multitail-go@latest
```

This puts a `multitail-go` binary in `$GOBIN` (or `$GOPATH/bin` if
`GOBIN` isn't set). Requires Go 1.19+.

## Basic usage

```
multitail-go /var/log/app/server.log /var/log/postgresql/postgresql.log
```

Each line printed is prefixed with the basename of its source file,
colored consistently per file for the life of the process:

```
[server.log]      2024-03-01 09:14:02 handling request GET /orders/42
[postgresql.log]  2024-03-01 09:14:02 LOG:  duration: 3.221 ms  statement: SELECT * FROM orders WHERE id = 42
[server.log]      2024-03-01 09:14:02 request completed in 4ms
```

Files are opened in the order given on the command line and followed the
same way `tail -f` follows a file — new lines appended to any of them show
up interleaved by the time they arrive, not grouped by file.

## Glob patterns and rotating logs

Instead of listing exact paths, you can pass a glob:

```
multitail-go '/var/log/app/*.log'
```

Quote the glob so your shell doesn't expand it — multitail-go does its own
expansion and, more importantly, keeps re-evaluating the pattern
periodically. That's what lets it handle log rotation: when a matched file
is rotated out (renamed, truncated, or replaced by logrotate), multitail-go
detects that its inode changed, stops following the old file descriptor,
and picks up the new file under the same name automatically. Newly created
files that match the glob but didn't exist when multitail-go started are
also picked up on the next rescan.

The rescan interval defaults to 5 seconds; adjust it with
`--rescan-interval`:

```
multitail-go --rescan-interval 2s '/var/log/app/*.log'
```

## Filtering with a regex

```
multitail-go --filter 'ERROR|WARN' /var/log/app/*.log
```

`--filter` takes a Go-flavored regular expression and only prints lines
that match it, across all watched files. This is a display filter, not a
tail-from-match — multitail-go still follows every file from the current
end and simply drops non-matching lines before printing, so it's cheap to
toggle on a running session by restarting with a different pattern.

## How colors are assigned

Colors are assigned to sources in the order files are first seen — the
first file (whether given explicitly or matched by a glob at startup)
gets the first color in multitail-go's built-in 8-color palette, the
second file gets the second color, and so on, wrapping around if you're
watching more than 8 files. A file's color is fixed for the life of the
process once assigned, including across log rotation — the new file that
replaces a rotated-out one under the same glob match keeps the same color
as the file it replaced, since multitail-go keys the color assignment on
the matched path pattern rather than the file's inode.

If your terminal doesn't support color, or you're piping output
somewhere, pass `--no-color` to fall back to plain `[filename]` prefixes.
