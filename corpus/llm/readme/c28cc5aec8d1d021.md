# vim-dslsyntax

Syntax highlighting for **Marlin**, the configuration DSL used across Brindle Systems' deployment tooling. Covers keywords, `${...}` string interpolation, both comment styles, durations, and heredoc blocks.

## Installation

**vim-plug** — add to your `.vimrc` and run `:PlugInstall`:

```vim
Plug 'brindle-systems/vim-dslsyntax'
```

**packer.nvim**:

```lua
use 'brindle-systems/vim-dslsyntax'
```

No configuration is required. The plugin ships `ftdetect`, `syntax`, and `ftplugin` files and nothing else — it does not remap keys or touch your colorscheme.

## Filetype detection

Files matching `*.mrl` or `*.marlin` are set to filetype `marlin`. The generated files under `.brindle/rendered/` are also detected, since they keep the `.mrl` extension after templating.

To force the filetype on a file with an unusual name:

```vim
:set filetype=marlin
```

Or add a modeline: `# vim: ft=marlin`.

## Highlight groups

Each group is linked to a standard group by default. Override any of them in your colorscheme or after `:colorscheme` in your vimrc.

| Group | Default link | Matches |
| --- | --- | --- |
| `marlinKeyword` | `Keyword` | `service`, `stage`, `import`, `when`, `unless`, `export` |
| `marlinBuiltin` | `Function` | `env()`, `secret()`, `file()`, `merge()` |
| `marlinString` | `String` | single- and double-quoted strings |
| `marlinInterp` | `Special` | `${...}` inside double-quoted strings |
| `marlinInterpVar` | `Identifier` | the identifier inside an interpolation |
| `marlinComment` | `Comment` | `#` line comments and `/* */` blocks |
| `marlinDuration` | `Number` | `30s`, `15m`, `2h` |
| `marlinHeredoc` | `String` | `<<<SCRIPT ... SCRIPT` bodies |

Example override:

```vim
highlight link marlinInterpVar Constant
```

## Reporting a highlighting bug

If a token renders with the wrong group, open an issue with:

1. A **minimal `.mrl` snippet** that reproduces it — five lines is better than a whole file.
2. The output of `:echo synIDattr(synID(line('.'), col('.'), 1), 'name')` with the cursor on the offending token. This tells us which rule actually matched.
3. Your Vim or Neovim version.

Interpolation nested inside heredocs is the usual culprit; check the open issues before filing.
