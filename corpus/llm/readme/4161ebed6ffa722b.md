# packlite

A small bundler for static sites. It concatenates and minifies your JavaScript and CSS into a handful of output files, writes source maps, and stops there.

packlite is for the kind of site that has a few script tags, a stylesheet or two, and no framework. If you are building a single-page app with a component compiler and code splitting, use a real bundler — packlite will not serve you. If you have been hand-concatenating files with `cat` or shipping eleven separate `<script>` tags because setting up a build pipeline felt disproportionate, this is aimed at you.

## Install

```
npm install --save-dev packlite
```

Or run it without installing:

```
npx packlite build
```

## Configure

packlite looks for `packlite.config.json` in the project root.

```json
{
  "outDir": "dist",
  "sourcemaps": true,
  "entries": {
    "app": ["src/js/util.js", "src/js/nav.js", "src/js/main.js"],
    "styles": ["src/css/reset.css", "src/css/layout.css", "src/css/theme.css"]
  }
}
```

Each key under `entries` becomes one output file, named after the key with the extension inferred from its inputs. The config above produces `dist/app.js`, `dist/styles.css`, and their `.map` files. Files are concatenated in the order listed — there is no dependency graph and no module resolution, which is the whole point. You control the order.

Options:

| Key | Default | Meaning |
| --- | --- | --- |
| `outDir` | `"dist"` | Where output files are written |
| `entries` | *(required)* | Map of output name to input file list |
| `sourcemaps` | `true` | Emit `.map` files and a sourceMappingURL comment |
| `minify` | `true` | Set false to concatenate without minifying |
| `banner` | `null` | String prepended to each output file |

## Build

```
packlite build
```

## Watch mode

```
packlite watch
```

Watches every file listed in `entries` and rebuilds the affected output on change. Rebuilds are incremental per entry: touching a CSS file does not re-minify your JavaScript. Add `--serve` to also run a static file server on port 3000 with live reload injected into HTML responses.

## Source maps

Source maps are on by default and map back to your original files, so a stack trace in the browser console points at `src/js/nav.js:42` rather than a column offset in the bundle. Turn them off with `"sourcemaps": false` if you would rather not ship the mapping files.

## Build times

Rough numbers from a site with 14 JS files (~180KB raw) and 6 CSS files (~90KB raw), on a 2021 laptop:

| Tool | Cold build | Incremental |
| --- | --- | --- |
| packlite | 0.4s | 0.09s |
| webpack (equivalent config) | 3.1s | 0.6s |
| rollup + postcss | 1.9s | 0.4s |

This is not a fair fight and packlite is not faster because it is cleverer. It is faster because it does not parse a module graph, resolve imports, tree-shake, or transpile. On a project that needs those things, the comparison is meaningless. On a project that doesn't, you are paying three seconds for them anyway.
