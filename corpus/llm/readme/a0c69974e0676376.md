# wavtag

A small, dependency-free C library for reading and writing metadata chunks in WAV audio files — artist, title, comment, and the rest of the standard `LIST/INFO` fields — without touching the underlying PCM sample data.

Most WAV tooling either forces you to re-encode the audio to change a tag, or pulls in a heavyweight multimedia framework just to read a title field. wavtag parses only the RIFF chunk structure, finds or creates the `LIST` chunk containing an `INFO` sub-chunk, and rewrites just that region of the file. The sample data chunk is never decoded, re-encoded, or moved unless a chunk resize forces a shift in file offsets, which the library handles automatically and transparently.

## Building

wavtag has no external dependencies beyond a C99 compiler and `make`.

```
git clone https://example.com/wavtag.git
cd wavtag
make
sudo make install
```

This builds `libwavtag.a` (static) and `libwavtag.so` (shared) and installs headers to `/usr/local/include/wavtag.h`. Run `make check` to build and run the bundled test suite against a handful of sample WAV files in `tests/fixtures/`.

## API

The public API is intentionally small and lives entirely in `wavtag.h`:

```c
wavtag_file *wavtag_open(const char *path);
int wavtag_read_tag(wavtag_file *f, const char *key, char *out, size_t out_len);
int wavtag_write_tag(wavtag_file *f, const char *key, const char *value);
int wavtag_save(wavtag_file *f);
void wavtag_close(wavtag_file *f);
```

`wavtag_open` parses the RIFF header and locates the existing `LIST/INFO` chunk, if any, without loading the audio data into memory. `wavtag_read_tag` and `wavtag_write_tag` take standard four-character INFO codes (`"IART"` for artist, `"INAM"` for title, `"ICMT"` for comment, and so on — see `wavtag.h` for the full set of recognized codes). Writes are staged in memory until `wavtag_save` is called, which rewrites the chunk in place if the new tag data fits in the existing space, or shifts the sample data chunk forward if it doesn't.

```c
wavtag_file *f = wavtag_open("track.wav");
char artist[256];
wavtag_read_tag(f, "IART", artist, sizeof(artist));
wavtag_write_tag(f, "ICMT", "Remastered 2026");
wavtag_save(f);
wavtag_close(f);
```

## Byte order

RIFF/WAV is a little-endian format by convention, but wavtag runs its own explicit byte-swapping on all multi-byte chunk-size and offset fields rather than relying on struct layout or the host's native endianness. This means the library behaves identically on little-endian and big-endian hosts, including big-endian embedded targets, at a small runtime cost that's negligible next to file I/O. If you're embedding wavtag in a cross-compiled toolchain, no additional configuration is needed — do not disable the byte-swap paths as a "portability" optimization, since doing so will silently corrupt chunk sizes on big-endian systems.
