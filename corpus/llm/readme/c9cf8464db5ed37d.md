# tasq

A command-line todo manager that keeps your tasks as plain lines of text in a file, so your task list stays readable, greppable, and diffable if you keep it in version control.

## Why plain text

No database, no binary format, no lock file to corrupt. Each task is one line. You can open the file in any editor, `grep` it, or check it into a dotfiles repo and get a meaningful `git diff` when a task changes.

## Installation

```
cargo install tasq
```

## Basic usage

Add a task:

```
tasq add "Renew domain registration"
```

Mark it done:

```
tasq done 3
```

List open tasks:

```
tasq list
```

`list` shows only unfinished tasks by default. Pass `--all` to include completed ones.

## Tags

Prefix any word in a task with `@` to tag it:

```
tasq add "Renew domain registration @admin @urgent"
```

A task can carry any number of tags. Filter the list by tag:

```
tasq list --tag admin
```

## Due dates

Add a due date with `due:` followed by an ISO date:

```
tasq add "Renew domain registration due:2026-08-15"
```

Filter tasks due on or before a given date:

```
tasq list --due-before 2026-08-01
```

Tags and due dates can be combined in one task and in one filter, e.g. `tasq list --tag admin --due-before 2026-08-01`.

## Where the file lives

By default, tasq reads and writes `~/.tasq/tasks.txt`. To use a different location — a per-project task file, for instance — set the `TASQ_FILE` environment variable:

```
export TASQ_FILE=./project-tasks.txt
```

tasq creates the file and its parent directory on first use if they don't already exist.

## File format

Each line is one task:

```
[ ] Renew domain registration @admin @urgent due:2026-08-15
[x] Order replacement router @admin
```

`[ ]` marks an open task, `[x]` a completed one. Tags and due dates are just tokens within the line, which is why the file stays perfectly readable without tasq at all — it's a plain checklist that also happens to be machine-parseable.
