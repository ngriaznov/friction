# confkeep

confkeep is a small Python library for reading and writing INI-style
configuration files without losing the formatting the user put there.
Comments, blank lines, and the ordering of sections and keys all survive a
round trip through the library — edit one value programmatically, write the
file back out, and the diff is exactly the change you made.

## Why not configparser?

The standard library's `configparser` is fine for reading configuration,
but it isn't designed to write a file back out in a way that respects what
was already there. Load a file, change a single value, and save it, and
you'll typically get a file with reordered sections, stripped comments, and
normalized whitespace. That's a problem if the config file is meant to be
edited by hand and also touched by scripts — the two workflows fight each
other, and every automated edit produces a noisy diff that obscures the
actual change.

confkeep parses the file into a structure that keeps track of comments,
blank lines, and formatting alongside the actual key/value data, so a
programmatic edit only changes what you told it to change.

## Installation

```
pip install confkeep
```

No dependencies outside the standard library.

## Example

```python
from confkeep import ConfigFile

cfg = ConfigFile.load("app.ini")

# read a value like a dict
print(cfg["database"]["host"])

# modify one value
cfg["database"]["port"] = "5433"

# write it back out — comments, blank lines, and section order
# are all preserved exactly as they were, aside from the one line
# that changed
cfg.save("app.ini")
```

Given an input file like:

```ini
; database connection settings
[database]
host = localhost
port = 5432   ; default postgres port

[logging]
level = info
```

after the edit above, the output is:

```ini
; database connection settings
[database]
host = localhost
port = 5433   ; default postgres port

[logging]
level = info
```

Note that the trailing comment on the `port` line survives even though the
value changed — confkeep treats the comment as attached to the line, not
the value.

## Supported syntax

confkeep handles a few real-world quirks that plain INI parsing usually
gets wrong:

- **Inline comments.** `key = value ; comment` and `key = value # comment`
  are both recognized and preserved on write.
- **Multi-line values.** A value can continue on following lines as long as
  they're indented further than the key, matching the convention most INI
  writers already use:

  ```ini
  description = This is a long value
      that continues on the next line
  ```

- **Section inheritance.** A section can declare `[child : parent]` to
  inherit any keys it doesn't define itself from `parent`. Lookups on
  `child` fall back to `parent` automatically; writes always go to the
  section you actually modified.

## Caveats

confkeep is intentionally narrow — it does not attempt interpolation
(`%(other_key)s` style substitution) or type coercion. Everything comes
back as a string; convert it yourself. If you need configparser's
interpolation features, confkeep isn't a drop-in replacement, but the two
libraries can read the same files.
