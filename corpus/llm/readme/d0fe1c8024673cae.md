# orbitsim

Two-body orbit propagation for small satellites in low Earth orbit, with optional J2 perturbation. Built for quick mission-planning sketches, coverage estimates, and teaching — not for operational orbit determination.

## Installation

```
pip install orbitsim
```

Requires Python 3.9+ and numpy (installed automatically). Plotting examples below also use matplotlib, which is not a dependency:

```
pip install orbitsim[plots]
```

## Quick start

Propagate a satellite over one orbit and plot its ground track:

```python
import numpy as np
import matplotlib.pyplot as plt
from orbitsim import Orbit, propagate, to_geodetic

# ISS-like state vector, ECI, km and km/s
r0 = np.array([-4550.4, 2220.1, 4527.8])
v0 = np.array([-3.452, -6.201, 0.591])

orbit = Orbit.from_state(r0, v0, epoch="2026-03-14T00:00:00Z")
print(orbit.period)          # 5555.8 seconds
print(orbit.elements.inc)    # 51.64 degrees

# One full orbit, 30-second steps, with J2 on
track = propagate(orbit, duration=orbit.period, step=30.0, j2=True)

lat, lon, alt = to_geodetic(track)   # ECI -> ECEF -> geodetic

plt.figure(figsize=(10, 5))
plt.scatter(lon, lat, s=2)
plt.xlim(-180, 180); plt.ylim(-90, 90)
plt.xlabel("longitude (deg)"); plt.ylabel("latitude (deg)")
plt.title("Ground track, one orbit")
plt.show()
```

`propagate` returns a `Trajectory` — an object holding `t`, `r`, and `v` arrays plus the epoch — so you can slice it, resample it, or hand it straight to `to_geodetic`.

You can also start from classical elements:

```python
orbit = Orbit.from_elements(
    a=6778.0, e=0.0004, inc=51.64,
    raan=247.3, argp=130.5, nu=0.0,
    epoch="2026-03-14T00:00:00Z",
)
```

## Coordinate frames

Three frames are supported, with conversions between them in `orbitsim.frames`:

- **ECI (J2000)** — inertial, the frame propagation happens in. All state vectors are ECI unless stated otherwise.
- **ECEF (WGS84)** — Earth-fixed. The ECI→ECEF rotation uses Greenwich mean sidereal time only; it does **not** model polar motion or nutation, which is worth a few tens of metres.
- **Geodetic (WGS84)** — latitude, longitude, altitude, via `to_geodetic`. Uses the standard iterative latitude solution.

Topocentric look angles (azimuth, elevation, range from a ground station) are available through `orbitsim.groundstation.look_angles`.

## Accuracy and what this propagator is not

The core is a closed-form Keplerian solver with an optional first-order secular J2 correction applied to RAAN, argument of perigee, and mean anomaly. That means:

- Position error against a full numerical integrator with a high-order gravity model is on the order of a few kilometres after one orbit, and grows roughly linearly. Over a day, expect tens of kilometres. Over a week, don't.
- **Drag is not modelled at all.** Below about 450 km this dominates everything else, and orbitsim will happily tell you a 300 km orbit is stable indefinitely. It is not.
- Solar radiation pressure, third-body (lunar/solar) gravity, and tesseral harmonics are absent.
- J2 is applied as a secular rate, not integrated. Short-period oscillations in the elements — the wobble you'd see in a real orbit within a single revolution — are not reproduced.

Where it does well: orbital period, ground-track repeat patterns, nodal regression rate, coverage and access windows over hours rather than days, and any case where you want a fast answer and know the error budget. Propagating a thousand satellites for a day takes under a second.

If you need better, use a numerical propagator with a real force model. orbitsim is deliberately the small tool you reach for first.
