# backupctl

Nightly backups for a single LAMP box: a MySQL dump, an rsync of the web root, and rotation of anything older than the retention window. Four bash scripts, no daemon, no agent, no dependencies beyond `mysqldump`, `rsync`, `tar`, and `gzip`.

This exists because the alternatives were either a full backup product or a one-liner in someone's crontab that nobody could restore from. These scripts are meant to be read in about ten minutes.

## Install

```sh
git clone https://example.org/backupctl.git /opt/backupctl
cp /opt/backupctl/backupctl.env.example /etc/backupctl.env
chmod 600 /etc/backupctl.env
```

Edit `/etc/backupctl.env`. It is sourced by every script, so keep it valid shell.

## Configuration

| Variable | Required | Meaning |
| --- | --- | --- |
| `BK_DB_USER` | yes | MySQL user with `SELECT`, `LOCK TABLES`, `SHOW VIEW` |
| `BK_DB_PASS` | yes | Password for that user |
| `BK_DB_NAMES` | yes | Space-separated database names |
| `BK_WEBROOT` | yes | Directory to mirror, e.g. `/var/www/html` |
| `BK_DEST` | no | Backup root, defaults to `/var/backups/backupctl` |
| `BK_RETAIN_DAYS` | no | Days of archives to keep, defaults to `14` |

The scripts write the password to a temporary `--defaults-extra-file` with mode 600 rather than passing it on the command line, so it does not show up in `ps`.

## Layout on disk

```
/var/backups/backupctl/
  db/2026-03-14/site_main.sql.gz
  web/current/          <- rsync target, hardlinked between runs
  archive/web-2026-03-14.tar.gz
```

`web/current` is a live mirror updated with `rsync --delete --link-dest`, so each nightly archive costs only the changed files.

## Running it

```sh
/opt/backupctl/backup-nightly.sh
```

Install the cron entry as root:

```
17 2 * * * /opt/backupctl/backup-nightly.sh >> /var/log/backupctl.log 2>&1
```

Pick an odd minute. If you and every tutorial on the internet run at 02:00, you will fight for I/O with logrotate.

Rotation runs at the end of `backup-nightly.sh` and deletes anything in `db/` and `archive/` older than `BK_RETAIN_DAYS`. It never touches `web/current`.

## Restoring

```sh
/opt/backupctl/restore.sh 2026-03-14
```

This unpacks that date's web archive into a staging directory, prints the diff summary against the live web root, and waits for you to type `yes` before swapping. The database is imported only after the file restore succeeds, so you do not end up with new schema against old code.

To restore just one database:

```sh
/opt/backupctl/restore.sh 2026-03-14 --db site_main --skip-web
```

## Caveats

- Single host only. Copy `BK_DEST` offsite yourself; `rclone` in a second cron line works fine.
- `mysqldump` takes table locks on MyISAM. If you are still on MyISAM, expect a write pause.
- Tested on Debian 12 and Rocky 9 with bash 5. It will probably work elsewhere, but nobody has checked.
