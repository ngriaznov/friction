# dotsync

Sync your dotfiles across machines with a bare git repository checked out straight into `$HOME`. No symlink farm, no `stow`, no directory of copies that drifts out of date. Your actual `~/.vimrc` *is* the tracked file.

`dotsync` is about 200 lines of POSIX shell. It doesn't do anything git can't do on its own — it just remembers the awkward incantations for you.

## Why bare?

The usual approach keeps dotfiles in `~/dotfiles/` and symlinks them into place. That works, but it means every new file needs a link, broken links are silent, and some programs get confused when their config is a symlink into a directory they don't expect.

A bare repo takes a different route. The git metadata lives in `~/.dotsync.git`, and the *work tree* is `$HOME` itself. Files sit exactly where the program expects them. There's nothing between the file and the tool reading it.

The catch is that `$HOME` contains thousands of files you emphatically do not want tracked, which is why every command has to be pointed at the right git dir explicitly. That's the part `dotsync` wraps.

## Install

```sh
curl -fsSL https://example.invalid/dotsync/install.sh | sh
```

Or copy `dotsync` anywhere on your `PATH` and `chmod +x` it. The only dependency is git.

## One-time setup

On the machine that has the dotfiles you want to keep:

```sh
dotsync init git@github.com:you/dotfiles.git
```

This does three things:

1. Creates the bare repo at `~/.dotsync.git`.
2. Sets `status.showUntrackedFiles no` on it, so `dotsync status` doesn't dump your entire home directory at you. This is not optional — without it the tool is unusable.
3. Adds `remote origin` pointing at the URL you gave.

It does **not** commit anything. Nothing is tracked until you say so.

## The wrapper alias

Everything runs through one alias:

```sh
alias dg='git --git-dir=$HOME/.dotsync.git --work-tree=$HOME'
```

`dotsync init` appends this to your shell rc file (`~/.bashrc` or `~/.zshrc`, whichever it finds). Open a new shell, or `source` the file, before continuing.

`dg` is a full git. Anything git does, it does — `dg log`, `dg diff`, `dg stash`, all of it, scoped to your dotfiles.

## Typical workflow

Adding a new config file:

```sh
dg add ~/.config/nvim/init.lua
dg commit -m "nvim: split keymaps into their own module"
dg push
```

Because untracked files are hidden, `dg status` after this shows only files you've already added that have changed. That's the whole point — it turns `$HOME` into a manageable repo.

A shortcut for the common case:

```sh
dotsync save "nvim keymaps"
```

which is `dg add -u`, commit with that message, and push. It only stages files already tracked, so it will never sweep up something by accident.

## Second machine

```sh
dotsync clone git@github.com:you/dotfiles.git
```

This clones bare into `~/.dotsync.git` and then attempts a checkout into `$HOME`. If any tracked file already exists locally, git refuses the checkout rather than overwriting. `dotsync` catches that, moves the conflicting files to `~/.dotsync-backup/`, prints the list, and retries.

Review that directory before deleting it.

From then on:

```sh
dotsync pull
```

is `dg pull --rebase`. If you've made local edits, rebase will stop and tell you; resolve as you would in any repo, then `dg rebase --continue`.

## Secrets

Nothing here encrypts anything. Don't track `~/.ssh/id_ed25519`, `~/.aws/credentials`, or shell history. `dotsync init` writes a starter `~/.gitignore` covering the obvious ones, but the responsibility is yours.
