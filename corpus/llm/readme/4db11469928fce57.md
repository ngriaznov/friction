# piswitch

A small home automation hub for the Raspberry Pi. piswitch drives a bank of relay modules over GPIO and puts a minimal HTTP API in front of them, so you can toggle lights, fans, or a coffee maker from a script, a phone shortcut, or whatever dashboard you already run.

It does one thing. There's no scheduler, no scene engine, no cloud account. If you want those, put them in front of piswitch and let it be the part that flips the pins.

## Hardware

You need a Pi (tested on 3B+, 4, and Zero 2 W), a relay module board, and a way to power both. Opto-isolated relay boards are strongly recommended — the cheap non-isolated ones couple switching noise back into the Pi's 3.3V rail and cause random reboots under load.

Wire the relay board's control side to the Pi like this:

| Relay board pin | Pi pin (physical) | Notes |
|---|---|---|
| VCC | 5V (pin 2) | Board logic supply |
| GND | GND (pin 6) | Must be common with the Pi |
| IN1 | GPIO17 (pin 11) | |
| IN2 | GPIO27 (pin 13) | |
| IN3 | GPIO22 (pin 15) | |
| IN4 | GPIO23 (pin 16) | |

If your relay board has a `JD-VCC` jumper, leave it in place only if you're powering the coils from the Pi's 5V rail. A four-relay board can pull 300 mA with everything energized, which a marginal power supply will not enjoy. For anything more than two relays, feed the coil side from a separate 5V supply, remove the jumper, and keep grounds common.

**Mains wiring is on you.** The relay contacts switch line voltage. If you aren't confident doing that safely and to code, hire someone who is, or restrict yourself to low-voltage DC loads.

## Install

```
git clone https://github.com/example/piswitch
cd piswitch
sudo ./install.sh
```

The installer drops the daemon into `/opt/piswitch`, writes a default config to `/etc/piswitch/config.json`, and installs a systemd unit. It does not start the service — edit your config first.

```
sudo systemctl enable --now piswitch
systemctl status piswitch
journalctl -u piswitch -f
```

The service runs as user `piswitch`, which the installer adds to the `gpio` group. It does not need root.

## Configuration

`/etc/piswitch/config.json` maps friendly names to GPIO pins:

```json
{
  "listen": "0.0.0.0:8480",
  "relays": [
    { "name": "porch_light",  "pin": 17, "active_low": true },
    { "name": "desk_lamp",    "pin": 27, "active_low": true },
    { "name": "fan",          "pin": 22, "active_low": true },
    { "name": "kettle",       "pin": 23, "active_low": true, "restore": "off" }
  ]
}
```

Fields:

- `name` — used in URLs, so stick to lowercase letters, digits, and underscores.
- `pin` — BCM numbering, not physical pin numbers. GPIO17 is physical pin 11.
- `active_low` — true for most relay boards, where pulling the input low energizes the coil. If your relays click on at boot and off when you toggle them, this is the setting you got wrong.
- `restore` — `off` (default), `on`, or `last`. What the relay does when the daemon starts.

Reload after editing:

```
sudo systemctl restart piswitch
```

Bad configs fail loudly at startup rather than half-loading; check the journal if the service won't come up.

## HTTP API

Four endpoints, all JSON, no authentication. **Do not expose this to the internet.** Bind it to your LAN and put a reverse proxy with auth in front if you need remote access.

### `GET /relays`

Returns every configured relay and its current state.

```json
{
  "relays": [
    { "name": "porch_light", "pin": 17, "state": "on" },
    { "name": "desk_lamp",   "pin": 27, "state": "off" }
  ]
}
```

### `GET /relays/<name>`

State of a single relay. 404 if the name isn't in the config.

```json
{ "name": "porch_light", "pin": 17, "state": "on" }
```

### `POST /relays/<name>`

Sets state explicitly. Body: `{"state": "on"}` or `{"state": "off"}`. Idempotent — setting a relay to its current state is a no-op and still returns 200.

### `POST /relays/<name>/toggle`

Flips the relay. No body needed. Returns the new state.

## Example

```
$ curl -s http://pihub.local:8480/relays/porch_light
{"name":"porch_light","pin":17,"state":"off"}

$ curl -s -X POST http://pihub.local:8480/relays/porch_light/toggle
{"name":"porch_light","pin":17,"state":"on"}

$ curl -s -X POST http://pihub.local:8480/relays/kettle \
    -H 'Content-Type: application/json' \
    -d '{"state":"off"}'
{"name":"kettle","pin":23,"state":"off"}
```

Every response carries the relay's state after the call, so a client never has to follow up with a `GET` to find out what happened.

## Known limits

State lives in memory. `restore: last` persists to `/var/lib/piswitch/state.json` on change, but a hard power cut between the toggle and the write can lose the last transition. Requests are handled serially; with four relays that has never mattered.
