Subject: We're migrating the internal wiki from Confluence to MkDocs (starting next week)

Hi everyone,

I want to give you a heads-up on a change that's going to affect how we document things internally: over the next six weeks, we're migrating our internal wiki off Confluence and onto a self-hosted MkDocs setup, backed by a git repository instead of Confluence's own storage.

**Why we're doing this**

A few things pushed this decision. First, cost: our Confluence licensing has scaled with headcount in a way that no longer makes sense for how lightly most of the wiki is actually used day to day. Second, search quality: several of you have flagged that finding anything in Confluence beyond the last few weeks of edits is unreliable, and that's only gotten worse as the space has grown. Third, and honestly the deciding factor for engineering: we want documentation changes to go through the same review process as code. With MkDocs, docs live as markdown files in a git repo, which means changes go through a pull request, get reviewed, and have a real history you can `git blame` instead of a page-edit log that's hard to search.

**Timeline**

- **Weeks 1–2:** We'll stand up the MkDocs site and migrate the top-level spaces that get the most traffic (Engineering, Onboarding, Runbooks) using an automated export tool. These will be read-only mirrors at first so you can check that content came across correctly.
- **Weeks 3–4:** Team and project-specific spaces migrate. This is where we'll need your help — automated conversion handles most formatting, but tables, embedded diagrams, and Confluence macros often need a manual pass.
- **Week 5:** Confluence goes read-only. You'll still be able to view and copy content, but new edits should happen in MkDocs from this point on.
- **Week 6:** Confluence access is fully retired, and the MkDocs site becomes the source of truth.

**What you need to do**

If you own a Confluence space or a handful of pages, please check the migration tracker (link below) during weeks 3–4 to confirm your content migrated cleanly, and fix up any formatting issues via a pull request to the docs repo. If you don't see your space listed as owned by anyone, please claim it in the tracker so it doesn't get missed. Everyone else can keep using Confluence normally until week 5 — no action needed until your content shows up for review.

**Questions**

Reach out to Priya on the platform team for anything related to the migration tooling or export accuracy, and to me directly for anything about the timeline or process. We'll also hold a short Q&A session before the read-only cutover in week 5, details to follow.

Thanks for bearing with the disruption — the new setup should make docs easier to find and easier to keep accurate.
